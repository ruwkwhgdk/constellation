## 구조와 동선
건물 크기 14.4 × 12m, 3층과 옥상. 층 바닥 높이 0 / 3.4 / 6.8 / 10.2m. 지붕까지 약 13.18m. 앞 방향은 Blender -Y입니다.

1층 정면 출입구 또는 왼쪽 측면 출입구 → 중앙 복도 → 뒤쪽 왼편 U자 계단 → 2층 → 3층 → 옥탑 출입구 → 옥상으로 연결했습니다. 층마다 전면 방 2개와 후면 방 1개를 두었습니다. 정면 출입구는 4개이며 두 개씩 하나의 큰 방으로 통합니다. 내부는 사진에 없는 부분이므로 새로 설계했습니다.

문 개구부 1.4 × 2.4m, 복도 약 2.45m, 계단 폭 1.8m, 단높이 17cm / 단너비 30cm입니다. 문짝은 아직 배치하지 않아 출입구가 열려 있습니다. 창유리는 블록아웃용 불투명 색상이며 충돌이 있습니다.

Blender `MODULE_LIBRARY` 컬렉션은 기본적으로 숨김 상태입니다. 개별 모듈을 편집할 때만 표시하세요. 원점에 원본 모듈들이 겹쳐 있으므로 건물 조립체와 동시에 표시하면 혼동할 수 있습니다. 각 조립 인스턴스는 모듈 메시 데이터를 공유합니다. 원본 파일을 복사해 수정하는 것이 좋습니다.

## FBX와 Unreal
모듈은 미터 기반으로 제작하고 FBX에 단위 정보를 기록했습니다. 단위 변환과 스케일은 FBX 재가져오기 검사로 확인합니다. Unreal의 최종 크기는 엔진에서 별도로 확인해야 합니다.

각 모듈 FBX에는 `SM_KB_*` 메시와 이에 대응하는 `UCX_*` 충돌 메시가 있습니다. 벽 개구부를 보존하도록 각 볼록 부품을 분리했습니다. 계단 충돌은 실제 단 형상입니다. 플레이 테스트에서 계단 진동이 보이면 램프형 충돌로 교체할 수 있습니다.

권장 검토 순서:
1. Blender 조립본과 미리보기로 외형·평면을 검토합니다.
2. Unreal에는 개별 모듈부터 가져와 3.6m 벽이 360cm인지 확인합니다.
3. 사용자 충돌을 가져오고 문 개구부를 덮는 자동 충돌을 추가하지 않습니다.
4. 조립 FBX를 씬으로 가져올 때 개별 객체의 배치를 유지합니다. 하나의 거대한 볼록 충돌로 병합하면 실내에 들어갈 수 없습니다.
5. 별도 테스트 레벨에서 실제 캐릭터로 출입문, 계단 양방향 이동, 계단참 회전, 옥상 출입과 카메라 벽 충돌을 확인합니다.

Unreal 임포트 단계에서는 `/Game/Environment/OldKoreanBuildingB/Blockout` 폴더를 사용합니다. 실제 캐릭터 이동·카메라 플레이 테스트는 사용자가 진행합니다. 임포트 결과는 `unreal_import_verification.json`을 확인하세요.

Unreal 임포트 과정에서 기존 FBX의 단위 메타데이터만으로는 자동 단위 변환이 적용되지 않는 것을 확인했습니다. `FBX_SCALE_NONE`으로 센티미터 변환을 객체 변환에 적용해 재출력했습니다. Blender 원본은 계속 미터 단위를 유지합니다.

## 검증 범위
`validation.json`: 계단/계단참 중심선 78개 지점의 아래쪽 지지와 위쪽 공간 검사. 캐릭터 캡슐 전체를 움직인 검사와는 다릅니다.

`fbx_verification.json`: 출력 FBX를 새로운 Blender 장면에 다시 가져와 원본 치수, UV, 충돌 형상 폐쇄성 및 배치 위치를 검사한 결과.

UV는 블록아웃용 반복 좌표입니다. 최종 라이트맵 UV, 텍스처, 벽돌 디테일, 한글 간판, 실외기·배관·소품·문 상호작용·LOD는 이번 범위에 포함하지 않았습니다. 프리뷰 색상은 부품 구분용입니다.

## 재생성
`generate_blockout.py`를 Blender의 백그라운드 Python 실행으로 실행하면 이 폴더의 산출물을 재생성합니다. 기존 산출물을 덮어쓰므로 수동 편집본은 다른 이름으로 저장하세요. `verify_fbx.py`는 생성이 끝난 뒤 별도의 Blender 프로세스로 실행합니다.
