# 원화에서 Unreal 환경까지 · 재사용 제작 절차

2026-09-30 사용자 시각 승인. 최신 유지 상태는 [CURRENT](../CURRENT.md), 실제 비교는 [v028](../TripoReplacement/v028/review.html), 판정 근거는 [성공 기준](../REFERENCE_ACCEPTANCE.md).

## 다음 작업에서 먼저 할 일

1. 원화 원본, 제외 대상, 플레이 캐릭터·이동 규칙, 목표 카메라와 플랫폼을 기록한다. 이미지에서 알 수 없는 치수/뒷면은 추정임을 표시한다.
2. 고정 ID로 모듈을 분해하고 누락 구조·접합 부품·움직이는 부분을 함께 목록화한다. 사용자의 채택/수정은 ID에 연결한다. 원화 시트 전체를 한 메시로 생성하지 않는다.
3. 실측 cm, 피벗, 삼각형 예산, UV/재질 슬롯, 충돌, 리깅 요구를 정한다. 문짝/문틀·형광등/광원·새의 날개와 전이 애니메이션을 따로 계획한다.
4. 형태의 유기적 복잡함은 Tripo로, 치수·접합·실루엣 보정은 Blender로 처리한다. 이번 작업에서 단순 절차형 나무·기둥·비둘기의 낮은 품질을 확인했다. 복잡한 환경 전체를 단순 기본 도형으로 대체하지 않는다. 정밀 모듈은 생성 메시의 윤곽을 그대로 믿지 않는다.
5. 사용자 선택에 따라 API 또는 웹을 사용하고 다운로드 원본을 보존한다. 크레딧 소진이나 다운로드 실패를 숨기지 않는다. 비밀키·세션 토큰·인증 URL을 산출물/Git에 저장하지 않는다.
6. Blender에서 정점/노멀/UV/재질, 치수, 열린 면, 중복면, 충돌을 확인한다. CLI는 프로젝트 `tools/run-blender.ps1`로만 실행한다. Boolean 뒤에는 메시가 성공적으로 만들어졌다는 로그 외에 바운드·부피·본체 존재도 검사한다. 몰딩과 본체가 겹친 메시에서는 조각별 정리/합집합 후 파손을 만든다.
7. Unreal에는 먼저 구조와 실제 캐릭터 스케일을 반입한다. 스크린샷 구도와 플레이 공간 크기는 별도 승인이다. 소품까지 일괄2배 확대하지 않는다. 사용자가 플레이 테스트를 맡으면 자동 플레이를 실행하지 않고 미검증 상태를 남긴다.
8. 구조 비율 → 고정 카메라 → 큰 명암 → 재질 색면 → 식생/물 → 세부 순으로 보정한다. 원화의 큰 창 칸수·기둥 경계·중간 띠 높이·측면 빈 공간부터 맞춘다. 후반에 구조 오류를 빛으로 숨기지 않는다.
9. 식생은 연속된 군집과 빈 공간을 함께 설계한다. 이끼를 균일하게 흩뿌리지 않고 습기/접합/아래쪽에 큰 비대칭 색면을 배치한다. 벽 잎·관목·바닥의 접합과 떠 보이는 수관을 실제 렌더로 확인한다.
10. 물은 잔물결의 크기, 세로 반사, 투과되는 바닥, 물가를 함께 조절한다. 게임 물리 효과와 미술용 발광 마스크를 구분해 기록한다. 평면 반사 설정은 `r.AllowGlobalClipPlane=1`; 성능 수치는 설정 변경 후 다시 측정한다.

## 성공 판정과 사용자 검토

- 매회 실제 저장 맵을 다시 읽고, 같은 카메라·노출에서 새 렌더를 촬영한다. 이미지 파일 존재만 보지 말고 촬영 시간과 갱신 확인 결과를 검사한다.
- 축소 이미지의 큰 구도/색면을 먼저 비교하고 원래 크기로 접합·파손·과노출을 본다. 코드 검사나 수정 횟수는 시각적 성공 근거가 아니다.
- 기준은 구도, 명암과 빛, 비대칭 식생, 잔잔한 물, 폐허 형태의 다섯 항목. 기준을 완료에 맞춰 낮추지 않는다. v023의 느슨한 판정을 철회하고 큰 창 비율부터 다시 수정한 경험을 반복하지 않는다.
- 수동 기준점과 카메라 투영의 픽셀 차이는 부분적인 검증이다. 전체 이미지 유사도 퍼센트로 바꾸어 말하지 않는다.
- 사용자 시각 승인, 저장 검사, 실제 플레이, 성능 측정, 애니메이션 접촉 검사를 각각 기록한다. 이번 승인은 시각 결과이며 플레이/성능 승인으로 확장하지 않는다.
- 리깅된 비둘기는 메시 외 스켈레톤·클립·Sequencer 바인딩·전이 길이까지 유지한다. 동작 파일 존재와 날개 접촉 품질은 다른 검사다.

## 유지와 정리

- 운영 시작점은 저장된 TripoFull 맵과 최신 캡처 스크립트다. 과거 레벨 생성 스크립트를 단독 재실행하지 않는다.
- `TripoFull`의 원본/중간 재질 중 일부는 현재 맵에서 미사용이어도 파생 레시피가 읽는 입력이다. 재반입용 FBX/Blend/원본 텍스처·사용자 채택 키트·검사 JSON을 보존한다.
- 초기 Blockout/Production/Scene/TripoReview의 런타임 복제본은 최종 맵 및 외부 하드/소프트 참조가 없으면 제거한다. 과거 생성 스크립트와 소스는 이력/재생성 참고이며 기존 폐기 맵의 존재를 보증하지 않는다.
- 삭제는 Asset Registry의 프로젝트 전체 참조로 보호 집합을 전파한 뒤 Unreal API로 수행한다. `.uasset`을 탐색기에서 무작정 삭제하지 않는다.
- 로그·Blender 자동 백업·비채택 실험은 파일별 범위를 검사해 지우고 삭제 목록/해시를 남긴다. 다른 캐릭터·맵 작업은 섞지 않는다.
- Git에는 유지 소스/최종 에셋/최신 비교와 결정 기록을 넣고 엔진 캐시·로그·비밀정보를 제외한다. 바이너리 원본은 LFS를 사용한다. 사용자가 정한 기존 `develop`에서 구체적인 제목과 본문으로 커밋하고 원격 동일 SHA까지 확인한다.
