# 모듈러 환경 제작 워크플로

다음 환경 제작·재현 작업 전에 이 문서와 [현재 산출물](CURRENT.md)을 읽는다. 캐릭터 애니메이션 작업은 별도의 AnimationWorkflow를 따른다.

## 작업 순서와 사람의 판단

1. **원화와 용도**: 원본 이미지를 보존한다. 실제 플레이 캐릭터, 이동 규칙, 카메라, 목표 플랫폼을 확인한다. 사진의 치수와 가려진 구조는 추정으로 표시한다.
2. **모듈 분해**: 고정 ID가 있는 원화 시트를 만든다. 시작 프롬프트 예시는 `Generate a matrix of individual modular pieces of this subway space.` 각 부품은 분리된 배경과 읽기 쉬운 형태로 제시한다. 시트 전체를 하나의3D 메시로 생성하지 않는다.
3. **작업자 선택**: ID별 채택·제외·수정 코멘트를 기록한다. 타일 규격, 난간의 수평/경사/끝단 연결, 누락된 후면 구조를 함께 검토한다. 기존 승인 범위 안의 보완은 자율 진행한다.
4. **제작 명세**: 실제cm 치수, 피벗, 접합면/방향/접선, 삼각형 상한, UV, 재질 슬롯, 충돌을 정의한다. 문은 문짝·문틀 분리 및 경첩 피벗을 요구한다. 형광등 본체·발광면·실제 광원을 구분한다.
5. **혼합 제작**: 계단·벽·타일·난간처럼 정밀 접합이 필요한 모듈은 Blender 파라미터 제작을 우선한다. 문짝·형광등처럼 채택된 Tripo 형태는 원본을 보정한다. 사용자가 선택한 API/웹 경로를 따른다. 크레딧 소진 시 무한 재시도하지 않으며 비밀키는 산출물/로그에 넣지 않는다. 생성 목표 폴리곤 수를 실제 상한으로 간주하지 말고 측정한다.
6. **Blender 검수**: 작업자에게 실제3D 검토 파일/렌더와 측정치를 제공한다. 형상·UV·노멀·텍스처·충돌·비유한 정점·열린 경계·중복면을 점검한다. 의도적인 열린 면은 따로 기록한다. 코멘트를 반영하고 채택 상태를 명시한다.
7. **Unreal 조기 플레이 검증**: 먼저 간단한 재질로 키트와 공간을 반입하고 실제 캐릭터를 배치한다. 폭, 참 깊이, 머리 위 여유, 단 높이, 문 통과, 카메라 충돌을 플레이로 확인한다. 원화와 비슷한 스크린샷만으로 공간 크기를 승인하지 않는다. 이 단계가 재질·조명 정교화보다 먼저다.
8. **장면 재현**: 구조/실제 스케일 → 카메라 → 조명 명암 → 재질/오염 → 디테일 순으로 원화와 비교한다. 구조 회전과 타일 무늬 회전을 구분한다. 각 수정은 고정 카메라 비교와 실제 플레이 양쪽에서 확인한다. 형광등의 벽/천장 부착면과 문 뒤의 구조도 검사한다.
9. **스케일 변경**: 전체 선택 스케일로 소품까지 키우지 않는다. 구조 치수와 소품 실측을 분리하고 난간은 지름·높이를 보존한 채 모듈을 추가한다. 문에 맞춘 벽 보강 등 추가 설계는 사용자 의도를 따른다. 단 높이가 변하면 캐릭터 MaxStepHeight와 실제 이동을 재검증한다. 수치가 허용 범위여도 플레이 통과로 기록하지 않는다.
10. **완료/정리**: 최종 플레이 맵 경로, 재생성 소스, 설정, 측정 보고서, 최신 비교 화면을 연결한다. 임시/백업 애셋은 프로젝트 전체의 하드·소프트 참조를 조사한 뒤 Unreal API로 지운다. 제작 스크립트가 읽는 원본은 런타임 미사용이어도 유지한다. 폐기된 작업으로 되돌아가지 않도록 CURRENT를 갱신한다.

## 이 프로젝트에서 확인한 주의점

- Blender CLI는 반드시 `tools/run-blender.ps1`로 실행한다. 프로필 검사 실패를 환경변수나 권한 변경으로 우회하지 않는다.
- FBX 축/단위는 실제 UE 바운드로 확인한다. 원본 키트에서Y 반전이 있었다. UCX 충돌과 문 피벗을 별도 검사한다. 필요한 FBX import 경로 변경은 해당 실행 세션에만 적용한다.
- ORM의 TC_MASKS 압축은 SAMPLERTYPE_MASKS와 맞춘다. NullRHI 검사만으로 실제SM6 재질 성공을 주장하지 않는다.
- Python `Rotator`는 `pitch=`, `yaw=`, `roll=` 키워드를 쓴다. 위치 기반 소품 재배치는 로컬 축 벡터를 이용해 발광면과 광원을 함께 옮긴다.
- 스크린샷용 에디터는 `set_keep_python_script_alive(True)`와 tick callback으로 렌더/셰이더 안정화 후 촬영하고 자신이 시작한 프로세스만 종료한다. 사용자의 에디터/Blender를 닫지 않는다.
- Windows Error32 저장 실패는 열린 프로세스의 파일 잠금일 수 있다. 성공으로 보고하거나 반복 덮어쓰지 않는다. 사용자가 저장 후 닫으면 재적용하고 새 프로세스에서 재검증한다.
- 계단의 캡슐 위치 변화가 카메라로 즉시 전달되는 경우 SpringArm 위치 보간을 점검한다. 이번 주인공은 lag10, max distance60cm, substep1/120을 적용했다. 수평 추적에도 지연이 생기므로 캐릭터별로 판단하며 슬라임 등 다른 이동 규칙에 일괄 적용하지 않는다.
- 가느다란 앞코 홈의 강한 재질 대비는 원거리에서 체크무늬로 보일 수 있다. 먼저 소스·재질·렌더를 비교해 원인을 좁히고, 필요하면 대비/반사를 낮추거나 거리별 표현을 바꾼다.
- 실제 렌더, 정적 치수 검사, 사용자 플레이 확인, 자동 이동 검사, 성능 측정을 별도 상태로 기록한다.

## 예산과 재사용

이번 키트의 삼각형 예산은 벽/평면/보4000, 계단6000, 점자 패널8000, 난간4000, 문짝/등기구3000이었다. 다음 프로젝트의 고정 규칙으로 복사하지 말고 목적과 플랫폼에 맞춘다. 유지 소스와 실행 순서는 CURRENT를 따른다.
