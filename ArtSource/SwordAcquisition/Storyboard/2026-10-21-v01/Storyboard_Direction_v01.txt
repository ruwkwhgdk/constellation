폐교 — 녹슨 검 획득 이벤트 / 스토리보드 기획 v01
작성일: 2026-10-21 (Asia/Seoul)
상태: 사용자 검토용 제안. 텍스트 콘티이며 실제 엔진 구도·영상 검증 전.

1. 확정 요청과 이번 범위
장소: AbandonedSchool, 무너지는 발판을 건넌 뒤의 발판 바닥에 꽂힌 검.
순서: 점프 획득 이후 검 상호작용 → 양손으로 힘주어 뽑기 + 위 방향 스와이프 QTE → 균형 회복 → 한 손으로 검을 하늘 높이 들기 → 든 자세에서 실제 아이템 획득 UI → Dialogue “녹슨 검을 얻었습니다.” → 공격 해금 → 컨트롤 복구 → 토스트.
검 위의 기존 별은 구현 단계에서 해당 배치 인스턴스만 제거한다. 점프 획득 별이나 공용 별 BP를 삭제하지 않는다. 실제 대상 actor/path 및 참조는 엔진에서 식별해야 한다.
이번 산출물은 방향과 콘티. 에셋 수정, 별 제거, 빌드, 애니메이션 제작 요청 전송은 하지 않는다.

2. 연출 방향 — 제안
신비로운 능력 흡수보다 무게와 저항, 스스로 검을 얻었다는 감각을 중심으로 한다.
조심스럽게 양손으로 잡고 무릎을 굽혀 버틴 뒤, 입력 성공 순간 검이 빠지며 체중이 뒤로 쏠리고 발로 받아 균형을 잡는다.
사용자 추가 확정(2026-10-21): 검을 뽑고 균형을 잡은 뒤 한 손으로 검을 하늘을 향해 높이 들고, 그 자세에서 아이템 획득 UI를 표시한다. 기존 제작 모션 이후에 한손 전환·들어 올리기·유지·내리기 연결이 추가로 필요하다. 시험 공격은 추가하지 않는다.
별 흡수·화이트 페이드·능력 선택 UI는 사용하지 않는다. 주변광과 작은 먼지, 마찰음, 빠지는 금속음으로 표현하는 안이다. 효과와 사운드는 승인 리소스 확보 전 미확정.
카메라는 A 공간 확인 → B 양손/발을 읽는 주 구도 → C 검을 높이 든 획득 구도, 세 구도를 기본으로 한다. 아래 8비트는 8카메라 컷을 뜻하지 않는다.
전체 시간은 애니메이션 전달 후 결정한다. 아래 시간은 편집 목표이며 클립 속도를 억지로 변경하는 기준이 아니다.

3. 텍스트 스토리보드 — 8비트

01 / 도착과 상호작용 / 게임 카메라 / 사용자 입력까지
화면: 건너온 발판에서 바닥에 꽂힌 검이 목표로 읽힌다. 검 위 별은 없다.
동작: 기존 상호작용 안내를 통해 검 선택. 점프 획득·미획득 검 상태 검사 후 시작.
의도: 점프를 배워 도달한 장소에서 새로운 행동 수단을 얻는 연결.

02 / 검 앞에 자리 잡기 / A 사선 중전신 / 약 1~1.5초
화면: 주인공, 검, 두 발과 안전한 발판 여유가 함께 보인다. 낭떠러지를 등지는 과도한 후퇴는 피한다.
동작: 게임 입력 잠금 후 승인 모션 시작 위치·방향으로 자연스럽게 정렬. 순간이동으로 보이는 보정 금지.
카메라: 현재 게임 카메라에서 A로 짧게 연결. 벽·머리·바닥 관통 없는 구도는 엔진 시안에서 결정.

03 / 양손 그립과 준비 / B 정면 사선 중전신 / 약 1~2초
화면: 검 손잡이와 양손, 어깨–팔꿈치–전완, 무릎과 발이 읽힌다. 반대손이 완전히 가려지지 않는 쪽 선택.
동작: 양손으로 잡고 발을 고정하며 무릎을 굽힌다. 작은 체중 이동으로 저항을 보여준다.
카메라: A→B는 그립 준비 때 한 번 전환. 이후 QTE와 뽑기까지 같은 축을 유지.

04 / 힘주어 버티기 + QTE / B 고정 / 입력 대기
화면: 얼굴·손을 가리지 않는 중앙 아래 여백에 투명 금빛 방향 드래그 UI. 아래→위 화살표.
입력 제안: 시작점에서 좌클릭 유지 후 위로 드래그 1회. 기존 DirectionDrag 사용, 화면 좌표 방향 (0,-1).
사용자 확정(2026-10-21): 시간제한 없이 무제한 대기. 시간 링 없음. 잘못된 방향/조기 해제는 재시도하며 성공할 때까지 버티기 구간을 유지한다.
동작: 승인된 버티기 루프에서 기다린다. 전신 정지 프레임이나 반복 당기기로 대체하지 않는다.
기술 주의: QTE Hold는 연출 시간 정책이다. 캐릭터 유지 루프까지 정상 재생되는지 별도 확인해야 한다. 제작 클립에 유지 루프가 없으면 이 구간 연결은 미해결이다.

05 / 입력 성공과 검 이탈 / B 연속 / 약 1~2초
화면: 같은 구도에서 손·검·상체가 함께 위로 움직인다. UI 성공 효과가 동작을 가리지 않는다.
동작: 성공 판정 즉시 뽑기 구간으로 연결. 실제 검 이탈 프레임에 고정 상태를 해제하고 승인된 검 궤적을 따른다.
효과: 바닥 접점의 작은 먼지와 마찰 해제음 제안. 큰 섬광이나 화면 진동은 기본안에서 제외.
검증: 입력 시점이 달라도 그립·검 위치·속도가 튀지 않음. 검은 UI 종료를 기다렸다가 늦게 빠지지 않음.

06 / 뒤로 쏠린 몸의 균형 회복 / B→C / 약 1.5~2.5초
화면: B에서 회복 동작 끝까지 발을 보여주고, 안정된 뒤 검을 들어 올리는 동작에 맞춰 C(검 끝까지 담는 사선 구도)로 연결. 얼굴과 한 손 그립이 보이고 검 끝이 화면 밖으로 잘리지 않도록 여백을 확보한다.
동작: 승인 모션의 발 디딤과 체중 회복을 보존. 검을 든 채 자세가 안정된다.
금지: 회복 중 UI를 띄워 발/손 결함을 가리기, 발판 밖으로 발 내딛기. 한손 전환은 회복 후 지정된 전환 동작으로 수행하며 손이나 검의 위치가 튀지 않도록 한다.
종료 자세와 게임 무기 장착/수납 방식은 기존 무기 시스템 확인 후 연결한다. 기본 제안은 인벤토리 지급과 기존 장착 흐름을 통해 바로 공격 가능한 상태로 복귀하는 것.

07 / 한 손으로 검을 하늘 높이 들기 → 획득 UI → 안내 대사 / C / 올리기 시간은 모션 확인 후 결정 + UI 확인 대기
동작: 균형 회복 후 한 손 그립으로 전환하여 검을 하늘 높이 들어 올린다. 사용할 손은 기존 무기 장착과 승인 애니메이션에 맞춰 결정한다. 최고 자세에 도달한 뒤 UI 확인이 끝날 때까지 자연스러운 호흡을 포함한 유지 구간을 재생한다. 정지 프레임이나 올리기 동작 반복으로 대체하지 않는다.
화면: 검을 높이 든 자세에서 기존 실제 아이템 획득 UI에 녹슨 검 데이터·아이콘·획득 수량 표시. UI는 얼굴·그립·검 실루엣을 가리지 않는 여백에 배치한다. 임시 대사창을 보상 UI로 대체하지 않는다.
순서: 검 뽑기/균형 회복 → 한 손으로 검 들어 올리기 → 최고 자세 도달 및 아이템 지급 성공 확인 → 든 자세 유지 + 획득 UI. 이후 연결 제안: UI 종료 → 검을 자연스럽게 내리기 → Dialogue “녹슨 검을 얻었습니다.” → 공격 기능 해금. 내리는 동작과 게임 복귀 사이에 자세가 튀지 않도록 검수한다.
UI와 Dialogue는 겹치지 않음. Dialogue는 기존 String Data 경로에 신규 행 연결.
아이템 실제 ID·인벤토리 지급 API·기존 획득 UI/닫힘 이벤트·공격 해금 저장 경로는 아직 미확인. UI를 띄웠다는 사실만으로 아이템 지급 완료라 하지 않는다.

08 / 게임 복귀와 공격 안내 / 게임 카메라 / 약 0.5~1초 전환
화면: C에서 게임 카메라로 자연스럽게 복귀. 입력 복구 완료 뒤 공격 안내 토스트.
토스트 제안: “공격할 수 있습니다.” + 현재 실제 바인딩된 공격 입력. 키를 텍스트에 고정하지 않는다.
상태: 다시 상호작용해 중복 지급되지 않으며, 저장/로드 이후 검 획득·공격 해금이 유지된다.

4. Scene Director 연결 설계
아래는 논리 단계 이름이며 모두 기존 노드 이름이라는 뜻은 아니다.
상호작용 조건 → 입력 잠금/배치 정렬 → 그립 준비 애니메이션 → 버티기 유지 + QTE(DirectionDrag, Up)
  Success → 검 뽑기 → 균형 회복 → 한손 전환/검 높이 들기 → 최고 자세 도달/아이템 지급 확인 → 든 자세 유지 + 획득 UI 닫힘 대기 → 검 내리기 → Dialogue → 공격 해금 → 게임 카메라/입력 복원 → 토스트 → 완료
  Retry → 검이 꽂힌 상태와 버티기 유지. 시간 만료 실패 분기는 사용하지 않는다. 오입력에 별도 실패 연출이나 페널티를 추가하지 않는다.
  Cancel/Error → QTE/획득 UI/카메라/입력 정리. 미지급 상태면 검 복구 후 재상호작용 가능.
실패 UI나 지급 실패 상태에서 획득 대사·공격 해금으로 진행하지 않는다.
지급 이후 중단 시 이미 지급한 검을 회수하거나 다시 지급하지 않는다. 지급·대사·해금 단계의 진행 상태를 저장하고 재진입 시 남은 해금 처리를 복구하는 설계가 필요하다.
스킵 기본 제안: QTE를 자동 성공시켜 보상을 주지 않는다. 지급 전 취소는 원상 복구, 지급 후 취소는 지급 상태에 맞춰 후속 해금 일관성을 복구. 현행 Scene Director 스킵 정책과 결합 전에 재검토한다.
점프 획득은 시작 조건 제안. 우회 이동으로 도착했더라도 미획득 상태면 검 이벤트는 시작하지 않는다.

5. 현재 확인한 것 / 미확인
확인: 기존 QTE 설정에 DirectionDrag, DragDirection, bTimed, Hold/Continue, Success/Failure/Cancelled와 입력 정리 코드가 있다. 이번 이벤트의 실동작 검증은 아니다.
확인: TutorialPromptWidget에 Attack 타입이 있다. 실제 공격 입력 매핑은 후속 확인.
확인: 애니메이션 채팅에서 사용자가 “버티다가 뽑고 균형 잡기”와 마네킹 영상 우선 검수를 승인했다. 현재 캐릭터 적용 완료본은 확인되지 않았다.
미확인: 맵 내 검/별 actor 식별, 정확한 발판 치수와 카메라 장애물, 실제 아이템 데이터/UI/무기 장착/공격 해금 경로, QTE와 유지 루프 동시 재생, 애니메이션 최종 길이와 그립/검 이탈 마커.
이 콘티 작성에서는 엔진 검사하지 않았다. 로컬 소스와 기록만 읽었다.

6. 애니메이션 전달 시 확인할 연결 항목
별도 제작 채팅의 승인 원본과 속도·양손 그립·손목/팔꿈치·발 접지를 보존한다.
필요 구간: 접근/그립 준비, 반복 가능한 버티기, 성공 이탈, 균형 회복, 한손 그립 전환, 하늘 높이 검 들어 올리기, UI 대기용 든 자세 유지, 검 내리기, 게임 복귀 자세.
필요 정보: 양손 그립 변환, 검 기준축/피벗, 그립 완료·이탈·회복 완료·한손 전환·검 최고 자세 도달·내리기 완료 시점, 루트 이동과 발 디딤 범위, 종료 시 검 보유 방식.
2026-10-21 사용자 명시 승인 후 플레이어 캐릭터 애니메이션 제작 채팅(01a0ba3a-ca09-73e0-b9bd-7084c8f3096b)에 한손 높이 들기·UI 대기 유지·내리기 및 관련 연결 요구사항을 전달했다. 전달 성공을 확인했으며 제작 완료를 뜻하지 않는다.
유지 루프/분기 전환이 없는 단일 클립을 임의 중간 분할하거나 속도 변경해 완료 처리하지 않는다.

7. 구현 및 검수 순서
① 콘티 방향 검토. QTE 정책은 시간제한 없이 재시도로 사용자 확정(2026-10-21).
② 최신 맵/프로세스 점유·검/별/기존 UI/아이템 경로 확인. 기존 리소스 재사용 여부 결정.
③ 승인 애니메이션으로 검수용 엔진 구도와 QTE 연결 영상 제작. 미완성 모션을 쓰면 블로킹 시안임을 표시.
④ 사용자 영상 확인 후 실제 맵·그래프 저장 및 검 위 별 인스턴스 제거.
⑤ 저장본 재로드 후 실제 일반 상호작용 키→타기팅→이벤트→보상→공격까지 검증.
⑥ 연출 타이밍·카메라·효과·사운드 폴리싱 후 재검수.
핵심 검사: QTE 장시간 대기/즉시 성공/오입력/중단/포커스 상실, 손·관절/발 접지/의상/검의 프레임 경계, 한손 전환/들어 올리기 중 손목·팔꿈치·어깨 꺾임과 검/머리 간섭, UI 장시간 대기 중 든 자세 유지와 종료 후 내리기 연결, UI 확인 입력이 공격으로 새지 않음, 중복 지급 방지, 취소 후 재시작, 저장·로드 후 상태 보존.
카메라 검수는 동영상으로 한다. 수치 검사·정적 콘티로 실제 동작 승인을 대체하지 않는다.
