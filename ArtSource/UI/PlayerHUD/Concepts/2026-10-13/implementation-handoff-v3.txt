HP·스태미너 HUD 제작 인계 — 최종 v3

사용자가 UI 시안 제작 채팅에서 이 디자인을 정리하고 「UI 구현」 채팅에 제작 요청을 보내도록 명시적으로 요청했습니다. 기존 더미 HP/스태미너 HUD를 아래 기준으로 제작·적용해 주세요.

최신 기준 이미지

이 파일이 최종 기준입니다. 이전 v1의 황금색 마름모와 v2의 '스태미너 부족' 문구는 사용자가 거절하여 폐기한 방향입니다.

확정 디자인
- A안 별빛 궤도형. 왼쪽 작은 별+궤도 문양, 오른쪽 2줄 게이지.
- HP: 위쪽 굵고 긴 붉은 산호색 게이지.
- 스태미너: 아래쪽 더 얇고 짧은 청록색 게이지. 왼쪽 시작점 정렬.
- 얇고 차분한 금빛 프레임, 어두운 남색 빈 트랙, 문양 주변에 절제된 청색 성운 질감.
- HP 위험은 붉은 별의 느린 맥동. 피격 손실 잔상은 실제 피격 시에만, 저HP 자체와 분리.
- 스태미너 부족으로 행동에 실패하면 왼쪽 별 중심/가까운 광륜이 잠깐 주황색으로 점멸하며 살짝 좌우로 흔들림.
- 별만 흔들리고 궤도선·게이지·주변 HUD는 고정.
- 경고 문구, 황금색 마름모, 다른 경고 아이콘은 넣지 않음.
- 실패 반응 종료 후 현재 HP 상태에 맞게 복귀: 정상일 때 금빛, 저HP일 때 붉은 맥동.
- 북쪽왕관자리 7개 별의 능력 해금 표현과는 별개인 단일 HUD 문양.

상태 동작 초깃값
- 실패 반응 약 0.3~0.4초, 작은 좌우 흔들림 2회. 실제 HUD 크기 기준 약 ±2~3 Slate 단위를 초기 후보로 검토하고 과하지 않게 조정.
- 실패 애니메이션 중 추가 입력으로 효과를 중첩하거나 무한 재시작하지 않음. 필요하면 짧은 재발동 제한.
- 주황 반응은 단순히 스태미너가 0인 동안 지속되는 상태가 아니라 실제 행동 거부 이벤트.
- 0보다 큰 잔량에서도 시도한 행동의 비용이 부족하면 반응해야 함.
- 쿨다운, 상태 제한, 사거리 등 다른 원인 실패에는 이 반응을 재생하지 않음.
- 이미지 3행의 ST 0%는 하나의 실패 예시. 실패했다는 이유로 실제 게이지를 0으로 만들지 않음.
- 스태미너 0에서는 빈 트랙을 유지하고 테두리는 차분한 회색으로 낮추는 시안. 회복 시 정상 스타일 복귀.
- 저HP 임계값/맥동 주기는 현행 값이 있으면 재사용, 없으면 편집 가능하게 두고 결정한 초깃값을 보고.

제작과 연결
- 프로젝트 AGENTS.md 및 현재 UI 구현 방식 확인. 기존 작업과 무관한 변경 보존.
- 기존 WBP_PlayerHUD, BPI_PlayerHUD, BP_HUD와 실제 플레이어 자원 연결을 먼저 조사.
- 이전 저장 그래프에는 HPProgressBar/StaminaProgressBar와 Ac_Stats 연결이 있으며, 네이티브 CombatAbilitySystem에도 GetHealth/GetStamina 및 최대값이 있음. 현재 실제 플레이어가 사용하는 권위 있는 값/동기화 경로를 확인해서 연결하고 두 수치를 독립적으로 갱신하지 말 것.
- 기존 HUD의 다른 기능을 보존하고 HP/스태미너 표시만 교체. 좌측 상단 배치 제안은 실제 HUD와 확인 후 조정.
- 시안 전체를 텍스처로 붙이지 말 것. 별/광륜/고정 궤도/프레임/빈 트랙/동적 채움/손실 잔상을 레이어로 분리.
- 이미지의 시트 제목, NORMAL/LOW HP/STAMINA FAIL 상태명, 우측 퍼센트는 비교용 주석이므로 게임 HUD에 표시하지 않음. HP/ST 작은 식별자는 시안 기준.
- 게이지는 실제 current/max 비율로 즉시 반영. 잔상만 별도 보간.
- 별 리소스는 색상 변경과 독립적인 흔들림이 가능해야 함.
- 게임 밸런스, 스태미너 비용/회복 규칙, 입력 모드·일시정지·커서 상태를 바꾸지 않음.

검증
- 정상, 피격, 저HP, 회복, 스태미너 소모/회복/0 상태의 실제 수치 일치.
- 스태미너 0 및 0보다 크지만 비용 미달인 경우의 실제 행동 실패에만 주황 반응.
- 다른 원인 실패에는 반응 없음, 연타 시 효과 중첩 없음.
- 저HP 중 스태미너 실패 후 붉은 맥동으로 정확히 복귀.
- 실제 화면 크기에서 밝고 어두운 배경 가독성, DPI/화면비, 재빙의·리스폰/위젯 재생성 시 이벤트 구독 정리.
- 관련 빌드/자동화와 PIE 확인. 정지 캡처 및 가능하면 짧은 실제 연출 영상을 UI 구현 채팅에서 사용자에게 보고.
- 정지 시안에는 점멸/흔들림이 구현되어 있지 않으므로 이를 검증 완료로 간주하지 말 것.
