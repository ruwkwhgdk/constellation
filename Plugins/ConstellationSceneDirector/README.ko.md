# Scene Director 사용 가이드

기획자 1명이 AI와 함께 연출을 제작하는 UE 5.8.0 플러그인입니다.

## 시작하기

1. 프로젝트를 열고 Tools → **Scene Director · 첫 연출 예제 열기**를 선택합니다. `/Game/SceneDirector/Examples/DA_FirstScene`을 직접 열어도 됩니다.
2. NPC 추가 노드의 **캐릭터 BP**, **NPC String Key**, **월드 위치와 회전**을 입력합니다.
3. 카메라·애니메이션 노드를 선택한 뒤 오른쪽 **NPC 목록**에서 Key를 누르면 대상이 지정됩니다.
4. 출력 ‘다음’ 핀을 대상의 ‘이전’ 핀으로 연결합니다. 여러 번 연결하면 기존 선을 유지하며 분기합니다. 선을 끊으려면 핀의 우클릭 메뉴를 사용합니다.
5. **생성 및 미리보기**를 누르면 툴 하단에 현재 레벨의 씬과 시간 막대가 나타납니다. 첫 프레임이 즉시 표시되며 시간 막대의 재생 버튼과 스크럽으로 확인합니다. 창을 최대화하면 속성과 씬을 함께 보기 편합니다.
6. **미리보기 종료** 후 저장합니다. 저장 시 노드로부터 시퀀스를 다시 생성합니다.

씬 미리보기는 조명이 없어도 보이는 **Unlit(밝게 보기)** 모드입니다. 최종 조명·후처리 품질은 레벨/PIE에서 확인합니다. 카메라가 없는 그래프는 첫 NPC를 중심으로 보여줍니다. 카메라 샷이 끝나면 마지막 시점으로 남으며, 새 샷이 시작하면 그 카메라를 따라갑니다.

## 이벤트 그래프와 노드 생성

- **좌측 고정 메뉴**에서 `+ 이벤트 추가`를 누르면 시작 → 대기 → 종료가 있는 새 이벤트가 만들어집니다. 목록의 이름을 클릭하면 현재 작업할 그래프가 바뀝니다. 선택된 이벤트는 파란색으로 표시됩니다.
- `현재 이벤트 이름`에서 이름을 바꿀 수 있습니다. 빈 이름과 중복 이름은 허용하지 않습니다. 기존 연출은 첫 이벤트 `Event_1`으로 유지됩니다.
- 각 이벤트의 노드, NPC, 카메라, Vector3 목록과 생성 시퀀스는 독립적입니다. 전환할 때 미리보기는 종료되고 선택한 이벤트의 내용으로 바뀝니다. 저장하면 에셋 안의 모든 이벤트를 생성하고 함께 저장합니다.
- 중앙 그래프의 빈 공간에서 **우클릭 → 캐릭터 / 카메라 / 흐름 제어 → 노드 종류**를 선택합니다. 클릭한 위치에 노드가 생성됩니다. 핀을 빈 공간으로 끌어 메뉴에서 생성하면 연결도 추가됩니다. 상단의 노드 생성 버튼은 제거했습니다.
- `레벨에 실행기 배치`는 현재 선택한 이벤트를 연결합니다. 실행기는 원본 연출 에셋과 이벤트 이름을 저장하며, Details의 `이벤트 그래프`에서 다른 이벤트를 고를 수 있습니다. `None`은 첫 이벤트입니다. 배치 후 이벤트 이름을 바꾸면 실행기의 이벤트 선택도 갱신하세요.

## 삭제와 실행 대기

- 그래프에서 노드를 선택하고 **Delete** 또는 **선택 삭제**를 누릅니다. 시작·종료는 보호됩니다. 텍스트 입력 중 Delete는 글자를 지웁니다. 삭제·연결·이동·속성 변경은 Undo/Redo를 지원합니다.
- 카메라·애니메이션·대기 노드의 **완료 후 다음 실행**은 기본 ON입니다. ON이면 설정한 시간이 끝난 뒤 다음 행동을 시작하고, OFF이면 현재 행동을 시작하면서 다음 행동도 시작합니다.
- 하나에서 여러 노드로 연결하면 다음 노드들은 동시에 시작합니다.
- 여러 노드가 하나로 합쳐지면 **모든 입력 경로에서 시작한 행동이 끝난 뒤 한 번만 실행**합니다. 이 규칙은 완료 대기 체크를 꺼도 적용됩니다.
- **합류** 노드는 완료 대기를 명시적으로 표현하는 노드입니다. 입력이 하나여도 앞서 시작된 행동을 모두 기다립니다. **종료**도 남은 행동을 기다린 뒤 NPC와 카메라를 정리합니다.

예: NPC 생성 → (애니메이션 2초 / 카메라 3초) → 합류 → 종료. 두 행동은 동시에 시작하고 3초에 종료합니다.

## NPC 목록과 애니메이션

NPC 추가 노드에 입력한 Key와 BP가 우측 목록에 저장됩니다. 별도로 중복 등록할 필요가 없습니다. Key는 비어 있거나 중복될 수 없으며 대소문자는 구분하지 않습니다. Key 변경 시 해당 NPC를 참조하는 노드의 대상 이름도 바뀝니다. NPC 노드를 삭제하면 남은 참조는 생성 단계에서 오류로 안내합니다.

애니메이션 노드 입력은 **대상 NPC Key / 재생할 애니메이션 / 시간(초)**입니다. 원본 클립을 입력한 시간 동안 **한 번 재생하도록 속도를 조절**합니다. 예를 들어 1초 클립에 2초를 입력하면 0.5배속입니다. 끝나면 이전 애니메이션 상태로 복구합니다. 반복·잘라내기·블렌딩은 아직 제공하지 않습니다.

대상 BP에는 스켈레탈 메시가 있어야 하며 애니메이션 스켈레톤과 호환되어야 합니다. NPC 생성이 연결 경로상 먼저 실행되어야 합니다. 동일 NPC의 애니메이션 또는 카메라 샷이 시간상 겹치면 생성 오류로 안내합니다. 서로 다른 NPC의 애니메이션과 카메라는 병렬로 실행할 수 있습니다. 생성 트랙은 Anim Notify를 실행하지 않으며, 게임 로직 호출은 향후 별도 액션으로 확장합니다.

## 위치 지정과 게임 재생

- NPC: 레벨에서 기준 Actor를 선택하고 NPC 노드에서 **뷰포트 위치 가져오기**를 누릅니다.
- 카메라: 레벨 뷰포트의 시점을 잡고 카메라 노드에서 같은 버튼을 누릅니다. 가져오면 ‘대상 바라보기’가 꺼져 현재 구도를 유지합니다.
- **레벨에 실행기 배치** 후 레벨을 저장합니다. 기본값은 게임 시작 시 자동 재생입니다. BP에서 PlayDirector / StopDirector로 호출할 수도 있습니다.
- 실행기의 **String Key로 NPC 찾기(FindNPC)**는 현재 생성되어 있는 NPC를 반환합니다. 생성 전·종료 후에는 None입니다. 외부에서 조작하려면 반환값을 확인합니다.
- 동시에 실행 가능한 Scene Director는 한 개입니다. 종료 시 생성 NPC·카메라를 정리하고 원래 플레이어 카메라로 돌아갑니다.

샘플 BP는 직육면체 대역입니다. 애니메이션을 확인하려면 스켈레탈 메시가 있는 NPC BP로 교체하세요. `/Game/SceneDirector/Examples/L_FirstScene`은 독립 테스트 레벨입니다. 사용자 레벨을 자동으로 덮어쓰지 않습니다.

## AI 유지보수

- Runtime: `Source/SceneDirectorRuntime`의 에셋·실행기. Editor: `Source/SceneDirectorEditor`의 그래프·컴파일러·툴킷·뷰포트.
- 검증: 프로젝트 루트에서 `./tools/test-scene-director.ps1`. 실패 또는 테스트 누락은 종료 오류로 반환합니다.
- 데이터 버전 3: 예전 단일 연결 데이터는 다중 연결로 변환되며, 기존 카메라는 초기 위치·화각을 보존하여 카메라 목록에 등록됩니다. 기존 에셋은 **생성 및 미리보기 → 저장**을 한 번 수행해야 게임에서 실행할 수 있습니다.
- 시퀀스는 고정 시간 행동을 DAG 실행 일정으로 계산하여 생성합니다. 선택지·Bool 조건 분기는 선택된 경로를 계산해 이어서 실행합니다. 루프와 비동기 BP 완료 이벤트는 현재 지원하지 않습니다.
- BP의 Construction Script·AI·BeginPlay 동작은 프로젝트마다 다르므로 실제 사용할 BP로 PIE 검증이 필요합니다.
- 기존 프로젝트의 무관한 변경을 정리·되돌리거나 일괄 스테이징하지 않습니다.

확장 요청에는 연출 에셋 경로, 기대 행동, 최소 입력값, 미리보기 결과를 포함하세요. 카메라 크로스페이드, NavMesh 경로 이동, 기존 NPC 바인딩, BP 액션, 검색·복사 등은 후속 범위입니다.

## 카메라와 Vector3 저장 목록

우측은 위쪽 노드 속성과 아래쪽 저장 목록으로 나뉩니다. 저장 목록은 **NPC / 카메라 / Vector3**가 구분선으로 분리됩니다. 공간이 부족하면 저장 영역을 스크롤하거나 가운데 분할선을 움직입니다.

- **카메라**: `카메라 저장값 편집`을 펼치고 `저장 카메라`의 + 버튼으로 Key, 초기 위치·회전, 화각을 등록합니다. 카메라 샷 또는 카메라 이동·회전 노드를 선택한 뒤 목록의 Key 버튼을 누르면 연결됩니다.
- 노드에 없는 카메라 Key를 입력하면 새 카메라 저장 항목이 자동 생성됩니다. 초기값은 노드 생성 당시 레벨 뷰포트 위치를 사용하며, 우측 저장값에서 변경할 수 있습니다.
- 같은 Key를 쓰는 노드들은 **한 카메라를 재사용**합니다. 생성 이후 연출 종료까지 유지되어 다른 샷에서 다시 사용할 수 있습니다. 실행기의 `FindCamera`로 현재 카메라를 조회할 수 있습니다.
- **Vector3**: `저장 Vector3` 배열의 + 버튼으로 String Key와 X/Y/Z를 등록합니다. 이동·회전 노드의 입력 방식을 `String Key`로 선택하고 이 이름을 입력합니다.
- 목록의 Key를 바꾸면 해당 카메라·Vector3를 참조하는 노드도 함께 변경됩니다. 복제한 항목에는 새 이름을 지정하세요. 빈 이름과 중복 이름은 생성 오류로 안내합니다. 이름은 대소문자를 구분하지 않습니다. NPC/카메라/Vector3의 이름 공간은 서로 독립적입니다.
- 카메라 이름을 처음 등록하는 노드가 기본값을 제공하므로, 사용 중인 카메라 등록을 삭제하면 다음 그래프 갱신 시 해당 Key가 다시 등록될 수 있습니다. 완전히 제거하려면 참조하는 노드도 제거하거나 다른 Key로 변경합니다.

### 위치·회전 입력 규칙

| 입력 방식 | 최종 목표값 |
|---|---|
| 절대값 | 직접 입력한 Vector3 |
| 현재 값 | 노드 시작 시 현재 위치/회전 + Offset (Key 불필요) |
| String Key, 현재값 옵션 OFF | 저장 Vector3 + Offset |
| String Key, 현재값 옵션 ON | 노드 시작 시 현재 위치/회전 + 저장 Vector3 + Offset |

`현재 위치/회전에 더하기`는 Key 입력일 때만 표시합니다. ‘현재’는 앞선 이동이 반영된 **해당 노드 시작 시점**입니다. 위치는 월드 축의 cm 단위이며 캐릭터 로컬 방향으로 변환하지 않습니다. 회전은 도 단위이고 X=Roll, Y=Pitch, Z=Yaw입니다. 회전 상대값은 각 성분을 더하며 로컬 쿼터니언 회전 합성은 아닙니다.

예: `MeetingPoint=(1000,200,0)`, Offset=(0,0,50)이면 목표는 (1000,200,50)입니다. 현재 위치가 (100,0,0)이고 현재값 옵션을 켜면 (1100,200,50)이 됩니다.

## 캐릭터 이동 노드

1. NPC 추가 노드에서 생성한 NPC를 대상으로 지정합니다.
2. 이동 위치를 절대값, String Key 또는 현재 값으로 입력합니다. Key 모드에서는 Offset과 현재값 가산을 선택할 수 있습니다.
3. `속도 / 시간 선택`에서 하나를 고릅니다. **속도 기준**은 거리÷속도로 시간을 계산하고 **시간 기준**은 거리÷시간으로 실제 이동 속도를 계산합니다. 선택한 방식의 숫자 입력만 표시됩니다.
4. `자체 걷기·달리기 자동 선택`을 켜면 NPC 추가 노드에 등록한 걷기/달리기 클립을 사용합니다. 실이동 속도가 NPC의 `달리기 전환 속도` 이상이면 달리기를 선택합니다. 기본 전환값 300cm/s는 해당 캐릭터에 맞게 조정하세요.
5. 자동 선택을 끄면 이동 노드의 `재생할 애니메이션`이 활성화됩니다. 선택한 클립을 이동 동안 원본 클립 기준 1배속으로 반복합니다. 자동 모드도 선택된 클립을 같은 방식으로 반복합니다.

캐릭터마다 사용하는 애니메이션은 **NPC 추가 노드에서 한 번 등록**합니다. 프로젝트마다 다른 ABP 변수명을 추측하거나 ABP를 자동 수정하지 않습니다. 해당 NPC와 호환되는 In-place 걷기/달리기 클립을 권장합니다. 실제 보폭에 맞춘 재생 속도 보정이나 Root Motion 경로 추출은 아직 적용하지 않습니다.

이동은 출발점→목표점 사이의 **직선·일정 속도 연출**입니다. 장애물 회피나 NavMesh 탐색을 하지 않습니다. 이동 후에는 목표 위치를 유지합니다. 연속 이동은 앞 이동의 도착점에서 시작합니다. 현재 캐릭터 방향은 유지됩니다. 위치 변화와 함께 이동 애니메이션이 재생되며, 종료 시 생성 캐릭터가 정리됩니다.

## 카메라 이동·회전 노드

`카메라 String Key / 이동 위치 / 회전 / 시간(초)`를 지정합니다. 위치와 회전 각각 절대값, String Key+Offset 또는 현재 값+Offset을 선택할 수 있습니다. `이 카메라로 촬영`은 기본 ON이며 이동 중 해당 카메라 화면을 사용합니다. OFF이면 화면 전환 없이 카메라만 준비 위치로 이동합니다.

기존 카메라는 앞선 카메라 동작의 도착점에서 출발하고, 새 카메라는 목록의 초기 위치·회전에서 출발합니다. 위치는 선형 보간, 회전은 Euler 각 축의 최단각으로 보간합니다. 350°→10°는 짧은 방향으로 이동하며, 360° 이상의 회전 누적 연출은 지원하지 않습니다. 화각은 우측 카메라 저장값에서 설정합니다.

두 이동 노드 모두 `완료 후 다음 실행`, 병렬 분기·합류, Delete/Undo, 미리보기를 지원합니다. 같은 NPC/카메라를 변경하는 노드들은 순서를 연결해야 하며 시간이 겹치면 오류를 안내합니다. 다른 대상의 이동은 병렬 실행할 수 있지만 동시에 촬영되는 카메라 샷은 하나입니다.

대사 진행 방식은 `지정 시간 후`, `음성 종료 후`, `시간/음성 종료 후 클릭`입니다. 음성 종료 방식에는 유한한 길이의 음성이 필요합니다. 클릭 방식에 음성이 있으면 음성 길이를 사용하고 없으면 입력한 시간을 사용합니다. 클릭 대기 중에는 전체 연출 시간이 멈추므로 병렬 연기도 함께 멈춥니다. 대사가 끝나기 전에는 다음 버튼이 비활성화됩니다. 음성 재생은 지원하지만 자동 립싱크는 이번 범위에 포함하지 않습니다.

표정과 시선은 설정 시간 동안 적용되며, 전환 시간은 시작과 종료의 블렌딩에 사용합니다. 계속 유지하려면 필요한 길이로 시간을 지정합니다. `완료 후 다음 실행`을 끄면 대사와 함께 재생할 수 있습니다. 같은 NPC의 시선끼리, 표정끼리 겹치는 구간은 오류로 안내합니다.

구도는 노드 시작 시 대상 위치에서 계산됩니다. 이후 움직이는 인물을 계속 따라가는 추적 카메라는 아닙니다. 구도 프리셋에서 `이 카메라로 촬영`을 끄면 즉시 구도만 준비합니다. 이어서 `촬영 카메라 전환` 노드를 연결하면 준비한 카메라로 부드럽게 전환할 수 있습니다. 화면 자체가 겹쳐지는 디졸브는 별도 후속 기능입니다.

### 캐릭터별 연기 프로필 설정

콘텐츠 브라우저에서 Data Asset → **SceneDirectorCharacterProfile**을 만들고 NPC 추가/기존 캐릭터 연결 노드의 `연기 프로필`에 지정합니다.

- 첫 스켈레탈 메시의 컴포넌트 이름, 머리 본, 본의 정면 축, 캐릭터 원점에서의 주시 높이를 설정합니다. 컴포넌트 이름은 비우면 첫 메시를 사용합니다. 이번 버전은 첫 스켈레탈 메시를 대상으로 합니다.
- `표정 프리셋`에 `Smile`, `Angry` 등의 Key를 만들고 실제 메시의 모프 이름과 0~1 가중치를 등록합니다. 이후 기획자는 노드에서 프리셋 Key와 강도만 지정합니다.
- 다른 Post Process Anim BP를 사용하는 캐릭터에는 시선 드라이버를 덮어씌우지 않고 오류를 안내합니다. 해당 캐릭터는 별도의 리그 통합이 필요합니다. 현재는 머리 시선을 제공하며 눈동자 독립 제어는 포함하지 않습니다.
- 프로필을 수정한 뒤 해당 연출에서 **생성 및 미리보기 → 저장**으로 다시 생성합니다.

현재 예제의 heroine 메시에는 표정 모프가 **0개**입니다. 따라서 예제는 구도·시선·대화·복귀 흐름을 보여주며 표정 노드를 임의의 모프로 채우지 않습니다. 실제 얼굴 표정에는 호환되는 모프 리소스를 먼저 준비해야 합니다. 원본 캐릭터·애니메이션은 수정하지 않았습니다. 예제 BP는 호환되는 Idle이 없으면 기존 이동 클립의 정지 포즈를 대역으로 사용합니다. 최종 연출에서는 대기/대화 애니메이션으로 교체하세요. 예제 음성도 지정하지 않았으므로 사용할 녹음 파일을 대사 노드에 연결합니다.

### 기존 캐릭터와 게임 복귀

`ExistingActors` 예제는 `BP_ConversationActor` 인스턴스 두 개에 각각 **Actor Tags** `Hero`, `Partner`를 넣어 사용합니다. Gameplay Tags와는 다른 Actor Tags입니다. 다른 캐릭터를 사용하려면 연결 노드의 BP와 프로필도 맞춥니다. 같은 태그의 Actor가 둘 이상 있거나 BP가 맞지 않으면 시작하지 않고 실행기의 `LastError`에 이유를 남깁니다.

배치 위치·구도는 노드에 저장한 월드 좌표를 기준으로 합니다. 기존 Actor도 연출 중에는 그 위치에 배치되고 종료/중단 시 원래 위치로 복구됩니다. 현재 위치를 기준으로 배치하려면 레벨에서 Actor를 선택해 **뷰포트 위치 가져오기**로 먼저 입력하세요. 기존 Actor는 삭제하지 않습니다.

정상 종료, `StopDirector`, 레벨 종료는 음성·자막·시선·표정을 정리하고 원래 카메라와 기존 입력/HUD 상태를 복구합니다. HUD 숨김은 `AHUD.bShowHUD` 대상으로, 프로젝트의 개별 UMG 위젯 표시나 전투 입력·AI 로직은 자동 변경하지 않습니다. 프로젝트별 연출 모드 연동은 그 UI·게임 로직에 맞춰 추가해야 합니다. 퀘스트/보상 같은 게임 동작은 아래 등록형 BP 액션으로 연결합니다. 선택지와 Bool 조건 분기는 아래 기능을 사용합니다.

### 선택지 UI

### 선택지별 경로와 조건 변수

1. 대사 노드의 선택지 목록을 작성하면 문구별 출력 핀이 생깁니다. 각 핀을 다음 노드에 연결하세요. 항목당 한 경로를 연결하며, 여러 선택지를 같은 노드로 연결해도 됩니다. 일반 다음 핀은 기존처럼 여러 노드로 병렬 연결할 수 있습니다.
2. 오른쪽 **조건 변수** 목록에 Key와 초기 참/거짓 값을 등록합니다. 우클릭 → 흐름 제어 메뉴의 **변수 설정**, **조건 분기**를 사용해 값을 변경하거나 참/거짓 출력으로 경로를 나눕니다.
3. 분기 경로를 다시 합치면 이번에 선택한 경로만 기다립니다. 합류 이후는 한 번 실행합니다. 병렬 행동 중간에 선택지나 조건을 배치하지 말고, 모든 행동을 합류시킨 다음 결정 노드를 연결하세요.
4. 각 대사 노드의 **미리보기 선택지 번호**를 1~4 중 실제 항목 번호로 설정한 뒤 생성 및 미리보기를 누르면 해당 답변 경로만 타임라인에 생성됩니다. 조건은 오른쪽 변수 초기값과 경로 안의 변수 설정에 따라 판단합니다. 상단 상태 문구에 미리보기 경로가 표시됩니다.
5. 실행기의 **재생 초기값 덮어쓰기**에는 이미 등록된 Bool Key만 지정합니다. 재생할 때 초기화되며 진행 중의 값은 `BoolValues`로 확인할 수 있습니다. 외부 저장 게임에는 자동 기록하지 않습니다.

선택지 항목 순서와 문구를 바꿔도 결과 Key를 기준으로 연결이 유지됩니다. 항목을 제거하면 해당 연결을 제거하고 Undo/Redo로 복구합니다. 기존 선택지 UI의 단일 다음 연결은 각 선택지의 같은 대상 연결로 옮겨집니다. 기존 복수 다음 연결은 모호하므로 그래프의 이전 연결을 확인하고 선택지별로 다시 연결해야 합니다.

오류 검사는 모든 조건 초기값과 선택 결과 조합을 확인합니다. 잘못된 Key, 미연결 출력, 순환, 선택한 경로에서 존재하지 않는 NPC 참조를 생성 전에 안내합니다. 현재 검증 한도는 조건 초기값과 선택 경로 조합 256개이며 초과하면 이벤트를 분리해야 합니다. 변수 자료형은 Bool부터 지원합니다.

예제 그래프: `/Game/SceneDirector/Examples/DA_Branching`
실행 예제 맵: `/Game/SceneDirector/Examples/L_Branching`

맵을 열고 PIE를 실행하면 두 선택지가 나옵니다. 도움 수락/거절 → `HelpAccepted` 변수 변경 → 조건 분기 → 다른 답변 → 게임 복귀 흐름입니다. `tools/setup-scene-director-branching.py`로 예제를 준비할 수 있습니다. 원래 대화 예제 맵은 유지합니다.


### 등록형 블루프린트 액션

1. 오른쪽 **게임 액션 → 등록 액션 목록**에 String Key와 액션 BP를 등록합니다. BP의 부모 클래스는 `SceneDirectorAction`입니다.
2. 우클릭 → **게임 연동 → 블루프린트 액션**을 추가합니다. **등록 액션 Key** 목록에서 실행할 액션을 고르고, 필요한 경우 **대상 NPC Key**를 입력합니다.
3. **액션 파라미터**에는 ID(퀘스트/아이템 등), 수량(int), 수치(float), 참/거짓을 입력합니다. 어떤 값을 사용하는지는 등록한 BP가 정합니다. 사용하지 않는 값은 기본값으로 둡니다.
4. BP에서 **액션 실행(Execute)** 함수를 오버라이드합니다. `Player`는 연출 실행기/월드 컨텍스트, `Target`은 선택한 NPC(미지정이면 None), `Parameters`는 노드 입력입니다. 함수가 성공하면 Return Value=true, 실패하면 false와 Error 설명을 반환합니다.
5. 실제 게임/PIE에서 선택된 경로의 액션만 호출합니다. 실행기의 **게임 액션 → Action Results**에서 노드 ID, 액션 Key, 성공 여부, 오류를 확인합니다. 이력은 재생 종료 후에도 유지하고 다음 재생을 시작할 때 초기화합니다.

동기 함수 호출을 지원하며 함수가 반환되면 다음 노드를 실행합니다. Delay·타이머·비동기 로딩의 완료 대기는 지원하지 않습니다. 그런 작업을 시작하고 바로 true를 반환하면 시작 요청만 완료된 것으로 처리됩니다. 여러 액션은 실행 순서가 명확하도록 선으로 순서대로 연결하세요. 선택지의 서로 배타적인 출력에 각각 배치하는 것은 가능합니다.

생성 및 미리보기·시퀀서 스크럽은 액션 BP를 실행하지 않습니다. 키 누락/중복, 실행 불가능한 클래스, 앞서 연결되지 않은 NPC는 생성 시 오류로 안내합니다. 액션 Key 이름을 바꾸면 관련 노드 참조도 갱신합니다.

실행 중 실패하면 후속 액션을 중단하고 연출 카메라/입력을 복구합니다. 이미 변경한 퀘스트나 재화는 되돌리지 않습니다. 한 번의 연출 재생에서 각 노드는 한 번만 실행되며, 선택으로 시퀀스가 바뀌어도 다시 호출하지 않습니다. 연출을 새로 시작하면 다시 실행할 수 있으므로 영구 보상의 중복 지급은 보상 API에서 퀘스트 완료 여부·지급 ID로 막아야 합니다. 액션 안에서 StopDirector는 가능하지만, 같은 실행기에 PlayDirector를 재진입하면 거부됩니다.

예제: `/Game/SceneDirector/Examples/DA_Actions`, 실행 맵: `/Game/SceneDirector/Examples/L_Actions`.
- `BP_ActionSetNPCTag`: 대상 NPC에 ID를 Actor 태그로 추가합니다. 참/거짓=false면 제거합니다. 예제 맵에서는 수락/거절 선택에 따라 서로 다른 태그가 추가됩니다. 저장 데이터에 영향을 주지 않는 실행 확인용 예제입니다.
- `BP_ActionAcceptQuest`: ID를 프로젝트 `QuestSubsystem.AcceptQuestFor`의 QuestID로 전달하고 결과를 반환합니다. 기존 퀘스트 데이터에 등록되어 수락 가능한 상태인 ID를 입력하세요. 예제 맵에는 등록만 되어 있으며 자동 실행되지 않습니다.
- 골드 보상 등은 동일한 Execute 함수에서 Player를 월드 컨텍스트로 사용해 프로젝트 재화 API를 호출하면 됩니다. 유효한 GameInstance/Subsystem과 양수 수량을 먼저 확인하고, 지급 여부에 따라 성공/실패를 반환하도록 구현하세요.

`tools/setup-scene-director-actions.py`로 예제를 준비할 수 있습니다. 플러그인은 Constellation 게임 모듈에 의존하지 않으며 프로젝트 API 연결은 위 BP가 담당합니다.

액션 확장 검증: 자동화 40개, Editor/Shipping 빌드, 실제 BP 함수 호출 및 액션 편집기 렌더링을 확인했습니다. 퀘스트 수락 BP는 컴파일과 저장을 확인했으며 실제 저장 데이터 변경은 실행하지 않았습니다. Cook/Stage/패키지 실행은 미검증입니다.


### 기존 레벨 시퀀스 재사용

우클릭 → **게임 연동 → 레벨 시퀀스 재생**을 추가하고 **레벨 시퀀스** 애셋을 선택합니다. 원본의 재생 범위와 **재생 속도**로 노드 시간이 자동 결정됩니다(1=원속도, 2=두 배). **완료 후 다음 실행**을 끄면 다음 노드도 시작하고, 합류에서는 시퀀스가 끝날 때까지 기다립니다.

시퀀스를 선택하면 **역할 연결**에 원본 Actor 목록이 자동 표시됩니다.
- **원본 Spawnable 사용**: 원본의 생성 Actor를 해당 구간 동안 사용합니다. 기존 Spawnable 형식과 UE의 표준 Spawnable Actor 바인딩을 지원합니다. 원본 내부 카메라도 이 방식으로 재생할 수 있습니다.
- **NPC Key**: 앞선 NPC 추가/기존 캐릭터 연결 노드의 Key를 입력합니다. 원본 역할이 같은 실제 NPC 인스턴스에 연결됩니다.
- **카메라 Key**: 앞선 카메라 노드에서 준비한 Key를 입력합니다. 준비만 할 때는 카메라 이동 또는 구도 프리셋 노드의 ‘이 카메라로 촬영’을 끕니다. 현재 등록 카메라는 ACameraActor이므로 CineCameraActor가 필요한 원본은 원본 Spawnable을 사용하세요.

원본의 기존 Actor(Possessable)는 NPC/카메라 Key에 연결해야 합니다. 대상은 원본 역할의 클래스와 같거나 그 자식 클래스여야 합니다. Actor 바로 아래 컴포넌트는 같은 클래스의 유일한 컴포넌트에 연결하고, 같은 클래스가 여러 개면 원본 역할 이름과 일치하는 컴포넌트가 필요합니다.

지원 트랙은 Transform, 일반 AnimSequence 기반 Skeletal Animation, Camera Cut, 기본 float/double/bool/int/vector/color/visibility, Audio입니다. Event·Control Rig·중첩 Subsequence·원본 트랙/행/섹션 조건 등은 생성 단계에서 오류를 안내합니다. 원본의 동적 바인딩을 실행하는 대신 연결한 역할을 사용하며, 원본 Spawnable 밑 동적 컴포넌트 바인딩은 지원하지 않습니다. 애니메이션 Notify는 재생하지 않습니다. 게임 동작은 별도의 BP 액션 노드로 연결하세요.

원본 애셋은 수정하지 않으며 생성 결과 안에 복사하여 사용합니다. 복사본의 재생 범위 밖 트랙과 프리롤/포스트롤은 평가하지 않고, 오디오의 Play Until Finished도 복사본에서 끄며, 원본 Spawnable도 해당 구간 종료 시 정리합니다. 원본을 수정한 뒤 **생성 및 미리보기**로 갱신하세요. 재생이 끝나면 해당 시퀀스가 덮어썼던 값을 부모 그래프 상태로 복구합니다. 이후 ‘현재 값’ 이동의 기준을 원본 마지막 프레임의 위치로 자동 변경하지 않습니다. 같은 NPC의 이동/연기나 촬영 카메라 시간이 겹치면 생성 오류로 안내합니다.

예제 원본: `/Game/SceneDirector/Examples/LS_ReusablePerformance`
예제 그래프: `/Game/SceneDirector/Examples/DA_SequenceReuse`
실행 예제 맵: `/Game/SceneDirector/Examples/L_SequenceReuse`

예제는 기존 캐릭터의 편안한 자세 애니메이션과 카메라를 2초 동안 재사용한 뒤 일반 대화 노드로 이어집니다. `tools/setup-scene-director-sequence-reuse.py`로 준비할 수 있습니다.

시퀀스 재사용 확장 검증: 자동화 44개, Editor/Shipping 빌드, 실제 캐릭터 애니메이션 및 재사용 카메라의 편집기 렌더링을 확인했습니다. 화면은 `Saved/SceneDirector-sequence-editor.png`에 있습니다. Cook/Stage/패키지 실행은 미검증입니다.


### 기존 시퀀스를 편집 가능한 그래프로 변환

콘텐츠 브라우저에서 **Level Sequence 하나를 선택**한 뒤 연출 툴의 **선택 시퀀스 가져오기**를 누릅니다. 검증에 통과하면 좌측에 `Imported_원본이름` 이벤트가 추가되고 해당 그래프로 전환됩니다. 현재 이벤트와 원본 애셋은 덮어쓰지 않습니다. 같은 원본을 다시 가져와도 별도 이벤트를 만듭니다. 저장 버튼으로 이벤트를 저장하세요. 실행기의 Event Key로 가져온 이벤트를 선택할 수 있습니다.

생성되는 것은 재생용 시퀀스 노드 하나가 아니라 NPC 추가, 캐릭터/카메라 이동, 애니메이션, 카메라 전환, 시작 지연용 대기와 병렬 연결입니다. 원본 Actor의 메시·컴포넌트 설정은 내부 생성 템플릿으로 보존합니다. NPC BP를 변경하면 원본 템플릿이 초기화되어 새 BP 기본값을 사용합니다. 등록된 NPC/카메라 Key는 우측 목록에서 바꿀 수 있습니다.

**경유점 리스트**: 이동 노드에서 ‘경유점 리스트 사용’을 켭니다. 첫 점은 0초, 시간은 오름차순이며 30fps 프레임 단위(예: 0, 0.5, 1초)입니다. 각 점의 월드 위치, Roll/Pitch/Yaw, 스케일과 다음 점까지의 직선/부드럽게/즉시 변경을 편집합니다. 마지막 점의 시간이 이동 시간이 됩니다. 경유점 입력은 절대 월드 값이며 기존 단일 목표의 String Key·현재 값 입력은 리스트를 끈 상태에서 사용합니다. ‘뷰포트 위치 가져오기’는 리스트의 마지막 점에 적용됩니다.

변환된 점의 ‘원본 축별 곡선 유지’는 축마다 다른 키 유무와 탄젠트·가중 탄젠트를 보존합니다. 새 점은 직선/부드럽게/즉시 변경을 선택하세요. 회전은 Euler 값을 보존하므로 360도 이상의 회전도 유지됩니다. 캐릭터 이동에서 ‘이동 중 애니메이션 재생’을 끄면 별도의 애니메이션 노드와 병렬로 연결할 수 있습니다. 자동 걷기·달리기는 전체 경유점 직선 거리 합/전체 시간의 평균 속도를 기준으로 선택합니다.

**애니메이션 블렌딩**: 블렌드 인/아웃 시간, 곡선, 가중치, 시작/끝/첫 루프 오프셋, 역재생을 설정합니다. 재생 속도 직접 설정을 끄면 남은 애니메이션 구간을 노드 시간에 맞추고, 켜면 입력한 속도로 재생·반복합니다. 서로 겹칠 두 애니메이션은 각각 ‘다른 애니메이션과 중첩 허용’을 켜고, 병렬 경로의 대기 노드로 겹치는 시점을 만드세요. 블렌드 인과 블렌드 아웃 각각은 노드 시간을 넘을 수 없으며, 두 구간끼리는 원본 시퀀서처럼 겹칠 수 있습니다. 완료 대기를 끄는 것만으로 자동 크로스페이드가 만들어지지는 않습니다.

**원본 비교**는 원본의 읽기 전용 복사본을 현재 미리보기와 같은 경과 시간에서 보여줍니다. ‘생성 및 미리보기’를 누르면 같은 시간의 변환 결과로 돌아옵니다. 원본은 수정하지 않습니다. 원본을 나중에 변경해도 가져온 노드는 자동으로 바뀌지 않으므로 다시 가져와 별도 이벤트에서 비교하세요.

현재 자동 변환 범위:
- 재생 시작부터 종료까지 유지되는 Spawnable Actor와 표준 Spawnable Actor 바인딩.
- 전체 구간의 단일 절대 Transform 섹션: 위치·Euler 회전·스케일, 축별 상수/선형/큐빅 및 가중 탄젠트. 반복 외삽·쿼터니언·Transform 중첩 블렌딩은 제외.
- 일반 AnimSequence 섹션: 고정 재생 속도, 오프셋, 역재생, 상수 가중치, 기본 이징 곡선, 겹치는 클립. Restore State 종료 방식 지원. Keep State, 시간 왜곡, 루트 모션 매칭/스왑, 가장 가까운 섹션 평가, 가중치 곡선, 사용자 정의 이징은 제외.
- 범위 내부의 하드 카메라 컷. 컷 크로스페이드는 현재 자동 변환 제외.
- 노드 경계 및 키 시간이 30fps로 정확히 표현되어야 합니다. 원본 틱 해상도가 달라도 해당 조건을 만족하면 변환합니다. 근사 샘플링으로 오차를 숨기지 않습니다.

외부 Possessable, 컴포넌트 트랙, Event, Control Rig, 중첩 시퀀스, Audio 및 일반 속성 트랙 등은 아직 자동 노드 변환 대상이 아닙니다. 실행할 Notify가 있는 애니메이션도 중단 사유를 표시합니다. 지원하지 않는 데이터가 있으면 일부만 생성하지 않고 이유를 반환합니다. 기존 ‘레벨 시퀀스 재생’ 노드의 지원 범위는 자동 변환 범위보다 넓으며, 전환이 어려운 구간은 그 방식으로 병행할 수 있습니다.

예제 원본: `/Game/SceneDirector/Examples/LS_GraphConversionDemo`
변환 그래프: `/Game/SceneDirector/Examples/DA_ImportedPerformance`
실행 맵: `/Game/SceneDirector/Examples/L_ImportedPerformance`
`tools/setup-scene-director-import.py`로 준비합니다. 원본에는 곡선 이동과 달리기→대기 자세 블렌딩이 들어 있으며, 변환 그래프에서는 이를 독립 노드로 편집할 수 있습니다.

변환 확장 검증: 자동화 51개, Editor/Shipping 빌드, 실제 블렌딩 포즈 비교, 원본 곡선 수치 비교, 저장·재열기와 비교 UI 렌더링을 확인했습니다. 화면은 `Saved/SceneDirector-import-editor.png`입니다. Cook/Stage/패키지 실행은 미검증입니다.

## 조건에 따른 이벤트 실행과 대화 UI

레벨의 석상을 선택하고 `Ac_SceneDirectorInteraction` 컴포넌트에서 **실행할 연출**만 지정합니다. 최초 이벤트·반복 이벤트·완료 선택지·원본 방문 변수·실행 방식 설정은 제거했습니다. 원본 석상 BP와 체크포인트 Level Sequence는 별도 보존되어 있습니다.

연출 툴 우측 **공용 변수**에 Boolean / Integer 변수와 초기값을 등록합니다. 모든 이벤트 그래프가 같은 변수 목록을 사용합니다. 좌측에서 이벤트를 선택한 뒤 아래 **이벤트 실행 조건**에 변수 Key와 비교값을 지정합니다.

- Boolean: true / false 일치.
- Integer: 같음, 다름, 초과, 이상, 미만, 이하.
- 한 이벤트의 조건은 전부 만족해야 합니다. 여러 이벤트가 만족하면 목록에서 위쪽 이벤트가 먼저 실행됩니다. 조건이 없으면 항상 실행 대상이 되므로 먼저 놓인 무조건 이벤트가 뒤의 이벤트를 가리지 않도록 주의하세요.
- 조건을 만족하는 이벤트가 없거나 Key가 잘못되면 실행하지 않고 컴포넌트의 `LastError`로 이유를 반환합니다.
- **변수 설정**과 **Integer 변수 설정** 노드로 값을 바꿉니다. 정상 종료한 결과는 같은 컴포넌트의 다음 재생에 유지됩니다. 취소·실패하면 이번 실행의 변경을 저장하지 않습니다. 액터별 상태는 독립적이며, 원본 애셋 초기값을 덮어쓰지 않습니다. 이 컴포넌트 단독 실행의 상태는 월드 생존 기간입니다. 이벤트 배치의 변수 영속 저장을 켜면 아래 SaveGame 연동 경로를 사용합니다.

석상은 공용 Boolean `HasInteracted=false`에서 시작합니다. 최초 그래프는 false, 반복 그래프는 true를 조건으로 사용합니다. `쉰다` 경로의 변수 설정 노드가 true를 기록하고 정상 종료하면 다음 상호작용부터 반복 그래프를 선택합니다. `쉬지 않는다`와 중단은 최초 상태를 유지합니다. 기존 Actor BP의 HasInteracted에는 의존하지 않습니다.

대사 노드의 새 설정:

- **대사창 유지**: 기본 true. 대사가 끝난 뒤 다음 대사가 시작될 때까지 현재 문장을 유지합니다. false면 해당 대사 종료 시 닫습니다. 게임 플레이 복귀·연출 종료·취소 시에는 항상 닫습니다.
- **화면 위치**: 상단 / 중단 / 하단. 기본 하단이며 석상 HP 회복 안내는 중단으로 설정했습니다. 편집기 미리보기에도 적용됩니다.
- **화자 표시명**: 비어 있거나 공백뿐이면 이름표 배경까지 숨깁니다. NPC Key를 대신 표시하지 않습니다.
- 본문·화자·선택지 글자는 이전 대비 약 70% 크기입니다.

이동·시점 조작을 잠그는 연출은 게임 UMG 위젯과 HUD를 자동으로 숨깁니다. 연출 중 새로 추가된 위젯도 숨기며, 제어권 반환·취소·종료 시 이전 표시 상태를 복원합니다. Slate로 출력하는 연출 대화 UI는 숨김 대상에서 제외됩니다.

NPC 추가/기존 캐릭터 연결 노드의 **플레이어 대역 (제어권 복귀 시 숨김)**은 실제 플레이어 대신 등장하는 NPC에 사용합니다. 석상 Heroine에 적용했습니다. 제어권 복귀 시 플레이어 표시 복원과 대역 숨김을 같은 평가에서 처리하며, 이후 연출 모드 재진입 시 대역의 이전 표시 상태를 복원합니다. 다른 일반 NPC를 함께 숨기지 않습니다. 석상에서 한 프레임 먼저 대역을 숨기던 표시 키도 제거 효과가 나도록 수정했습니다.

**기존 오브젝트**는 우측 목록에 Key·클래스·Actor 태그를 등록합니다. NPC 연결 노드와 카메라 목록의 기존 오브젝트 Key에서 사용합니다. 단순화된 상호작용 컴포넌트는 별도 오브젝트 연결 설정을 받지 않고 등록된 유일한 Actor 태그로 찾습니다. 일반 SceneDirectorPlayer의 수동 Actor 연결 기능은 유지됩니다.

**기준 좌표**는 연출 애셋 공통 설정입니다. `상호작용 Actor를 배치 기준으로 사용`을 켜면 소유 Actor의 위치·회전에 맞춰 전체 연출을 이동합니다. 스케일은 적용하지 않습니다. 석상의 제작 기준은 위치 `(-34550, -16750, 1750)`, Yaw `90°`입니다. 툴 미리보기는 제작 좌표에서 보여줍니다.

이번 수정 이관 도구는 `tools/upgrade-scene-director-events.py`입니다. 이관 전 연출·파생 BP·맵 백업은 `Saved/DirectorRefactor/Backup`에 있습니다. 원본 시퀀스 4개와 석상 BP의 파일 해시는 그대로 유지했습니다.

이번 수정 검증: 자동화 61개 통과, Editor·Shipping 빌드 통과. 조건 선택·Integer 비교·상태 보존/취소·액터별 독립 상태·대화 유지/닫기·빈 화자·대역 인계 및 재진입을 확인했습니다. 실제 Slate 대사창과 석상 맵 에디터를 렌더링해 글자 크기·화면 위치·조건 패널을 확인했습니다. 직접 PIE 조작과 패키지 실행은 수행하지 않았습니다. 화면: Saved/SceneDirector-conditions-editor.png, Saved/SceneDirector-dialogue-bottom-small.png, Saved/SceneDirector-dialogue-center-small.png.

## 이벤트 배치 도구 1차 구현

연출 편집 화면 상단의 **이벤트 배치**, 또는 **도구 → Scene Director · 이벤트 배치**를 엽니다. 레벨 뷰포트 옆에 도킹하여 사용하세요.

1. **이벤트 추가**에서 영역 진입 / 상호작용 / 전투 종료 / 레벨 준비 완료 / Actor 파괴를 선택합니다.
2. 뷰포트에서 대상 Actor를 선택하고 **선택 Actor를 대상으로**를 누르거나 우측 대상 필드에서 지정합니다. 영역은 대상 없이 배치 Actor 자체의 Box를 사용할 수도 있습니다.
3. **실행할 연출**을 지정합니다. 필요한 경우 배치 기준과 오브젝트 Key별 Actor 연결을 설정합니다.
4. **연출 생성·검사**, **전체 검사**, **레벨 저장**을 실행합니다.
5. PIE에서 실제 발동 또는 **PIE 발동 시험**을 사용합니다. 발동 시험은 조건과 대기 정책을 적용하며 게임 액션도 실행합니다. 시각 확인만 원하면 기존 연출 편집의 미리보기를 사용하세요.

현재 제공 범위:

- 월드 공통 실행기, 연출 인스턴스별 Boolean/Integer 상태, 같은 애셋의 상태 공유 그룹.
- 매번 / 이번 레벨 방문에서 1회 / 저장 데이터 기준 1회. 정상 종료 때만 완료 처리하며 취소·실패는 변수 변경을 반영하지 않습니다.
- 영역 진입 감지, 초기 겹침 opt-in, 퇴장 후 재진입, 대기 중 영역 이탈 취소.
- 기존 Ac_SceneDirectorInteraction의 RouteInteraction 경로 연결. 등록된 배치가 우선하며 비활성화하면 기존 경로로 우회 재생하지 않습니다. 컴포넌트만 붙인 일반 Actor는 프로젝트 상호작용에서 RouteInteraction을 호출하는 연결도 필요합니다.
- Actor 파괴 신호와 당시 좌표 보관. 레벨 언로드는 파괴로 취급하지 않습니다.
- 명시적 전투/준비 신호 처리 API, 64개 대기열, 최근 100개 실행 기록.

### 화자 데이터 관리 제안 (이번에는 설계만 정리)

현재 원본은 `/Game/Constellation/Gameplay/Sequences/Data/DT_SequenceStringData` **DataTable**입니다. 이름에 ST가 들어간 `ST_StringData`는 행 구조로 사용되므로 Unreal String Table과 구분해야 합니다. 현 연출 이관 코드는 대사 행의 FText를 노드에 복사하고, 화자명은 별도 FText로 받습니다.

추천은 **화자 전용 테이블 + 대사 행의 화자 참조**입니다.

| 위치 | 저장할 내용 | 기획자 작업 |
|---|---|---|
| 새 `DT_SpeakerData` | 행 이름을 화자 Key로 사용, `DisplayName`은 FText | 화자 이름을 한 번 등록 |
| 기존 `DT_SequenceStringData` | 기존 대사 유지, `SpeakerKey` 참조 열 추가 | 대사마다 화자 목록에서 선택 |
| 연출 대사 노드 | 대사 행 참조, 화자 사용 방식(대사 기본값 / 다른 화자 / 없음) | 대사 선택 시 기본 화자 자동 적용 |

이름을 모든 대사 행에 직접 적으면 이름 변경과 번역 검수가 반복됩니다. 별도 화자 테이블로 분리하면 화면 밖 화자·내레이션도 NPC 배치와 무관하게 관리할 수 있습니다. 이름을 밝히기 전에는 `Girl_Unknown → ???`, 이후에는 별도 공개 이름 항목을 사용합니다. `없음`은 이름판을 숨기고, 잘못된 Key는 조용히 숨기지 않고 검증 오류로 표시합니다.

대사 노드가 텍스트 복사본만 들고 있는 현재 방식도 함께 개선해 대사 행과 화자를 참조하도록 연결해야 합니다. 기존 노드는 직접 입력 방식으로 유지하고, 참조 방식으로 전환할 때 원본 대사 Key를 연결하는 절차가 필요합니다. 이번 수정에서는 원본 대사 테이블과 행 구조를 바꾸지 않았습니다.

참고: 실제 Unreal String Table의 CSV는 Key·SourceString이 기본이며 추가 열은 메타데이터입니다. 따라서 그 형식을 선택하더라도 화자 이름은 별도 번역 가능한 엔트리로 관리하는 편이 명확합니다. [Epic 공식 문서](https://dev.epicgames.com/documentation/unreal-engine/using-string-tables-for-text-in-unreal-engine)

검증: Editor 모듈 빌드 성공, 변환 후 자동화 81개 통과, 실제 학교 맵 EditorSmoke 및 화면 캡처 통과, 4개 연출·소녀 중단/재실행·입력 복원·저장 후 석상 반복 분기 선택 통과. 종합 기록은 `Saved/SceneAuthoringRefinement/result.json`입니다. Shipping 패키지는 갱신하지 않았습니다.
