# 기획자용 노드 기반 시퀀서 도구 제작 계획서

작성일: 2026년 10월 3일
상태: 검토용 초안
가칭: Constellation Scene Director

기획자 1명이 AI를 개발 파트너로 활용해 도구를 제작·유지보수하며, 캐릭터, 위치, 시간, 카메라 구도만 입력하고 노드를 연결해 연출을 제작하는 언리얼 플러그인을 제안한다. 그래프는 실행 순서와 분기를 관리하고, 시퀀서는 시간에 따른 움직임과 카메라 연출을 담당한다. 첫 목표는 NPC 추가부터 미리보기와 게임 내 재생까지 연결된 작은 도구를 완성하는 것이다.

## 1 목표와 전제

사용자 요구는 노드 연결 방식, 간단한 파라미터, 시각적 미리보기, NPC BP와 위치만으로 자동 구성하는 기능이다. 상세 기능은 제작 중 구체화한다. 첨부 이미지는 왼쪽 목록·중앙 그래프·오른쪽 공유 데이터의 배치 참고로 사용하며, 이미지의 모든 노드를 필수 요구로 간주하지 않는다.

이번 계획은 UE 에디터 내부 C++ 플러그인, 단일 플레이어의 게임 내 연출, 한 번에 하나의 연출 실행을 기본 가정으로 한다. 프로젝트의 Constellation.uproject에서 EngineAssociation 값 5.8을 확인했다. 설치 엔진의 정확한 빌드와 API 호환성은 첫 단계에서 확인한다. 본 문서는 제안이며 구현·실행 검증 완료를 의미하지 않는다.

## 2 제작 방식 비교

| 방식 | 장점 | 제약 | 판단 |
| --- | --- | --- | --- |
| 에디터 유틸리티 중심 | 입력 폼과 자동 생성을 빠르게 시험 | 복잡한 그래프와 실행 디버깅 확장에 한계 | UX 실험에 활용 가능 |
| 전용 그래프와 시퀀서 연동 플러그인 | 노드 UI, 기존 자산 활용, 실행 제어 확장 | 편집과 실행 계층을 함께 설계해야 함 | 권장 |
| 독자 타임라인과 재생 시스템 | 모든 동작을 자체 설계 | 보간·카메라·애니메이션 평가 중복 개발 | 초기 범위 제외 |

기존 StateTree 등의 재사용은 기술 검증에서 검토한다. 도구의 병렬 실행과 미리보기 규칙에 적합한지 확인한 뒤 결정하며, 처음부터 특정 실행 체계에 종속시키지 않는다.

## 3 기획자 작업 흐름

1. 연출 그래프 에셋을 만들고 레벨과 시작 조건을 선택한다.
2. NPC 추가 노드에 BP를 넣고 뷰포트에서 위치를 지정한다.
3. 카메라 샷 노드를 연결하고 대상과 구도를 선택한다.
4. 이동·애니메이션·대기·게임 액션을 필요에 따라 연결한다.
5. 미리보기에서 현재 노드와 카메라 화면을 확인하고 수정한다.
6. 검증·저장 후 PIE와 패키지 빌드에서 실행한다.

대표 예제는 시작 → NPC 추가 → 카메라 샷 → 애니메이션 → 게임 액션 → 종료다. 기획자가 Director Blueprint나 이벤트 키의 내부 연결을 직접 만들 필요가 없도록 한다.

## 4 화면 설계

| 영역 | 기능 | 편의 원칙 |
| --- | --- | --- |
| 상단 | 저장, 검증, 미리보기, 중지, 게임에서 확인 | 실행 불가 원인을 바로 표시 |
| 왼쪽 | 연출 목록, 시작 조건, 노드 검색, 템플릿 | NPC·카메라·흐름·게임 액션으로 분류 |
| 중앙 | 그래프, 그룹, 주석, 실행 상태 | 노드에는 대상과 동작 요약만 표시 |
| 오른쪽 | 선택 노드 속성, 역할·위치·변수 목록 | 필수 입력 우선, 고급 설정 접기 |
| 하단 | 카메라 미리보기, 현재 구간 시간 막대, 오류 | 오류 선택 시 해당 노드와 속성으로 이동 |

BP 썸네일, 카메라 구도 프리셋, 위치 핸들, 이동 경로를 통해 숫자 입력을 줄인다. Undo/Redo, 복사·붙여넣기, 검색, 정렬은 기본 편집 기능으로 제공한다. 초기에는 기존 레벨 뷰포트를 활용하고 별도 미리보기 뷰포트는 검증 결과에 따라 확장한다.

## 5 그래프 실행 규칙

외형은 State Machine 형태로 구성하되, 초기 모델은 동작 완료에 따라 다음 노드로 이동하는 연출 흐름 그래프로 정의한다. 기획자가 각 상태의 Enter·Tick·Exit를 직접 작성하게 하지 않는다. 지속 상태가 필요해지면 상위 상태 안에 연출 그래프를 넣는 방식으로 확장한다.

| 항목 | 제안 규칙 |
| --- | --- |
| 순차 | 이전 노드가 완료되면 다음 노드 실행 |
| 완료 | NPC는 생성·바인딩 완료, 카메라는 지정 시간 종료, 비동기 액션은 완료 통지 |
| 분기 | 조건 평가로 하나의 경로 선택 |
| 병렬 | 명시적인 병렬 노드로 시작하고 합류에서 모든 경로 완료 대기 |
| 실패 | 기본적으로 중단하고 원인 표시. 이후 실패 경로 지원 |
| 취소 | 활성 동작 취소, 임시 객체와 제어 상태 정리 |
| 반복 | MVP는 순환 연결 금지. 이후 최대 횟수·종료 조건을 가진 반복 지원 |
| 재호출 | 동일 연출 실행 중에는 거부하고 실행 상태 반환 |

다중 연결선만으로 병렬과 합류를 암묵적으로 만들지 않는다. 같은 NPC 위치 또는 화면 카메라를 동시에 제어하면 검증 오류로 처리한다. 분기에 따라 총 길이가 달라질 때는 선택한 경로 기준의 시간만 보여준다.

| 시작·종료 | 시작 방식, 정리 정책 | 실행 수명 관리 | MVP |
| NPC 추가 | BP, 위치 | 역할 등록, 생성·바인딩, 위치 트랙 | MVP |
| 카메라 샷 | 대상, 구도, 시간 | 카메라 및 관련 트랙 | MVP |

| 시퀀스 재생 | 기존 시퀀스, 역할 연결 | 기존 자산 재생 | MVP |
| 게임 액션 | 등록된 액션, 대상, 파라미터 | 공통 인터페이스로 BP 호출 | MVP에서 대표 액션 1개 |

첫 이동 기능은 연출용 위치 이동이다. 내비게이션, 장애물 회피, 루트 모션은 별도 범위로 둔다. 대사·퀘스트·저장은 프로젝트별 게임 액션으로 연결한다. 모든 시퀀서 기능의 일괄 노드화는 목표로 삼지 않는다.

## 7 NPC 추가 설계

기본 입력은 BP와 위치 두 가지다. 역할 이름은 자동 생성한다. 위치는 뷰포트 클릭, 기준점 선택, 좌표 입력을 지원하고 내부적으로 위치·회전·스케일을 저장한다.

1. BP의 Actor 적합성과 컴포넌트 구성을 검사한다.
2. 연출 안에서 유지되는 역할 ID를 발급한다. 다른 노드는 이 ID로 NPC를 참조한다.
3. 적용 또는 미리보기 시 생성·바인딩과 위치 트랙을 구성한다.
4. 위치 수정은 원본 데이터에 반영하고 변경 구간만 갱신한다.
5. BP 교체 시 역할 연결은 유지하고 스켈레톤·컴포넌트 호환성을 다시 검사한다.
6. 중지·재실행 때 중복 NPC가 남지 않도록 정리한다.

연출 전용 NPC는 Spawnable을 우선 활용하고, 기존 NPC는 기존 Actor를 바인딩한다. 단순 NPC 생성에는 반드시 커스텀 이벤트 키가 필요한 것은 아니다. Unreal은 임시 생성 Actor와 기존 Actor 바인딩을 지원한다. [Epic Spawnables와 Possessables 문서](https://dev.epicgames.com/documentation/en-us/unreal-engine/spawn-temporary-actors-in-unreal-engine-cinematics)

여러 분기 구간에 걸쳐 유지할 NPC는 실행기가 소유하고 각 구간에 바인딩하는 정책을 추가한다. 한 Actor를 두 계층에서 동시에 생성하지 않는다. 임의 BP의 AI·BeginPlay·Construction Script가 모두 자동 대응된다고 가정하지 않는다. 대표 BP로 지원 범위를 검증하고 필요하면 연출 어댑터를 제공한다.

## 8 시스템 구성

기획자 입력 → 그래프 원본 에셋 → 검증·변환 → 실행 데이터와 Level Sequence 구간 → 런타임 실행기 → 화면 연출과 게임 액션 순서로 구성한다.

### 편집기 모듈

새 플러그인에 그래프 UI, 에셋 편집, 검증, 시퀀서 생성, 미리보기 제어를 둔다. 구현 후보는 Slate 기반 에셋 편집기와 UEdGraph/SGraphEditor다. 정확한 API와 의존성은 설치 엔진에서 검증한다. 기존 리소스 도구와 책임을 분리한다.

### 런타임 모듈

실행 데이터, 실행기, 역할 바인딩, 액션 인터페이스를 담당한다. 편집기 모듈과 UI 클래스에 의존하지 않으며 패키지 빌드에서도 동작해야 한다.

### 원본 데이터와 생성 데이터

원본에는 안정적인 노드 ID, 타입별 파라미터, 연결, 역할 ID, BP 참조, 기준점, 타입이 있는 변수와 초기값, 데이터 버전을 저장한다. 그래프 화면 좌표 등 편집 전용 정보는 런타임 데이터와 분리한다.

고정 시간 구간은 Level Sequence로 생성한다. 조건 분기와 완료 시간이 유동적인 액션은 실행기가 처리한다. 노드 ID와 생성 트랙·구간의 대응 정보 및 원본 버전을 저장해 오류를 원래 노드로 연결한다.

### BP 액션 계약

기획자는 개발자가 등록한 액션을 선택한다. 액션 정의에는 대상 타입, 노출 파라미터, 동기·비동기 여부, 완료·실패 통지, 제한 시간, 취소 방식, 미리보기 허용 여부를 둔다. 첫 예제는 문 열기처럼 작고 명확한 액션으로 한다.

프레임 단위 호출은 Event Track 연결을 자동 생성하는 경로를 기술 검증한다. Unreal의 Event Track은 엔드포인트와 파라미터 연결을 지원한다. 실행기와 이벤트 트랙이 같은 액션을 중복 호출하지 않도록 호출 주체를 하나로 정한다. [Epic Event Track 문서](https://dev.epicgames.com/documentation/en-us/unreal-engine/cinematic-event-track-in-unreal-engine)

## 9 수동 편집과 재생성

자동 생성 구간은 그래프를 원본으로 삼는다. 같은 입력으로 갱신해도 트랙과 바인딩이 중복되지 않게 하고, 변경 구간만 재생성한다. 생성 성공 후 결과를 교체하고 실패하면 마지막 정상 결과를 보존한다. 원본 변경 후 오래된 결과가 남아 있으면 명확히 표시한다.

정교한 수동 연출은 별도 시퀀스 에셋으로 저장해 시퀀스 재생 노드에서 참조한다. 자동 생성 결과의 직접 수정은 감지·경고하고 수동 에셋으로 분리할 수 있게 한다. 초기에는 시퀀서 수정 내용을 그래프로 역변환하는 완전한 양방향 동기화를 제공하지 않는다.

## 10 미리보기와 복구 정책

- 일반 미리보기는 위치·카메라·지원 애니메이션을 대상으로 한다. 게임 상태 변경 액션은 실행하지 않고 표시한다.
- 게임 로직은 PIE에서 확인한다. 에디터 실행은 미리보기 허용 계약이 있는 액션에 한정한다.
- 시간 막대 역이동 시 임의 BP 이벤트를 재실행하지 않는다. 시각적 스크럽과 게임 로직 재생을 구분한다.
- MVP는 처음부터 재생과 시각적 구간 탐색을 지원한다. 임의 노드부터 재생은 앞선 역할·변수 복원 체계가 필요하므로 후속 범위다.
- 실행 전 카메라와 변경 대상 상태를 기록한다. 정상 종료·중지·오류·PIE 종료에서 도구 소유 변경을 정리한다.
- 위치·애니메이션의 유지·복구 정책을 명시한다. 임의 BP의 모든 부작용을 자동 복구한다고 보장하지 않는다.
- AI와 시퀀서가 동시에 NPC 위치를 제어하지 않도록 제어권 인계 규칙을 마련한다.

## 11 단계별 작업 계획

실제 운영 목표는 기획자 1명과 AI 개발 지원이다. 기획자는 요구와 시각 결과를 판단하고 AI는 구현·빌드·테스트·수정을 담당한다. 아래 기간은 최초 계획의 사람 개발자 기준 참고치로만 보존하며, AI 작업의 소요 시간으로 사용하지 않는다. 진행은 검증 가능한 결과물 단위로 관리한다.

| 단계 | 작업 | 완료 기준 | 예상 작업일 |
| --- | --- | --- | --- |
| 0 기술 검증 | 엔진 확인, NPC·카메라 생성, 이벤트 연결, 패키지 시험 | 대표 BP와 카메라가 에디터·PIE·패키지에서 재생되고 중지 후 정리됨 | 3~5 |
| 1 편집기 기반 | 모듈, 원본 에셋, 그래프, 속성, 저장, Undo/Redo | 재열기 후 연결·속성 유지 | 5~8 |
| 2 MVP | NPC, 카메라, 대기, 기존 시퀀스, 대표 액션, 기본 미리보기 | BP 내부 편집 없이 대표 연출 작성과 게임 실행 | 8~12 |
| 3 흐름 확장 | 이동, 애니메이션, 분기, 병렬·합류, 액션 취소 | 분기·병렬 샘플에서 실행과 정리 검증 | 8~12 |
| 4 실사용 정리 | 프리셋, 오류 안내, 사용성 검증, 가이드 | 배포 가능한 플러그인과 샘플 완성 | 5~8 |

MVP까지 16~25작업일, 전체 29~45작업일을 초기 범위로 본다. 대규모 기존 자산 변환, 복잡한 캐릭터 체계 대응, 멀티플레이, 대사 시스템은 제외한다. 각 단계에서 실제 연출 하나로 기획자 리뷰를 진행하고 노드 이름, 입력 수, 위치 지정, 오류 이해도, 작업 시간을 기준으로 다음 범위를 조정한다.

## 12 검증 기준

| 구분 | 확인 항목 | 통과 기준 |
| --- | --- | --- |
| 데이터 | 저장, 재열기, 복사, Undo/Redo | 연결·파라미터·역할 ID 유지 |
| 생성 | 재생성, 노드 삭제, BP 교체 | 중복 없음, 제거 결과 정리, 수동 자산 보존 |
| 실행 | 완료, 실패, 취소, 재호출 | 정의한 흐름과 정리 정책 준수 |
| 시간 | 프레임 변환, 구간 경계, 합류 | 프레임률별 일관성, 완료 통지 중복 없음 |
| 미리보기 | 재생·중지·스크럽 반복 | 우발적인 게임 액션과 NPC 중복 생성 없음 |
| 패키징 | 편집기 의존 분리, 자산 포함 | Windows 패키지에서 동일 샘플 재생 |
| 사용성 | 새 연출 작성, BP와 위치 교체 | 기획자 2~3명이 BP 내부 편집 없이 완료 |

사용성 목표는 짧은 안내 후 NPC 1명과 카메라 샷 1개를 포함한 연출을 10분 이내에 작성하는 것으로 제안한다. 기존 작업 시간을 측정해 조정한다. 반복 재생은 최소 20회 시험하고, 50노드·역할 5개 정도의 샘플에서 편집 반응과 생성 시간을 측정해 성능 기준을 정한다.

## 14 제작하면서 구체화할 사항

계획 검토 시 최초 사용 사례를 정한다. 아직 정해지지 않았으므로 NPC 등장과 카메라 전환이 있는 짧은 컷신을 기준 예제로 제안한다. 0단계에서는 대표 NPC BP·샘플 레벨·AI와 플레이어 제어권 정책, 2단계에서는 NPC 유지 여부·구도 프리셋·미리보기 방식, 3단계에서는 실제 필요한 분기와 병렬 사례를 결정한다.

기존 시퀀스 완전 자동 변환, 멀티플레이, 협업 충돌 해결 UI는 후속 요구가 확인되면 별도 계획한다. 최종 산출물은 편집기·런타임 플러그인, 그래프 에셋과 프리셋, 샘플 레벨, BP 연동 예제, 기획자 가이드, 지원 범위와 제약 문서다.
