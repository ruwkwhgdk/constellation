# 기본 교전 진행: 이동·카메라·타깃 잠금

> 최신 업데이트: [프로젝트 기본 조작값 동기화](2026-10-04-combat-project-controls.md). 현재 이동 속도는 500cm/s이며 아래 168cm/s 기록은 첫 구현 당시의 결과다.

2026-10-04. [전체 기획](2026-10-04-combat-ai-direction.md)의 단계 2 중 이동·시점·타깃 잠금까지 진행했다. 기존 전투 플러그인과 시험장을 확장했으며, 원본 전투 에셋 41개의 해시는 유지되었다.

## 이동 문제와 수정

사용자가 보고한 증상은 “움직이지만 방향이나 카메라가 이상함”이었다. 기존 코드는 비스듬한 고정 카메라를 사용하면서 WASD를 월드 X/Y 축에 직접 연결했다. 따라서 화면 앞쪽과 W의 이동 방향이 달랐다. 컨트롤러의 Yaw가 캐릭터 회전을 덮어쓸 수 있는 설정도 남아 있었다.

카메라 각도 90°, -60°, 180°에서 W 입력을 주입해 방향 불일치를 재현한 뒤 수정했다.

- WASD를 현재 카메라의 수평 방향 기준으로 변환한다.
- 마우스로 시점을 돌린다. 위아래 시점은 -65°~15°로 제한한다.
- Spring Arm이 컨트롤러 시점을 따르고, 카메라 회전이 캐릭터의 방향을 강제로 덮어쓰지 않도록 했다.
- 캐릭터는 이동 방향을 바라본다. 잠금 상태에서는 공격 시작 시 대상을 바라본다.
- 공격 중 새 이동 입력과 잔여 속도를 정리한다. 공격 확정 시점에도 즉시 정지시켜 다음 프레임까지 남는 이동을 막는다.

## 추가한 기능

**Tab 타깃 잠금:** 화면 전방의 살아 있는 적을 선택한다. 선택 거리 900cm, 유지 거리 1,100cm다. 다시 Tab을 누르거나, 대상 사망·거리 초과·벽에 의한 시야 차단 시 해제된다. 잠금 중 카메라는 대상을 따라가고 마우스 자유 회전은 잠시 멈춘다. 대상 위에 청록색 표시가 보인다.

**이동 모션:** 유지 중인 RunSoft를 168cm/s 기준으로 연결하고 대기 모션도 지정했다. 몽타주가 실행 중일 때 이동 모션이 공격을 덮어쓰지 않는다. 공격 완료·취소 후에는 이동 속도에 맞는 모션으로 돌아온다. 몬스터에도 기존 대기 모션을 연결했다.

애니메이션 원본이나 캐릭터 체형은 수정하지 않았다. 현재는 단일 노드 재생 방식으로, 대기↔달리기 전환 블렌딩과 전용 옆걸음·후진 모션은 아직 없다. 잠금 이동도 이동 방향을 바라보며 달리는 방식이다.

## 현재 조작

| 입력 | 동작 |
|---|---|
| WASD | 카메라 기준 이동 |
| 마우스 이동 | 자유 시점 회전 |
| Tab | 타깃 잠금/해제 |
| 왼쪽 마우스 | 기본 공격 |
| 오른쪽 마우스 | 시험용 공격 강제 취소 |
| R | 시험장 초기화 |

맵: `/Game/Constellation/Review/CombatCore/L_CombatCore`

실행: 프로젝트 루트에서 `./tools/play-combat-lab.ps1`. 이미 열어둔 이전 시험 실행은 종료한 뒤 다시 시작해야 새 C++ 동작이 적용된다. PIE에서는 플레이 화면을 클릭해 입력을 받은 뒤 조작한다.

기획자는 시험 캐릭터 Details의 Locomotion 항목에서 Idle Animation, Move Animation, Animation Move Speed를 확인할 수 있다. 생성 스크립트는 비어 있는 모션 항목만 채워 기존 선택을 보존한다.

## 다음 구현 단위

단계 2 전체가 끝난 것은 아니다. 다음은 입력 예약·3타 연결·회피·스태미나 회복·피격 반응이다. 현재 2·3타 전용 모션이 미검증이므로 같은 1타를 반복해 완성된 3타로 간주하지 않는다. 무기 소켓 판정과 이동/전투 모션 전환 품질도 별도 보완이 필요하다. 기존 플레이 BP로의 이식, 스킬·궁극기, 기획자 통합 제작 도구는 후속 범위다.
