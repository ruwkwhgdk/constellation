# 이벤트 연출 발동 도구 기획서

작성일: 2026-10-04 · 상태: 설계안 · 대상: 기획자 1인 제작과 AI 개발 지원

## 1. 제작 방향

**기존 연출 툴에 ‘이벤트 배치’ 화면을 추가한다. 기획자는 레벨의 대상과 발동 방식을 선택하고 연출 애셋을 연결한다.** 일상적인 이벤트 배치에 Blueprint 연결 작업이 필요하지 않은 것을 목표로 한다.

| 영역 | 책임 | 예시 |
|---|---|---|
| 이벤트 배치 | 어디서, 무엇을 계기로, 어느 연출을 요청하는가 | 석상 A와 상호작용 → 석상 연출 |
| 연출 애셋 | 어떤 내용의 그래프를 실행하는가 | HasInteracted로 최초/반복 선택 |
| 공통 실행기 | 중복, 대기, 시작·종료, 상태 보관 | 현재 연출 종료 후 다음 요청 실행 |

Ac_SceneDirectorInteraction에 최초·반복 연출, HasInteracted 등을 다시 추가하지 않는다. 해당 컴포넌트는 상호작용 신호를 공통 실행기에 전달하는 역할로 유지한다. 다른 발동 방식의 설정은 별도 이벤트 배치 데이터가 담당한다.

## 2. 현재 기반과 추가 개발

현재는 연출 내부 Boolean/Integer 변수, 이벤트 그래프별 조건과 목록 순서에 따른 그래프 선택, 변수 설정 노드가 구현되어 있다. 석상은 연출 애셋 하나로 최초/반복을 처리한다.

현재 상태는 상호작용 컴포넌트 생존 기간에 유지되고 정상 종료 시 반영된다. 취소·실패하면 해당 실행의 변수 변경을 반영하지 않는다. SaveGame 영속 저장과 공통 대기열은 추가 개발 대상이다.

확인한 전투 코드는 개별 적의 감지·추적·복귀를 제공한다. 특정 전투 전체의 승리 신호와 게임 준비 완료 신호는 기존 Blueprint 연결 지점을 추가 조사해 표준화해야 한다. 아래는 신규 설계이며 이미 구현된 기능을 뜻하지 않는다.

## 3. 기획자 화면과 작업 흐름

상단 작업 모드를 ‘연출 편집 / 이벤트 배치’로 구분한다. 연출 편집의 좌측 그래프 목록과 우측 공용 데이터는 유지한다. 이벤트 배치는 현재 레벨의 모든 발동 지점을 관리한다.

| 화면 영역 | 내용 |
|---|---|
| 좌측 | 이벤트 목록: 이름, 발동 방식, 연결 연출, 검사 상태 |
| 중앙 | 레벨 뷰포트: 선택 영역·대상 강조, 위치 이동 |
| 우측 | 선택한 방식에 필요한 필드만 표시 |
| 하단 | 검사 결과, 최근 발동 기록, 실행되지 않은 이유 |

기획자 작업 순서:

1. 이벤트 추가 → 발동 방식 선택.
2. 뷰포트 선택 가져오기 또는 스포이드로 Actor/Volume 지정. 전투는 등록된 목록에서 선택.
3. 실행할 연출 애셋 지정.
4. 반복 정책과 필요한 대상 연결 확인.
5. 검사 → 미리보기 → 실제 플레이에서 발동 시험.

이벤트에서 연결 연출을 바로 열고, 연출에서 자신을 참조하는 레벨 이벤트를 찾아갈 수 있게 한다. 내부 ID 직접 입력은 기본 작업 흐름에서 제외한다.

### 공통 설정

| 항목 | 규칙 |
|---|---|
| 이름 / 사용 여부 | 알아보기 쉬운 이름, 임시 비활성화 |
| 발동 방식 / 대상 | 방식에 맞는 설정만 표시 |
| 실행할 연출 | 연출 애셋 하나. 실행할 내부 그래프는 애셋 조건이 결정 |
| 반복 정책 | 매번 / 이번 레벨 방문에서 1회 / 저장 데이터 기준 1회 |
| 다른 연출 실행 중 | 방식별 기본값 제공. 고급 설정에서 정책 변경 |
| 연출 배치 기준 | 제작 좌표 / 발동 대상 / 지정 앵커. 위치·회전 적용, 스케일 제외 |
| 대상 연결 | 연출에서 요구하는 오브젝트 Key에 레벨 Actor 연결 |

저장 데이터 기준 1회는 SaveGame 연결이 완료된 단계에서 노출한다. 이벤트 영구 ID는 자동 생성하고 복제 시 새로 발급한다. 이름을 바꿔도 이력이 유지되어야 한다.

대상 연결은 레벨 배치 정보로 관리한다. 기존 ActorTag 탐색은 호환용으로 유지하되 중복이면 오류를 표시한다.

## 4. 다섯 가지 발동 방식

### 영역 진입

기존 TriggerVolume을 선택하거나 ‘영역 생성’으로 Box 영역을 만든다. 기본 대상은 플레이어다. 여러 충돌 컴포넌트가 진입해도 Actor 기준으로 한 번 요청한다.

- 밖에서 안으로 들어오는 순간 발동한다.
- 반복 이벤트는 완전히 나간 뒤 다시 들어와야 재발동한다.
- ‘시작부터 영역 안에 있으면 실행’ 옵션은 기본 꺼짐. 켜면 게임 준비 완료 시 겹침을 검사한다.
- 다른 연출 중에는 대기한다. 시작 직전에 아직 영역 안인지 검사하고 나갔다면 취소한다.
- 정상 종료 후 영역 안에 서 있다는 이유로 반복 실행하지 않는다.

### 특정 Actor 상호작용

기존 상호작용 시스템에서 상호작용이 확정된 순간 요청한다. 연출 시스템이 키 입력을 별도로 감지하지 않는다.

- 기본 반복은 매번. 최초/반복 내용은 연출 내부 변수로 결정한다.
- 다른 연출 중이면 대기시키지 않고 ‘현재 연출 중’으로 거절한다. 이후 다시 상호작용한다.
- 종료·취소 시 상호작용 가능 상태를 복구한다.
- 기존 석상 연결과 신규 이벤트 배치가 동시에 요청하지 않도록 연결 경로를 하나로 통일한다.
- 공통 상호작용 규약을 지원하지 않는 Actor는 검사에서 알리고 최초 한 번 개발용 어댑터를 제공한다.

### 특정 전투 종료

전투 그룹을 선택하고 결과 조건을 승리/패배/결과 무관 중 고른다. 기본은 승리다. 전투 그룹 ID는 개별 몬스터 AI 프로필과 분리한다.

전투 관리자는 전투 인스턴스 ID와 결과를 포함한 완료 신호를 보낸다. 웨이브 전투는 마지막 웨이브까지 기다린다. 적 Actor 파괴, 추적 포기, 잠시 생존 적이 0명인 상태만으로 승리를 추정하지 않는다.

- 다른 연출 중이면 신호를 보관해 종료 후 실행한다.
- 같은 전투 인스턴스의 완료 중복 통지는 통합한다.
- 전투 재시작은 새 인스턴스로 구분한다.
- 고정 전투는 등록된 적 목록으로 그룹을 만들 수 있지만 증원·웨이브는 전투 시스템의 명시적 완료 판정을 사용한다.

### 레벨 로드 완료 후

표시 명칭은 ‘레벨 시작 준비 완료’로 한다. 필수 레벨 로딩, 플레이어 생성·소유, 저장 상태 복원, 기본 카메라·UI 준비가 끝난 후 한 번 통지한다. BeginPlay 또는 임의의 N초 지연으로 준비를 추정하지 않는다.

- 기본 반복은 이번 레벨 방문에서 1회다.
- 스트리밍 하위 레벨 재로딩은 전체 레벨 재방문으로 보지 않는다.
- 첫 게임 시작에만 필요한 연출은 저장 이력 또는 연출 내부 저장 변수로 구분한다.
- 동시에 등록된 시작 연출은 목록 순서로 요청한다.
- 준비가 늦으면 미충족 항목을 기록하며 준비 조건을 무시하고 재생하지 않는다.

### 특정 Actor 파괴

대상 Actor의 게임플레이 중 실제 제거를 감지한다. 레벨 언로드, PIE 종료, 단순 숨김은 제외한다. HP 0과 Actor 파괴가 다르면 별도 사망 신호를 연결해야 한다.

- 기본 반복은 이번 레벨 방문에서 1회다.
- 다른 연출 중이면 파괴 시점 위치·회전을 복사해 보관한다.
- 파괴되는 Actor의 컴포넌트가 연출 재생 수명을 소유하지 않는다.
- 파괴 Actor를 이후 카메라 타깃 등으로 요구하면 검사 오류로 처리한다. 위치 스냅샷이나 별도 앵커를 사용한다.
- 최초 버전은 레벨 배치 Actor를 지원한다. 동적 생성 대상의 등록 Key 연결은 후속 확장한다.
- 파괴 전 추가 정보가 필요하면 게임플레이 파괴 통지에서 확보하는 어댑터를 제공한다.

## 5. 조건과 상태 관리

발동 계기는 레벨 배치에, 이야기 분기는 연출 내부에 둔다. 석상은 ‘상호작용 → DA_StatueInteraction, 매번’ 하나만 등록한다. 내부 HasInteracted 조건으로 최초/반복 그래프를 선택하고 지정된 정상 완료 경로에서 값을 변경한다.

반복 정책의 1회는 이벤트 소비 여부이며 HasInteracted와 용도가 다르다. 신호 수신이나 대기 등록만으로 소비하지 않고 정상 완료 후 소비한다. 취소·실패·조건 불일치는 미완료다.

변수의 기본 저장 단위는 연출 인스턴스다. 같은 애셋을 사용하는 다른 석상의 상태는 독립적이다. 여러 발동 지점이 상태를 공유해야 할 때만 고급 설정의 ‘상태 공유 그룹’을 사용한다. 애셋 원본 초기값은 수정하지 않는다.

실행 순서:

신호 수신 → 사용 여부·반복 이력 검사 → 중복 통합 → 즉시 실행/대기 → 대상 재검사 → 최신 변수로 내부 그래프 선택 → 재생 → 정상 완료 시 변수·이력 반영.

기본적으로 재시도는 새 신호가 있어야 한다. 전투 종료·파괴의 자동 대기는 다른 연출이 실행 중인 경우에 적용한다. 조건 불일치나 참조 오류는 이유를 기록하고 종료하며 변수 변경 때 자동 재발동하지 않는다. 이러한 상태 감시는 별도 기능으로 분리한다.

변수 변경을 폐기해도 이미 실행된 보상·퀘스트 액션까지 취소되는 것은 아니다. 외부 게임 액션은 고유 실행 ID로 중복 지급을 방지하고 해당 게임 시스템에서 확정 결과를 관리해야 한다.

## 6. 충돌과 레벨 수명

최초 범위는 싱글플레이와 제어권을 사용하는 연출 한 개다. 기존 LevelSequence 실행도 점유 상태에 포함한다. 강제 중단 우선순위는 최초 버전에 넣지 않는다.

| 방식 | 다른 연출 실행 중 기본 처리 | 시작 직전 검사 |
|---|---|---|
| 영역 진입 | 대기 | 아직 영역 안인지 |
| 상호작용 | 거절 후 재입력 | 대상·상호작용 유효성 |
| 전투 종료 | 신호 보관 후 대기 | 결과·중복·필수 대상 |
| 레벨 준비 | 설정 순서로 대기 | 현재 레벨 방문·준비 상태 |
| Actor 파괴 | 위치 복사 후 대기 | 파괴 대상의 생존은 요구하지 않음 |

대기열은 기본 수신 순서로 처리하며 같은 발동 건을 통합한다. 상한 초과는 오류로 기록하고 조용히 버리지 않는다. 자동 무한 재시도는 하지 않는다.

레벨 이동 시 이전 레벨 대기는 취소하고 활성 연출은 중단 경로로 제어권·HUD·카메라를 복원한다. SaveGame에는 완료 이력과 변수만 저장하며 Actor 포인터나 실행 중 대기열을 저장하지 않는다.

단발 신호 보관은 현재 레벨 방문 동안 보장한다. 종료·재접속 후에도 이어야 하는 진행은 전투 결과나 파괴 사실을 별도 게임 상태로 저장하고 재진입 때 평가하는 후속 기능이 필요하다.

## 7. 구현 구조 제안

아래 명칭은 가칭이다.

| 구성 | 책임 |
|---|---|
| 이벤트 배치 편집기 | 목록, 방식별 설정, 검사, 실행 기록 |
| SceneEventBinding | 레벨에 저장되는 배치 Actor 단위 발동 설정·영구 ID |
| 방식별 어댑터 | 다섯 종류의 신호를 공통 요청으로 변환 |
| SceneEventSubsystem | 월드 단위 등록·해제, 대기열, 실행 상태·인스턴스 변수 관리 |
| 기존 SceneDirectorPlayer | 선택된 그래프 재생 |
| 저장 연결부 | 기존 SaveGame과 영구 ID 기반 이력·변수 연동 |

재사용하는 연출 DataAsset과 레벨 Actor 참조를 가진 배치 데이터를 분리한다. 이벤트 배치 화면과 Actor Details는 같은 데이터를 편집한다. 복제, Undo/Redo, 저장·재열기, 스트리밍 등록·해제를 지원한다. 매 프레임 전체 Actor 검색은 사용하지 않는다.

## 8. 기획자 검증 도구

- 전체 검사: 대상·연출 누락, ID·태그 중복, 조건 변수 오류, 무조건 그래프가 뒤의 조건을 가리는 문제.
- 실행 기록: 발동 시각·대상, 선택 그래프, 대기·거절·취소 이유. 오류 클릭 시 관련 설정으로 이동.
- 연출 미리보기: 기존 시각 미리보기, 보상·저장 액션 실행 안 함.
- 발동 시험: PIE에서 신호 모의 발생, 실제 조건·대기 정책 적용. 게임 액션이 실행될 수 있음을 표시.
- 테스트 초기화: 현재 PIE 상태만 초기화하며 실제 저장 데이터와 구분.

## 9. 제작 순서와 완료 기준

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 상호작용의 상태·요청·종료를 공통 실행기로 분리 | 기존 석상 최초/반복·취소·제어권 복귀 유지 |
| 2 | 이벤트 배치 목록·설정·검사·레벨 저장 | Blueprint 수정 없이 영역·상호작용 설정 |
| 3 | 영역·상호작용·레벨 준비와 대기 처리 | 실제 플레이에서 발동, 중복·준비 전 실행 없음 |
| 4 | 전투 완료 계약·파괴 알림 연결 | 다른 연출 중 발생한 신호가 종료 후 1회 재생 |
| 5 | SaveGame·상태 공유·ID 이관 | 재접속 후 이력·변수 복원, Actor별 독립 상태 유지 |
| 6 | 다섯 방식 예제·실행 기록·실제 맵 검수 | 기획자 혼자 배치·시험·원인 확인 가능 |

일정은 1단계에서 기존 Blueprint 상호작용, 전투 완료, 게임 준비 및 SaveGame 연결 지점을 확인한 후 산정한다. 전투 그룹 관리자와 저장 연동은 UI와 별도 개발 항목이다.

필수 검수:

1. 다중 충돌 진입과 상호작용 연타에도 한 번만 재생한다.
2. 영역 재진입은 반복되고 대기 중 영역 이탈은 취소된다.
3. 마지막 적 사망·파괴 중복 통지를 통합하며 다음 웨이브가 남으면 실행하지 않는다.
4. 저장 복원과 플레이어 준비가 늦어도 시작 연출을 조기 재생하지 않는다.
5. 파괴 후 대기 연출이 저장한 위치에서 시작하고 언로드에는 발동하지 않는다.
6. 레벨 이동·대상 삭제·취소·실패 후 제어권과 실행 상태가 정상 정리된다.
7. 취소·실패는 1회 이력을 소비하지 않고 보상 재시도는 중복 지급되지 않는다.
8. 저장·재접속·Actor 복제·이름 변경·Undo/Redo 후 ID와 연결이 유효하다.
9. 자동화 검사 외에 실제 PIE와 최종 Cook/패키지에서 발동·중단·저장을 확인한다.

## 10. 첫 적용

AbandonedSchool의 기존 석상을 공통 실행 경로로 이관한 다음 입구 Volume과 레벨 시작 이벤트를 하나씩 제작한다. 전투 종료와 파괴는 별도 시험 대상으로 검증한 후 실제 플레이 구간에 적용한다.

기존 연출 그래프, 원본 LevelSequence, 원본 석상 BP는 보존한다. 기존·신규 발동 경로를 동시에 활성화하지 않고 이벤트별로 전환·검증한다.

이번 산출물은 기획서이며 런타임 코드와 레벨 애셋은 변경하지 않았다.
