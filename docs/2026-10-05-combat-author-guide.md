# 전투 제작실 — 기획자 사용 안내

## 바로 시작
프로젝트 루트에서 **Combat-Author.cmd**를 더블클릭한다. 로컬 브라우저 제작실이 열린다. Unreal 에디터 화면이나 터미널 명령을 직접 열 필요가 없다. 설치된 UE5.8과 Python3를 사용한다.

**Play-Combat.cmd**는 기본 CombatTool_v3 시험장을1600×900으로 바로 실행한다. 창 크기는 조절할 수 있으며1280×720에서는 항목을 스크롤해 확인한다. 이 실행기는 설치된 엔진의 게임 모드를 사용한다. 별도 배포 패키지와는 다르다.

## 새 전투 만들기
1. 저장된 버전 **CombatTool_v3**를 선택하고 **복제하여 시작**을 누른다.
2. 새 이름을 입력한다. 영문자로 시작하고 영문·숫자·밑줄48자 이내. 기존 버전을 덮어쓰지 않는다.
3. **플레이어·슬롯**에서 기본 공격/Q 스킬/E 궁극기와 HP/SP·회피·이동을 정한다. 기본 이동500cm/s와 프로젝트 카메라 설정을 기준으로 삼는다.
4. **플레이어 액션**에서 피해, 비용, 쿨다운, 몽타주, 타격 구간, 다음 콤보, 선입력·회피 전환 구간, 돌진과 범위 판정을 편집한다.
5. **몬스터·능력치**, **AI 공격 패턴**, **추적·복귀**에서 공통 몬스터 설정을 편집한다. 패턴은 거리·시야·각도·가중치·연속 제한으로 선택된다.
6. **적 배치·교전**에서 적을 추가하고 위치와 동시 공격 수를 정한다. **개별 설정 항목 확장**은 공통값을 복사하면서 기존 개별 값을 보존한다. Scout/Guard/Flanker가 같은 모델을 쓰면서 다른 수치를 갖는 샘플이다.
7. **변경 내역**으로 확인하고 **① 입력 검사 → ② 새 버전 저장 → ③ 엔진 검증 → ④ 맵 제작 → ⑤ 플레이**를 누른다.

입력 검사는 JSON 구조·범위·연결을 확인한다. 엔진 검증은 실제 자산 존재, 몽타주 스켈레톤/길이, 타격 창과 비용 등을 검사한다. 제작은 원본을 복제한 새 폴더에 수행한다. 생성 도중 실패한 폴더는 자동으로 삭제하지 않으며 새 이름으로 재시도한다. 완료 기록이 없는 버전은 플레이에서 차단한다.

## 액션 규칙
- 기본 콤보는 next_action으로 이어진 유한한 연결이다. 순환 연결은 거절된다. 선입력은 설정 구간에서만 받으며 자원이 부족하면 다음 타가 나가지 않는다.
- 몬스터는 AI 패턴으로 액션을 선택한다. 플레이어용 next_action 연결은 몬스터에 허용하지 않는다.
- Q/E도 같은 액션 실행·비용·쿨다운·취소 규칙을 사용한다. 슬롯이 비어 있으면 사용 불가로 표시한다.
- 궁극기 게이지는0~100이다. 일반 적중으로 획득하고 액션의 비용만큼 소비한다. 실패한 시작은 소비하지 않는다.
- 돌진은 지상에서 실행하고 벽과 충돌한다. 중단·피격·사망 때 이동이 정리된다.
- 주변 범위 판정은 벽 뒤 적을 제외하고, 다른 몬스터가 가린 적은 포함한다. 전방 판정은 기존 전방 sweep을 사용한다.
- 타격/입력/회피 창은 몽타주 시간(초), 거리/반경/배치는cm, 배속은 원본 대비 비율이다.
- 타격 창을 직접 지정하면 복제 몽타주에만 적용된다. 지정하지 않으면 원본의 타격 창을 사용한다.

## 플레이하면서 조정하고 저장하기
WASD 이동 · 마우스 시점 · 좌클릭 콤보 · Space 회피 · Q 스킬 · E 궁극기 · Tab 락온 · 우클릭 공격 취소 · R 재시작 · F1 조정 패널.

F1은 전투를 멈춘다. 플레이어/슬라임/공격·패턴/상세 상태/변경 내역으로 분리되어 있으며 여러 적은 **다음 대상**으로 바꾼다. **적용 후 전투 재시작**은 모든 대상의 자원·위치·쿨다운을 초기화한다. HUD에는 게이지·스킬 사용 가능 여부와 남은 적/동시 공격 수/승패가 표시된다.

1. F1에서 값을 바꾸고 **AI 전달 파일**로 고유 이름을 저장한다.
2. 제작실에서 그 플레이의 원본 버전(예:CombatTool_v3)을 열고 새 버전 이름을 정한다.
3. **AI 파일·JSON → 플레이 조정 보고서 → 플레이 조정값 불러오기**를 누른다.
4. **변경 내역**에서 어느 적의 어떤 값이 바뀌었는지 검토한다.
5. 새 버전 저장→엔진 검증→맵 제작→플레이한다.

프리셋은 세션용 튜닝 파일이고, 제작실의 새 버전 생성은 다시 실행해도 유지되는 자산 저장이다. 보고서의 원본 대상/액션/맵 서명이 일치해야 가져올 수 있다. 다른 버전의 보고서를 억지로 적용하지 않는다. reports의 preset.values가 실제 입력이며 설명용 fields는 자동 적용하지 않는다.

검증 예제 **CombatTool_Tuned_v1**: v3의 플레이 보고서에서 플레이어 HP100→117, Guard Heavy28→31만 변경했다. Scout Heavy22와HP150, GuardHP220을 유지한 상태로 새 자산을 생성하고 별도 엔진에서 재로드 확인했다.

## AI에게 전달할 요청 예시
“첨부한 schema_version=2 전투 레시피를 기반으로 새 id SlimeTrial_v1을 만들어 줘. 기존 메시/몽타주 경로를 유지하고 Guard의 HP와 Heavy 피해만 조정해 줘. 원본 슬롯/콤보/타격 창은 보존하고 바꾼 값과 이유를 별도로 설명해 줘. 전체 JSON만 제작실에 넣을 수 있게 반환해 줘.”

제작된 버전을 열면 실제 상속값까지 해석한 snapshot을 편집한다. AI 입력은 **AI 파일·JSON**에 붙여넣거나 JSON 파일로 불러온다. 알려지지 않은 키, 누락값, NaN, 잘못된 자산 경로, 연결 순환은 검증 대상으로 처리한다. 임의 명령이나 Python코드를 실행하는 입력 경로가 아니다.

## 진단과 보관 위치
- 레시피: CombatRecipes/<id>.json
- 제작된 전체 설정: <id>.resolved.json, 완료/대상 서명: <id>.manifest.json
- 생성 자산: Content/Constellation/Review/CombatRecipes/<id>/
- 플레이 프리셋: Saved/CombatTuning/, 보고서: Saved/CombatTuningReports/
- 제작 작업별 결과와 엔진 로그: Saved/CombatAudit/RecipeJobs/<고유번호>/
- 제작실 작업 로그: Saved/CombatAuthor/

**진단 로그 → 초안·변경·로그 내려받기**로 AI에 재현 파일을 전달할 수 있다. 입력 오류의 **해당 항목으로 이동** 버튼은 관련 편집 화면으로 이동한다. 되돌리기/다시 실행은 현재 브라우저 초안을 대상으로 하며 저장된 자산을 되돌리지는 않는다. 브라우저를 닫기 전에 새 버전을 저장한다.

## 기존 프로젝트 연결 및 현재 범위
CarryComponent가 들기/운반 중일 때 공격·Q/E·회피를 막고, 피격 시 기존 내려놓기 처리를 수행한다. 장면 연출의 이동 입력 잠금과 기존 밀기/오르기/변신 상태도 확인한다.

교전 설정의 battle_key와 notify_scene를 설정하면 승리/패배를 기존 SceneEventSubsystem으로 한 번 전달한다. 해당 키를 사용하는 SceneEventBinding을 장면 도구에서 연결한다. 새 교전 실행은 별도 GUID를 사용한다.

완성 범위는 단일 플레이 전투 제작·튜닝 도구와 슬라임 계열 샘플이다. 본편 모든 전투 존의 자동 교체, 새 스켈레톤용 이동 템플릿, 가드·패링·공중전, 멀티플레이와 최종 전투 연출은 포함하지 않는다. 원본 본편 맵은 자동으로 교체하지 않았다. 모션은 기존 자산을 재사용했으며 전용 모션 요구는 [애니메이션 전달 목록](2026-10-04-combat-animation-backlog.md)에 있다. 최종 손맛·모션/카메라 연출은 사용자의 플레이 검수가 필요하다.
