# 인게임 전투 워크벤치 사용법

## 제작실과 함께 사용하기
프로젝트 루트의 **Combat-Author.cmd**를 더블클릭하면 브라우저 전투 제작실이 열린다. 플레이 슬롯·액션·타격 구간·AI 패턴·개별 적·배치를 편집하고 새 맵으로 저장한다. 전체 흐름은 [전투 제작실 안내](2026-10-05-combat-author-guide.md)를 따른다.

## 실행
프로젝트 폴더의 **Play-Combat.cmd**를 더블클릭한다. 기본 CombatTool_v3 3마리 시험장을 1600×900으로 실행한다.
설치된 UE5.8의 게임 모드로 실행하므로 에디터 화면을 열 필요가 없다. 배포용 독립 패키지는 아니다.

## 플레이와 조정
- WASD 이동, 마우스 시점, 좌클릭 콤보 공격, Q 돌진 스킬, E 범위 궁극기, Space 회피, Tab 락온, 우클릭 공격 취소.
- R: 현재 세션에 적용한 설정을 유지하며 전투 재시작.
- F1: 전투를 일시정지하고 조정 패널 열기.
- 플레이어: 최대 HP/SP, SP 회복, 경직, 이동, 회피, 콤보 단계별 공격 수치.
- 슬라임: 최대 HP/SP, SP 회복, 경직, 이동·감지·추적·복귀.
- 공격·패턴: 선택한 슬라임의 공격 수치와 선택 거리·각도·가중치·연속 제한.
- 상세 상태: AI 판단과 공격 처리 이유. 여러 슬라임이 있으면 '다음 대상'으로 편집할 대상을 바꾼다.
- 숫자는 Enter 또는 다른 항목 클릭으로 입력을 확정한다. 스크롤하여 아래 항목을 볼 수 있다.
- **적용 후 전투 재시작**: 전체 수치를 검사하고 양측 자원·위치·쿨다운을 초기화하여 새 전투에 적용한다.
- F1 / Escape / **변경 취소 후 계속**: 초안 변경을 버리고 이전 전투를 계속한다.
- 항목별 원복: 해당 항목을 자산의 초기값으로 되돌린다.
- 초기 설정 복원: 모든 대상의 초안을 자산 초기값으로 되돌린다. 적용 버튼을 눌러야 전투에 반영된다.
- 사망한 상태에서도 F1과 R로 다시 시험할 수 있다.

## 프리셋
1. 이름 칸에 영문·숫자·밑줄·하이픈으로 새 이름을 입력한다.
2. **프리셋 저장**으로 현재 초안을 Saved/CombatTuning/<이름>.json에 보관한다.
3. **목록 순환**으로 저장된 이름을 고르거나 이름을 직접 입력하고 **불러오기**를 누른다.
4. 불러온 초안을 **적용 후 전투 재시작**으로 반영한다.

동일 이름의 파일을 덮어쓰지 않는다. 저장은 전투 적용과 별개다. 게임 종료 후에는 저장한 프리셋을 다시 불러와야 한다.
프리셋에는 플레이어와 모든 슬라임의 편집값을 함께 기록한다. 시험장·대상 이름·원본 메시·공격/패턴 자산 구성이 다른 프리셋은 거부한다.
이 파일은 AI에 전달할 수 있는 튜닝 결과물이다. 기존 CombatRecipes 형식이나 uasset을 직접 수정하지 않는다.

## 화면
기본 1600×900, 1920×1080 대응. 1280×720에서도 본문 크기를 유지하고 스크롤로 항목에 접근한다.
플레이어/몬스터 상태, 선입력/결과, 조작 안내를 카드로 나누었다. 편집 중에는 HUD를 숨겨 글자가 겹치지 않는다.

## 구현과 검사
런타임 Action/Pattern/Encounter는 대상별 복사본을 사용한다. 콤보 연결·패턴 참조는 같은 대상의 복사본으로 연결한다.
최대 HP/SP는 기본 100을 유지하며, 초기화 이후 회복·클램프·복귀 회복·표시에 실제 최대값을 사용한다.
설정 적용 전 검사는 초안 전체를 검증하며 오류가 있으면 기존 전투를 유지한다.

검사 도구:
- tools/test-combat.ps1: 전체 Editor 빌드 및 전투 자동 검사. ResourceLimits와 WorkbenchCloneIsolation/DraftValidation/PresetAndRestart 포함.
- tools/test-combat-workbench.ps1 -Width 1600 -Height 900: 실제 게임에서 HP175/SP80·슬라임HP200 설정 후 재시작을 검증하고 패널/HUD 캡처.
- 같은 도구에 -Width 1280 -Height 720 또는 -Width 1920 -Height 1080 사용 가능.
- 캡처/로그: Saved/CombatAudit/Workbench/<해상도>/.
- 위 검사용 수치는 검사 프로세스 안에서만 사용하고 기본 자산이나 사용자 프리셋에 저장하지 않는다.

렌더 자동 검사는 창 배치와 실제 재시작 설정 반영을 확인한다. 사용자의 마우스·키보드 조작감 평가를 대체하지 않는다.

## F1 와이어프레임 충돌 수정 — 2026-10-05

- 수정 전 재현: open=1, view=1(Wireframe), before=3(Lit), F1 열기/닫기 검사 실패. 로그: Saved/CombatAudit/Workbench/f1-before-fix.log.
- 수정 후: F1OpenReview PASS(open=1, view=3, before=3), F1CloseReview PASS, RestartReview PASS. 최종 빌드 및 기존34개 검사 통과.

## 변경 내역 비교 — 2026-10-05

F1 → 수치 수정 또는 프리셋 불러오기 → **변경 내역**에서 적용 전에 비교한다.

- 플레이어와 모든 슬라임의 변경을 대상·항목별로 표시한다. 현재 선택한 몬스터만으로 제한하지 않는다.
- 비교 기준은 현재 전투에 적용된 값이다. 예: HP175를 적용한 뒤200을 초안에 입력하면 175 → 200.
- **이 변경 취소**는 해당 항목만 현재 적용값으로 돌린다. 위 예에서는175가 되며, 초기값100으로 되돌리는 **원복 / 초기 설정 복원**과 다르다.
- 프리셋 불러오기와 초기 설정 복원 후에도 변경 목록을 갱신한다. 실제 반영은 기존 **적용 후 전투 재시작** 버튼으로 수행한다.
- 변경 목록 확인과 개별 취소는 런타임 전투 설정이나 원본 자산을 바꾸지 않는다.
- 변경이 없으면 안내 문구를 표시한다. 여러 항목은 본문 스크롤로 확인한다.

검사 도구에 ChangesReview와 UndoChangeReview를 추가했다. 현재HP175·원본100인 게임에서 초안200을 비교하고, 취소 후175로 복원되며 런타임 값이 유지되는지 검사한다.
화면 캡처는 Saved/CombatAudit/Workbench/<해상도>/changes.png다.

검증 결과: 전투 자동 검사36개 통과. 최종 전체 Editor 빌드 성공. 1280×720 및1600×900에서 변경 비교·개별 취소, F1, 사망 후 재시작, 별도 프로세스 프리셋 저장/불러오기 검사를 통과했고 changes.png를 직접 확인했다. 이는 자동 입력·런타임 검사이며 사람의 조작감 평가를 대체하지 않는다. 빌드 중 발견한 CombatObservation.cpp의 대응 헤더 우선 include도 수정했다.

## AI 전달용 튜닝 보고서 — 2026-10-05

1. F1에서 수치를 조정하거나 프리셋을 불러온다.
2. **변경 내역**에서 비교하고 하단 이름 칸에 영문·숫자·밑줄·하이픈으로 이름을 입력한다.
3. **AI 전달 파일**을 누르면 Saved/CombatTuningReports/<이름>.json을 저장한다.
4. 그 파일과 원하는 전투 방향을 AI에 전달한다. 파일 저장은 현재 전투에 설정을 적용하지 않는다.

파일 내용:
- 전체 플레이어·몬스터의 대상 키, 항목명, 분류, 단위가 포함된 라벨, 허용 범위와 자료형.
- initial: 이번 세션이 읽은 자산 초기값. 최초 제작 당시의 역사적 값이라는 뜻은 아니다.
- current: 현재 전투에 적용된 값.
- proposed: 내보내는 초안 값. 미적용 변경도 포함한다.
- 현재값/초기값에서 달라진 항목 수와 항목별 표시.
- preset: 원본 자산 구성과 제안 값을 포함하는 기존 ConstellationCombatTuning 형식의 객체.

보고서는 CombatRecipes 입력이 아니다. 아래 직접 불러오기 기능에서 AI 파일로 선택할 수 있으며, preset 객체를 별도 JSON으로 저장해 기존 프리셋으로 사용하는 방법도 유지한다. 자료형 boolean_0_1 항목의 프리셋 값은 JSON true/false 대신 숫자0/1을 사용한다.
타격 노티파이·애니메이션·지형·카메라·피해 기록은 보고서 범위 밖이다. 수치 검사를 통과했다는 사실이 전투 밸런스나 조작감 승인을 의미하지 않는다.

AI 요청 예시:
> 이 튜닝 보고서를 읽고 슬라임의 공격 준비가 더 잘 보이도록 수치 변경안을 제안해 줘. preset의 sources와 값 키는 보존하고, 허용 범위 안에서 수정해 새 이름의 Saved/CombatTuning 프리셋 JSON으로 저장해 줘. 기존 파일을 덮어쓰지 마. 변경 이유와 게임에서 확인할 항목도 알려 줘.

그 후 게임에서 새 프리셋을 불러오고 **변경 내역 → 적용 후 전투 재시작**으로 확인한다. 새 액션·패턴 추가나 애니메이션 제작은 별도 작업이다.

저장은 기존 전체 초안 검증을 통과해야 하며, 잘못된 이름·수치 또는 같은 이름의 기존 보고서는 거부한다. 보고서 디렉터리는 프리셋 목록과 분리되어 있다.

보고서 검증: 전체 Editor 빌드 성공, 전투 자동 검사37개 통과. 보고서 미구현 실패를 먼저 확인한 뒤 저장 내용·현재/초기값 구분·잘못된 입력·덮어쓰기 방지·전투 값 보존을 검증했다. 1280×720 및1600×900의 실제 게임 내보내기 검사를 통과했고, 두 해상도의 버튼 배치와 저장된 보고서/포함 프리셋의 항목·원본 구성·변경 건수 일치를 확인했다. 증거: Saved/CombatAudit/Workbench/<해상도>/tuning-report-Save.json 및 tuning-report-Load.json.

## AI 파일 직접 불러오기 — 2026-10-05

AI가 보고서 안의 **preset.values**를 수정해 Saved/CombatTuningReports에 새 이름의 JSON으로 저장하면, 객체를 따로 추출할 필요 없이 불러올 수 있다.

1. F1 → 이름 칸 옆 **입력: 프리셋** 버튼을 눌러 **입력: AI 파일**로 전환한다.
2. **목록 순환**으로 파일을 선택하거나 확장자를 제외한 이름을 직접 입력한다.
3. **불러오기**를 누르면 검증 후 자동으로 **변경 내역** 탭을 연다.
4. 값을 검토하고 **적용 후 전투 재시작**으로 반영한다. 취소하려면 F1로 닫는다.

입력 종류에 따라 목록과 불러오기 폴더가 달라진다. 프리셋 저장 버튼은 계속 Saved/CombatTuning에, AI 전달 파일 버튼은 Saved/CombatTuningReports에 저장한다.

읽는 값의 기준은 preset.values 하나다. fields의 initial/current/proposed 및 변경 건수는 내보낸 당시의 참고 기록이며 불러오기에는 사용하지 않는다. AI는 보고서 형식·버전·preset.sources·항목 키를 보존하고 preset.values만 수정한다. 게임의 변경 내역은 파일의 오래된 설명 대신 실제 현재값과 불러온 값을 비교한다.

AI 요청 예시:
> 보고서의 preset.values만 수정해 슬라임의 공격 피해를 낮춰 줘. sources, 항목 키, 파일 형식과 버전은 보존하고 Saved/CombatTuningReports에 새 이름으로 저장해 줘. fields는 내보낸 당시의 참고 기록으로 그대로 두어도 돼. 기존 파일을 덮어쓰지 말고 변경 이유를 설명해 줘.

## 콤보 선입력 시간 편집 — 2026-10-05

F1 → 플레이어 → 다음 공격이 연결된 공격 항목에서 **선입력 시작 (몽타주 s)**, **선입력 종료 (몽타주 s)**를 조정한다. 다음 공격 이름과 현재 몽타주의 전체 길이를 함께 표시한다. 다음 공격이 없는 액션에는 효과 없는 편집 항목을 표시하지 않는다.

선입력은 현재 공격 중 다음 공격을 예약하는 시간 구간이다. 공격을 즉시 끊는 캔슬 시각이나 타격 판정 시간과 다르다. 시간은 몽타주 기준이며 재생 배속/0.25배 관찰 상태의 실제 경과 시간과 다를 수 있다.

0 ≤ 시작 < 종료 ≤ 몽타주 길이여야 한다. 변경 내역에서 비교한 뒤 적용 후 재시작하며, 원본 액션·몽타주·애니메이션은 수정하지 않는다. 공격 연결 대상 자체를 바꾸는 기능은 이번 범위 밖이다.

신규 프리셋 내부 형식은 schema_version=2다. AI 보고서 바깥 형식은1을 유지하며 포함된 preset만2를 사용한다. 기존 schema_version=1 프리셋/보고서도 읽는다. 예전 파일에 선입력 항목이 없으면 해당 자산 초기값으로 채우고 화면에 안내한다. 다른 기존 항목 누락·알 수 없는 항목·잘못된 수치·원본 불일치는 계속 거부한다. schema_version=2에서는 모든 항목을 명시해야 한다.

선입력 편집 검증: 미구현 시 항목 누락 실패를 확인한 뒤 구현. 전체 Editor 빌드 및 전투 자동 검사38개 통과. WorkbenchInputWindow에서 연결된 액션만 노출, 구간 순서/길이 오류 거부, 값 저장·재로드, v1 신규 항목 기본값 보완, v2 누락 거부를 확인했다. 1280×720 및1600×900의 Save/Load 두 프로세스 모두 InputWindowReview: PASS. 시험에서 플레이어 선입력 시작을0.25초로 설정해 재시작 후 반영과 AI 보고서 포함을 확인했다. 검사용 프리셋은 도구가 정리하며 기본 자산 수치는 변경하지 않았다.

## 공격 중 회피 전환 편집 — 2026-10-05

각 공격에 회피 전환 허용 체크와 시작·종료 시간을 추가했다. 켜진 경우에만 시작 < 종료 ≤ 몽타주 길이를 검사하며, 기본은 꺼짐이다. 현재 HUD에서 전환 구간 열림/닫힘과 회피 입력 결과를 확인한다. 규칙 상세는 docs/2026-10-04-combat-dodge.md의 최신 절을 참조한다.

새 프리셋은 schema_version=3을 사용한다. 기존1·2도 계속 읽으며, 누락된 회피 전환 항목만 해당 자산 초기값으로 보완해 안내한다. 기존 프리셋을 읽었다고 회피 전환을 자동으로 켜지 않는다. AI 보고서의 바깥 schema_version은1이며 내부 preset 형식만3이다. 현재 버전3 파일은 모든 편집 항목을 명시해야 한다.

회피 전환 검증 완료: 전체 빌드 및 전투 검사40개 통과, 두 해상도의 별도 Save/Load 게임 프로세스에서 설정 유지와 실제 Space 전환 성공. 상세 근거와 검사 범위는 회피 문서의 최신 절에 기록했다.
