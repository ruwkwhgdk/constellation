# 한국 지하철역 입구 1차 제작 계획

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task after user review. 현재 요청은 제작 계획이며 모델/레벨/게임 로직을 변경하지 않는다. 서브에이전트 실행을 전제로 하지 않는다.

**Goal:** 사진의 지하철역 입구만 애니메이션풍 게임 애셋으로 제작하여 시작 섬에 배치할 준비를 한다.

**Architecture:** 입구를 재사용 가능한 모듈 묶음으로 제작한다. 외부는 시작 섬, 내부는 기존 계단 레벨에 각각 존재하며 향후 레벨 이동으로 연결한다. 물리적인 계단 접합·내부 레벨 이동/확대는 하지 않는다.

**Tech Stack:** Tripo 외형 후보/유기적 표면, Blender 정밀 형상·피벗·UV·충돌·보정, Unreal 재질/배치/검사. 내장 image_gen은 원화 및 입구 전용 부품 시트에 사용한다.

**Spec:** `ArtSource/SubwayEntrance/CURRENT.md`와 2026-09-30 사용자의 범위 수정. 미술 기준은 사진과 `Concepts/v001/subway_entrance_anime.png`이며 원화 전체 배경은 제외한다.

## 범위와 제약

- 제작 대상: 차양 지붕, 기둥, 유리/석재 난간 벽, 바깥 진입 계단과 참, 점자블록, 입구에서 보이는 짧은 하강 계단/벽/천장, 금속 난간, 역명·출구 표지 및 안내판.
- 제외: 도로, 고가도로, 건물, 차량, 가로수, 가로등, 전신주, 도시 전체, 사람, 내부 역 전체, 이번 단계의 레벨 이동 코드.
- 사용자가 말한 `LV_StartIsland`의 현재 파일은 `Content/Levels/L_StartIsland.umap`이다. 패키지 `/Game/Levels/L_StartIsland`를 실행 전 재확인한다. 새 유사 이름 레벨을 임의로 만들지 않는다.
- 내부 유지 맵은 `/Game/Environment/StairwellModular/Scene/Maps/L_Stairwell_PlayScale2`다. 내부480cm 폭을 외부의 강제 접합 치수로 삼지 않는다.
- 사진의 원근과 숨은 면으로 실제 치수를 단정하지 않는다. 캐릭터 스케일로 입구 폭·머리 위 여유를 먼저 검토하고 소품 치수를 분리한다.
- Blender CLI는 반드시 `tools/run-blender.ps1` 사용. 최신 소스와 최종 산출물은 `ArtSource/SubwayEntrance/CURRENT.md`에 연결한다.
- 기존 `develop`만 사용한다. 단계별 사용자 검토가 필요한 외형 결정과 실제 플레이 확인을 건너뛰지 않는다.

## 우선 검토할 다섯 문제

1. **지면이 하강 입구를 막는 경우:** 시작 섬 바닥/지형의 종류와 충돌을 확인하고 입구 점유 영역에만 개구부 처리를 설계한다. 검은 판이나 바닥 위 가짜 계단으로 막힌 입구를 숨기지 않는다.
2. **사진보다 캐릭터 기준 공간이 좁은 경우:** 블록아웃 단계에서 폭·카메라·난간·머리 위 여유를 확인한다. 사용자가 플레이 확인 전 통과로 기록하지 않는다.
3. **반대편에서 보이는 빈 면:** 정면3/4뿐 아니라 뒤/측면/지붕 아래를 확인해 실제3D 구조를 완성한다.
4. **유리/금속이 과도하게 사실적이거나 번쩍이는 경우:** 작은 노멀과 날카로운 반사를 줄이고 큰 색면/제한된 오염으로 원화와 대조한다.
5. **전환 구간이 노출되거나 복귀 즉시 재진입하는 경우:** 후속 전환을 위한 진입 구역과 복귀 스폰을 분리한다. 1차에서는 공간과 방향을 검토하고 실제 왕복 로직 통과로 간주하지 않는다.

### 2. 입구 블록아웃과 배치 공간

**산출물:** `Blockout/v001/entrance_blockout.blend`, `Blockout/v001/dimensions.json`, `Blockout/v001/review.html`.

- [ ] 시작 섬을 읽어 배치 가능한 위치, 지면 높이, 지형/바닥 충돌, 주변 기존 오브젝트를 확인한다. 사진 배경은 새로 만들지 않는다.
- [ ] 지붕·기둥·유효 통로·진입 단·짧은 하강부를 단순 형상으로 조립한다. 입구 유효 폭은 초기 검토 후보3.6–4.8m로 비교하며 확정 치수로 취급하지 않는다.
- [ ] 바깥 단은 초기 단 높이15–18cm/디딤판28–32cm 후보에서 캐릭터와 비교한다. 사진의3D 실측값이라고 주장하지 않는다.
- [ ] 지면 개구부, 계단 바닥, 난간과 캡슐/카메라 여유를 단면과 측면으로 확인한다.
- [ ] 외부 하강 구역, 외부 복귀 위치, 바라보는 방향을 표시한다. 기존 내부 레벨과 기하를 붙이지 않는다.
- [ ] 사용자에게 배치/스케일 검토본을 제공한다. 플레이는 사용자가 확인한다.

## 1차 완료 기준

- 시작 섬에 입구 단독 구조물이 배치되고 지붕·금속 기둥·유리 난간·석재 참·점자블록·하강 계단으로 사진의 입구가 식별된다.
- 주변 사진 배경은 제작되지 않으며 기존 내부 레벨도 유지된다.
- 부유물·막힌 하강부·바닥 관통·뚫린 뒷면·틀어진 난간이 검토 시점에서 없다.
- 실제 스케일과 미술 표현을 따로 검토하고 사용자 외형 승인 및 사용자 플레이 결과를 구분해 기록한다.
- 최신 소스/반입 파일/검증 기록과 후속 레벨 이동 위치 명세가 연결되어 있다. 이 기준의 완료가 레벨 왕복 이동 구현 완료를 뜻하지 않는다.

## 2026-09-30 승인 후 범위 갱신

사용자는 원화/모듈 전체 채택 및 시작 섬 좌표 (3900,-19500,10530)를 지정했다. 해당 subway_station의 입구 방향을 유지하며 해당 액터만 교체한다. 하늘섬 아래 추락을 방지하고 일정 깊이에서 내부 레벨로 자연스럽게 이동하도록 최신 요청이 추가되었으므로, 위의 '이동 코드 제외/후속'은 초기 범위 기록이다. 블록아웃 검토 이후 전환 구현/스폰/페이드/실패 시 안전 바닥도 진행 범위에 포함한다. 실제 플레이는 사용자 담당이다.
