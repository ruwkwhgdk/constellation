# 대화 선택지 UI 구현 계획

> 실행 지침: executing-plans에 따라 현재 작업 공간에서 순서대로 구현하고 검증한다.

**목표:** 사용자 제공 이미지 5개로 최대 4개의 선택지 UI를 구현한다.
**구조:** SDirectorChoices가 포커스·마우스·키보드·확정을 담당하고, SDirectorDialogue와 함께 게임 및 미리보기에서 사용한다. 렌더링 위젯은 경로 실행 정책을 소유하지 않고 선택된 항목의 고유 Key를 전달한다.
**기술:** Unreal 5.8 C++, Slate, UI Texture2D.
**설계:** ../specs/2026-10-04-scene-director-branching-design.md

## 제약
최대 4개, B 버튼 제외, 제공된 포커스/비포커스 리소스 구분, 원본 이미지 보존. 화자 글자 크기 16 유지. 입력 대기 중 일반 대사 진행과 이중 실행 금지.

## 작업
- [x] 5개 이미지 이름 정리 및 UI 텍스처 임포트. 런타임에 hard reference로 보관한다.
- [x] SDirectorChoices 구현. 고정된 최대 슬롯 수, 안정적인 항목 ID, 포커스 배경과 커서, 긴 문구 줄바꿈, 클릭/방향키/Enter. 한 번만 선택 콜백을 발생시킨다.
- [x] 대사 노드에 선택지 목록을 노출하고 런타임·미리보기에 동일한 위젯을 연결한다. 선택 결과를 공개 이벤트로 전달한다. Bool 조건 및 서로 다른 출력 경로 실행은 분기 실행기 단계이며 이번 UI 검증과 구분한다.
- [x] 항목 수 0/1/4/5, 빈/중복 Key, 입력 중복, 대기 중 일반 진행 차단을 테스트한다. 포커스 이동, 긴 한글, 4개 항목 전체를 실제 렌더링한다.
- [x] 전체 회귀 테스트, Editor/Shipping 빌드, 코드 검토. 사용자 문서에 현재 UI 동작과 분기 실행기의 남은 범위를 명시한다.

## 검토 중점
텍스처 알파 정렬, 활성 테두리의 외곽 glow 잘림, 선택지 본문 가림, 선택 확정 직후 일반 대사 건너뛰기, 사라진 위젯 콜백 및 중복 입력, 게임 종료 시 정리.

검토 결과: 미리보기 클릭 후 강조가 고정되는 문제를 수정하고 회귀 테스트를 추가했다. 분기 실행기는 완료 범위에 포함하지 않는다. 검증 로그: Saved/Logs/SceneDirector-tests.log, Choice-final-visual.log, Choice-shipping-build.log.
