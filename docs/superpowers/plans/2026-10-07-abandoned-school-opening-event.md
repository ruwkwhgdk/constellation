## 1. 구현 기준

- 대상 맵: `/Game/Constellation/Worlds/AbandonedSchool/Maps/AbandonedSchool`.
- 첫 화면부터 게임 HUD를 감추고, 락커 안 1인칭으로 시작한다. 대사와 선택지 UI는 진행에 필요하므로 게임 HUD와 별개로 표시한다.

## 4. 선택지 구현과 최소 툴 확장

### 권장 분기

첫 메뉴는 A `틈으로 밖을 살펴본다.`, B `락커 안을 둘러본다.`, C `문을 연다. (필요 스탯 : 힘 1)`로 구성한다. C는 항상 표시되지만 비활성이다.

- A를 먼저 선택: A 연출 → 기준 구도 → B+C 메뉴 → B 연출 → 기준 구도 → 바깥 기척.
- B를 먼저 선택: B 연출 → 기준 구도 → A+C 메뉴 → A 연출 → 기준 구도 → 바깥 기척.
- 두 번째 조사 뒤에는 비활성 C만 남은 메뉴를 띄우지 않고 다음 사건으로 진행한다.
- 각 순서에 필요한 A/B 연출 노드 체인은 별도로 배치하되 대사·카메라 값·모션 자산은 공유한다. 분기 상태를 가진 같은 노드로 되돌아가는 연결은 만들지 않는다.
- 런타임 임의 루프를 추가하는 방식은 공통 실행기의 영향 범위가 커서 이번 S0에는 선택하지 않는다. 향후 반복 조사가 많은 이벤트에서 별도 검토한다.

### 비활성 선택지 계약

`FDirectorChoice`에 제안 필드 `bEnabled=true`, `DisabledReason`을 추가한다. 기존 자산은 기본 true로 기존 동작을 유지한다. C의 사유는 `힘 1 필요`로 표시한다.

- UI: 회색/잠금 표현, 클릭 차단, 키보드 이동은 활성 항목만 순회. 활성 항목이 없는 선택 노드는 컴파일 오류로 처리한다.
- 런타임: UI 이외의 직접 선택 API로 C의 Key를 제출해도 거절한다. 빠른 중복 입력도 한 번만 수락한다.
- 에디터: 비활성 항목에는 실행 출력 핀을 요구하지 않는다. 다시 활성화하면 연결할 출력 핀이 필요하다.
- 분기/검증: 활성 항목만 필수 실행 경로로 계산한다. 비활성 항목의 오래된 출력 연결은 컴파일에서 명확히 안내하며 자동으로 임의 분기에 연결하지 않는다.
- 미리보기: 비활성 항목을 경로로 고를 수 없으며 저장·재열기·Undo/Redo에도 상태와 사유를 유지한다.

주요 변경 후보는 `SceneDirectorChoice.h/.cpp`, `SDirectorChoices.cpp`, `SceneDirectorPlayer.cpp`의 선택 처리, `SceneDirectorBranching.cpp`, `SceneDirectorCompiler.cpp`, `SceneDirectorAsset.h`의 후속 노드 열거, `SceneDirectorGraph.cpp`와 필요한 속성 편집 부분이다. Runtime·Editor 모두 `Plugins/ConstellationSceneDirector/Source` 아래 기존 구현을 확장한다.

이 확장은 S0만 하드코딩하는 UI가 아니라 다른 연출에서도 사용할 수 있는 ‘표시되지만 선택할 수 없는 항목’ 기능으로 만든다. 일반적인 스탯 계산·인벤토리·조건식 언어는 추가하지 않는다.

| S0_G05 | 꼬마 소녀 | 인간이다아!! |

화자 마스터는 기존 `/Game/Constellation/Gameplay/Sequences/Data/DT_SpeakerData`를 사용한다. 기존 다른 장면의 `Girl` 표시명을 일괄 변경하지 않고 필요하면 S0용 `LittleGirl`을 추가한다. 나레이션 표시 방식은 문구와 가독성을 유지하는 방향으로 설정한다.

조사 나레이션은 최소 표시 시간 이후 클릭 진행을 제안한다. 소녀 경악·도주 구간은 음성/고정 시간 기반으로 동작과 연결한다. 현재 클릭 대기는 연출 시간을 정지시키므로 조사 중 계속 재생되어야 할 몸짓은 별도로 점검한다.

작은 별 노래는 원문에 있는 세 줄을 부르는 장면용 음원으로 준비한다. 멀리서 시작해 소녀 위치를 따라 접근하도록 하고, G01 직전에 중지한다. 고정 시간 연기와 동기화할 수 있도록 실제 음원 길이에 맞춰 입장 동선을 조정한다. 환경음·발소리·문 여닫는 소리·잡동사니 낙하·넘어짐 충격음을 별도 조절한다. 임시 음원을 사용한 초벌과 최종 음원이 적용된 결과를 구분한다.

## 6. 자산 제작 범위와 화면 구성

| 대상 | 재사용/제작 계획 | 검수 기준 |
|---|---|---|
| 락커 | 기존 본체/문/Blueprint를 검사하고 S0 전용 파생 자산 구성 | 실제 주인공 160cm 기준 내부 여유, 내부 면, 문 경첩, 틈 시야, 문 열림 각도 |
| 내부 꾸밈 | 스티커·포스트잇·별자리 이미지·사진은 평면/데칼, 키링·인형은 필요한 입체 소품 | 1인칭 근접에서 깨짐/겹침 없이 읽히고 원문의 귀여운 장식 분위기 반영 |
| 두 사람 사진 | 주인공과 신원 불명의 소녀가 함께 있는 전용 사진 자산, 눈 위치에 검은 바 | 눈만 가리며 사진의 두 인물과 주인공의 존재는 분명히 보임 |
| 교실 | 현행 시작 공간을 조사해 락커-칠판-입구-개구멍의 시선을 맞춤 | 틈에서 칠판, 낮은 시점에서 도주 구멍이 자연스럽게 보임 |
| 꼬마 소녀 | 기존 BP/메시를 우선 재사용 | 초등학교 4학년 정도의 작은 체격 인상, 주인공과 눈높이 관계 |
| 소녀 모션 | 노래하며 입장, 발견·달리기·정지, 문 열기, 굳음, 경악, 도주, 몸 낮추기·구멍 통과 | 손 접촉, 발 미끄러짐, 문과의 간섭, 구멍 통과 실루엣 |
| 소녀 표정 | 현 모프/얼굴 구조 확인 후 놀람·눈 확대·눈 감기 제작, 만화적 눈/입은 전용 얼굴 표현으로 보완 가능 | 단순 확대만으로 원문의 만화적 경악을 대체하지 않음 |
| 주인공 모션 | 손 뻗기 → 발 걸림 → 넘어짐 → 고개 들기 → 플레이 자세 인계 | 1인칭 팔/손이 보이고 넘어짐이 카메라 흔들림만으로 끝나지 않음 |
| 잡동사니 | 도주 때 떨어지고 넘어짐 원인이 되는 소품 배치/낙하 클립 | 무작위 물리로 타이밍이 바뀌지 않도록 연출 중 궤적을 통제 |
| 지역명 | WBP_RegionTitle 재사용 우선 | 폐교/텅 빈 교실, 화면 중앙, 입력 비점유 |

환경은 구조·실제 스케일 → 카메라 → 빛 → 재질 → 소품 순서로 조정한다. 본편 다른 락커나 소녀를 일괄 변경하지 않는다. 새 모델 작업에는 모듈러 환경 Workflow의 캐릭터 크기 우선·문짝/피벗 분리·실제 플레이 검증 원칙을 적용한다.

1인칭 연기는 전용 카메라와 필요한 신체 대역으로 촬영하는 안을 권장한다. 실제 플레이어 입력/충돌, 대역, 카메라를 각기 소유하고, 머리 내부가 보이거나 팔까지 사라지지 않도록 근접 렌더를 검사한다. 대역 사용 시 최종 위치·방향·포즈를 실제 플레이어로 인계하고 숨겨진 대역의 충돌을 제거한다. 기존 소녀/주인공의 다른 이벤트 상태를 건드리지 않는다.

## 7. 레벨 시작과 종료 연결

시작 배치 `연출_S0_시작`은 LevelReady로 `DA_S0_Opening`에 연결한다. 런너의 별도 자동 재생과 레벨 BP 직접 재생을 동시에 켜지 않는다.

기존 SceneGameSubsystem은 준비 여부를 알려주지만 시작 화면의 암전과 HUD 최초 노출까지 보장하는 기능은 아니다. S0가 실행될 진입에서 PlayerController의 HUD 표시 전 단계에 맵 한정 초기 암전·HUD 보류를 연결한다. UIReady는 내부 UI 준비를 알리는 신호로 계속 전달해, ‘HUD가 보일 때까지 기다리는 연출’과 ‘연출 종료를 기다리는 HUD’ 사이의 교착을 피한다.

연출이 정상 종료되면 다음 순서로 한 번만 처리한다.

1. 노래·연출 음향·눈꺼풀 효과를 정리하고 대사창을 닫는다.
2. 교실의 안전한 플레이 위치/방향·몸 상태를 인계하고 3인칭 카메라 이동/회전을 완료한다.
3. Scene Director 종료 정리까지 끝낸 뒤 조작과 게임 HUD가 복원된 것을 확인한다.
4. 지역명 UI로 `폐교 / 텅 빈 교실`을 표시한다. 이 UI는 입력을 잠그지 않는다.
5. 기존 이동 튜토리얼은 지역명 연출 직후 별도 순서로 호출하는 안을 권장한다. 첫 조작 가능 프레임에 즉시 UIOnly로 전환하지 않는다.

Cinematic 중단/실패는 정상 완료로 기록하지 않는다. 락커 안에 플레이어가 갇힌 채 제어권만 돌아오는 상태를 방지하도록 안전한 교실 복구 지점을 둔다. 문·소녀·소품 상태는 정상 완료에서는 최종 상태 유지, 취소/실패에서는 재시도 가능한 초기 상태 복원을 구분한다. 재시도는 명시적 테스트 신호 또는 다음 진입으로 수행하며 무한 자동 재시도하지 않는다.

원문에 스킵 요구는 없다. 최초 구현에 스킵 기능을 추가하지 않으며, 디버그 StopDirector를 성공한 스킵으로 간주하지 않는다.

## 10. 전달물과 구현 순서 제안

전달물은 편집 가능한 DA_S0_Opening, 실제 AbandonedSchool 시작 연결, S0 전용 콘텐츠와 제작 소스, 재실행 가능한 제작/검사 도구, 양쪽 조사 순서를 확인한 결과, 전체 플레이 영상, 기획자용 노드·카메라·대사 수정 안내다.

구현은 **선택지 최소 확장 → 실제 공간과 시작/복귀 검증 → 전체 초벌 → 연기·소품·음향 완성 → 실제 게임 회귀** 순서로 진행한다. 다만 공간/자산 조사는 첫 단계에서 수행해 접촉 모션의 기준을 먼저 정한다. 원문이 요구하는 사건과 플레이 흐름을 모두 통과한 뒤에 최종 시각 완성도를 판정한다.

소요 기간은 소녀의 표정 모프, 문 열기/넘어짐/구멍 통과 모션과 노래 음원의 재사용 가능 여부에 크게 좌우된다. 현재는 파일 존재와 코드 기능을 확인한 단계이므로 날짜 단위의 확정 일정을 제시하지 않는다. 작업 1 완료 후 재사용/신규 제작 분량을 기준으로 산정한다.
