# Heroine Lighting Integration Implementation Plan

> **Execution update:** 사용자가 후속 메시지에서 구현을 승인했다. 2026-10-14 백그라운드 Unreal에서 구현했으며, 실제 완료 범위와 제한은 `ArtSource/HeroineLighting/README.md` 및 `manifest.json`을 따른다. 아래 체크리스트는 최초 계획으로, 포괄적인 전체 플레이 검증 완료를 뜻하지 않는다.

**Goal:** 주인공의 승인된 색·스타일을 유지하면서 밝은 교실과 어두운 벽 근처에서 환경 조명에 자연스럽게 반응하게 한다.

**Architecture:** 실제 PIE 플레이어의 메시 및 재질 오버라이드부터 추적한다. 발광, 셰이딩 모델, 전용 조명, 후처리를 각각 분리 진단하고 확인된 원인만 수정한다. 같은 위치·카메라·노출 조건에서 비교한 뒤 정상 게임 노출로 검증한다.

**Tech Stack:** Unreal Engine, Material Editor, Blueprint, PIE, 필요 시 Unreal Python 읽기 전용 감사.

**Spec:** 2026-10-14 사용자 요청과 첨부된 밝은 교실/어두운 벽 근처 플레이 스크린샷. 이 문서에 목표와 검증 조건을 명시한다.

## Global Constraints

- 최초 요청은 계획 작성이었으나 후속 요청으로 게임 에셋 수정이 승인되었다. 사용자 화면·열린 에디터는 조작하지 않고 별도 백그라운드 Unreal을 사용한다.
- 외부 `Constellation_ArtWorkspace/ArtSource/Heroine_Rebuild/GamePilot/CURRENT.json`이 현재 소스 포인터다. 2026-10-14 확인 시 Revision09와 LockerAnimation을 참조한다.
- 기존 BP_Player_Heroine에 GamePilot을 연결했다는 기록은 확인했으나 실제 현재 PIE 인스턴스의 연결은 미확인이다.
- 캐릭터 얼굴·UV·모프·체형·애니메이션을 보존한다. 얼굴 패치 재질을 일괄 치환하지 않는다.
- 환경 전체 밝기나 원본 텍스처를 먼저 변경하지 않는다. 변경 전 참조 관계와 복구 가능한 기준값을 기록한다.
- Blender 작업은 현 계획에 필요하지 않다.

## Review Focus

- 어두운 장소에서도 상의·피부가 자체 발광처럼 유지되는지: Task 1–3의 암부 비교.
- 밝은 장소에서 흰 부분의 형태가 소실되는지: Task 3의 밝은 교실 비교.
- 얼굴 보정 패치와 피부 경계가 조명별로 드러나는지: Task 2–3의 얼굴/표정 비교.
- 플레이 시 동적 재질 설정이 저장된 수정값을 덮는지: Task 1의 런타임 감사와 Task 3의 재시작.
- 암부에서 플레이어 식별성이 과도하게 떨어지는지: Task 3의 이동·카메라 회전 검토.

## Task 1: 재현 기준 및 실제 원인 분리

**Read:** `Content/Constellation/Characters/Heroine/Blueprints/BP_Player_Heroine.uasset`, 현재 PIE 인스턴스, 실제 메시 슬롯/오버라이드/부모 재질. `Refined`의 옛 재질 이름만으로 대상 확정 금지.

**Create at execution:** `Saved/HeroineLightingReview/baseline.json`, `diagnosis.json`, 전후 캡처.

- [ ] 현재 맵, 플레이어 클래스, 메시 경로, 각 슬롯의 실효 재질과 부모 체인, 동적 파라미터를 기록한다.
- [ ] 첨부 장면의 밝은 교실과 어두운 벽 위치를 재현하고 위치·회전·카메라·노출·그래픽 품질을 기록한다. 원래 게임 노출과 임시 고정 노출을 구분한다.
- [ ] 머리·가디건·상의·피부·다리의 Shading Model, Base Color, Emissive 연결과 강도, Roughness, Specular 및 텍스처 색공간을 확인한다. 그래프의 값을 화면만 보고 추정하지 않는다.
- [ ] 캐릭터/카메라 부착 조명, Lighting Channels, 그림자 설정, BeginPlay/Tick의 재질 변경, Post Process 및 Custom Depth 기반 캐릭터 보정을 검사한다.
- [ ] 저장하지 않는 비교 상태에서 한 변수씩 분리한다. Lit 재질은 발광 제거 비교, Unlit은 Base Color를 연결한 임시 Lit 진단 재질과 비교, 전용 조명/후처리는 각각 비활성 비교한다. Unlit의 Emissive만 끄면 검게 되는 것을 원인 해결로 판단하지 않는다.
- [ ] 원인과 증거 캡처를 기록한다. 변화가 없으면 해당 가설을 폐기하고 다른 원인을 검사한다.

**Gate:** 실제 재질 경로와 재현 가능한 원인 분리 결과가 있어야 수정 단계로 이동한다.

## Task 2: 확인된 원인에 한정한 후보 수정

**Modify:** Task 1에서 확인한 실제 재질/인스턴스 또는 BP 조명·보정 설정만. 공유 부모 수정 전 참조 사용처를 조사하고 필요한 경우 캐릭터 전용 후보를 만든다.

- [ ] 발광이 원인이면 몸/의상 발광을 우선 제거한 후보를 비교한다. 게임 식별성은 이후 실제 암부 플레이에서 판단한다.
- [ ] Unlit이 원인이면 원래 텍스처/마스크/얼굴 보정 연산을 보존하여 조명 반응 재질 후보를 구성한다. 단순한 셰이딩 모델 변경만으로 끝내지 않는다.
- [ ] 부착 조명이나 후처리 보정이 원인이면 해당 설정만 조정한다. 원인이 아닌 재질 설정은 함께 바꾸지 않는다.
- [ ] 정상 조명 반응을 확보한 다음에도 밝은 부분이 뭉개질 때만 가디건·피부의 색 배율/표면 반사를 개별 조정한다. 일괄 회색화하지 않는다.
- [ ] 얼굴 정면·사선과 눈 깜박임을 확인하여 피부/눈꺼풀/귀/입 주변 보정 경계가 다시 드러나지 않는지 검사한다.

**Gate:** 원래 밝은 의상과 피부색을 알아볼 수 있고, 암부 반응이 개선되며 얼굴 보정이 유지된 후보만 채택한다.

## Task 3: 게임 조건 검증 및 전달

**Create at execution:** `Saved/HeroineLightingReview/result.json`, 비교 이미지 및 변경 목록.

- [ ] 밝은 교실, 어두운 벽, 청록색 광원 근처에서 같은 카메라와 고정 노출로 기준/후보를 비교한다. 상의·피부의 뭉개짐, 음영, 주변 빛의 색 반응을 확인한다.
- [ ] 원래 자동 노출과 게임 후처리를 복원하고 세 지점 사이를 왕복한다. 밝기 적응 중에도 자체 발광처럼 뜨거나 실루엣을 잃지 않는지 확인한다.
- [ ] 카메라 회전, 걷기·달리기·상호작용, 얼굴 표정에서 재질 경계·깜박임·발밑 그림자를 점검한다. 발밑 그림자 문제는 별도 원인이 확인될 때만 수정한다.
- [ ] 채택 에셋 저장 후 PIE를 다시 시작하여 실제 실효 재질/파라미터와 외형이 유지되는지 확인한다. 저장 readback과 실제 렌더 검증을 구분한다.
- [ ] 수정 에셋 목록, 변경 전후 값, 동일 조건 비교, 검증한 맵/그래픽 품질, 남은 한계를 전달한다. 임시 진단 상태는 복구한다.

**Acceptance:** 어두운 장소에서 상의/피부도 주변 조도에 따라 어두워지고, 밝은 교실에서 형태와 색이 유지되며, 실제 플레이에서 식별성과 기존 얼굴 스타일이 유지된다. 임의의 밝기 감소율을 성공 기준으로 강제하지 않는다.

## Technical reference

Epic의 [Shading Models](https://dev.epicgames.com/documentation/en-us/unreal-engine/shading-models-in-unreal-engine): Unlit은 색을 Emissive로 출력한다. 이는 우선 검사할 가설의 근거이며 현재 프로젝트가 Unlit이라는 증거는 아니다.
