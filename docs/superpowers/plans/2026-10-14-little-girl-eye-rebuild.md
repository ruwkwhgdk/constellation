# 소녀 눈 구조 재설계 — 조사 및 제작 계획

> 실행자는 superpowers:executing-plans를 적용해 단계별 산출물을 확인한다. 이번 요청은 조사와 계획이며 모델 수정은 시작하지 않는다.

**Goal:** 원화의 인상과 복원본의 캐릭터 정체성을 유지하면서 흰자위·홍채·눈꺼풀 연결과 시선/깜빡임을 함께 성립시키는 게임용 눈을 제작한다.
**Architecture:** 기존 생성 메시 위에 표면을 덧붙이는 방식을 중단한다. 눈 주변 피부를 연속된 변형용 토폴로지로 교체하고, 별도 얕은 안구 표면에 흰자위/홍채/동공을 명시적 UV 마스크로 구성한다. 눈꺼풀은 셰이프 키, 시선은 재질 좌표 제어를 우선 시험한다. 구형 안구 본 회전 방식과 짧은 검증을 거쳐 최종 결정한다.
**Tech Stack:** Blender, Unreal Skeletal Mesh/Morph Target/Material Instance. Blender 드라이버를 Unreal이 그대로 실행한다고 가정하지 않는다.
**Spec:** 아래 원화 보존 조건 및 단계별 검수 기준. 제안 계획이며 최종 디자인 승인 전 구현하지 않는다.

## 2. 이전 접근의 문제

- 좌우 정점 수/대칭 좌표가 같다는 것은 구조 검사의 일부이며 미적 완성도 증명이 아니다.
- 원래 눈꺼풀은 비대칭/불규칙한 상태인데 눈 안쪽만 복제하여 경계와 비율이 맞지 않았다.
- 생성 텍스처에 피부·속눈썹·흰자·홍채·그림자가 섞여 있다. RGB 임계값으로 흰자를 추정하면 어두운 홍채가 흰색으로 바뀐다.
- 기존 표면 위의 대체 곡면은 이중 표면, 간격, 그림자, 관통 문제를 추가한다.
- 피부와 머리카락의 접합을 공간 좌표나 색으로만 분류하면 머리카락 손상이 발생한다.
- 정면 렌더만 개선한 뒤 시선과 깜빡임을 뒤늦게 붙이는 순서가 잘못됐다.

## 4. 권장 구조와 대안

권장 시험안: 원화에 맞춘 얕은 곡면 안구 + 독립 UV 홍채/동공 + 연속 피부 눈꺼풀 + 별도 속눈썹 메시.
- 흰자 표면은 눈꺼풀 뒤까지 충분히 이어져 시선 이동에도 구멍이 나지 않게 한다.
- 흰자/홍채/동공은 명시적인 제작 마스크를 사용한다. 기존 이미지의 색상 판별로 분리하지 않는다.
- 눈꺼풀 피부는 얼굴에 연속되게 연결한다. 눈구멍 테두리뿐 아니라 눈썹 아래, 콧등 옆, 윗볼까지 부드럽게 이어지는 범위를 잡는다.
- 앞머리와 피부가 붙은 부분은 실제 토폴로지를 확인하고 수동 분리한다. 머리카락 앞면을 피부 보정 대상으로 포함하지 않는다.
- 속눈썹은 눈꺼풀을 따르는 두께/폭 변화가 있는 메시. 균일한 검정 타원으로 눈 전체를 두르지 않는다.
- 눈꺼풀 그림자와 하이라이트는 홍채 기본색에서 분리한다. 하이라이트를 좌우 텍스처 복제로 무조건 반전시키지 않는다.
- 반사/각막은 기본 형태 통과 후 추가 여부를 결정. 과한 굴절과 젖은 반사로 결함을 숨기지 않는다.

대안 A: 구형 또는 타원형 안구를 눈 본으로 회전. 구현/엔진 연결은 비교적 단순하지만 큰 스타일 눈에서는 돌출과 눈꺼풀 충돌 가능성이 있다. 비균등 스케일과 회전 순서도 검증한다.
대안 B: 얕은 안구는 고정, 홍채를 표면 좌표/셰이더로 이동. 원화 비율 제어가 좋지만 극단 시선/사선의 왜곡과 Unreal 제어 구현을 별도 검증해야 한다. B를 우선 시험하되 3단계 결과로 확정한다.

## 5. 실행 순서와 통과 기준

### 단계 1 — 시각 설계, 카메라 기준
- [ ] 원화를 현재 얼굴 시점과 가능한 범위에서 맞춰 눈 폭/높이, 양 눈 간격, 눈꼬리 높이, 홍채 노출 비율, 속눈썹 두께를 표시한다.
- [ ] 작은 원화 크롭에서 정확한 3D 치수를 추론하지 않는다. 원화의 고개 기울기/원근과 얼굴 자체 비대칭을 구분한다.
- [ ] 정면/좌우 3/4/측면 카메라, 중립 조명, 실제 게임 대화 거리 카메라를 고정한다.
산출물: 원화 비교 시트와 눈 단면 설계. 기준선과 디자인 방향이 합의되기 전 고해상도 텍스처 제작하지 않는다.

### 단계 2 — 한쪽 눈과 주변 피부의 구조 원형
- [ ] 작은 눈 패치를 덧씌우지 않고 해당 영역의 오래된 피부/눈 표면을 실제 교체할 경계를 정한다.
- [ ] 앞머리와 피부를 명확히 구분한다. 머리카락 원형 보존을 비교한다.
- [ ] 한쪽 눈꺼풀-눈꼬리-눈밑을 연속된 쿼드 중심 루프로 재구성한다. 변형이 집중되는 눈꺼풀 가장자리에 극점과 긴 가는 면을 피한다.
- [ ] 흰자위는 별도 안구 표면, 눈꺼풀에는 얇은 두께를 부여한다. 공유 피부 경계를 연결하고 겹친 원래 내부 면은 남기지 않는다.
- [ ] 단색 피부/흰자/홍채만으로 정면과 사선을 확인한다.
통과: 미간/윗볼로 이어지는 이음새, 구멍, 겹친 면, 눈꺼풀 돌출/평평한 붙임판 인상이 없어야 한다. 이 단계 실패 시 리깅/텍스처로 덮지 않는다.

### 단계 3 — 최소 움직임 원형과 방식 선택
- [ ] 한쪽 눈에 중립, 좌우, 상하 시선과 깜빡임 중간/닫힘을 만든다.
- [ ] A/B 중 원화 인상과 사선 안정성을 더 잘 지키는 방식을 선택한다. 기존 +/-6도/4도는 제한된 옛 실험값이지 새 품질 기준이 아니다.
- [ ] 시선 한계는 예상 대사 연출의 주시점으로 시험하고 실측해 문서화한다.
- [ ] 깜빡임 0/25/50/75/100%에서 피부/속눈썹과 안구 충돌을 확인한다.
통과: 흰자 구멍, 홍채 잘림, 눈꺼풀 통과, 닫힘 틈이 없어야 한다. 형상과 움직임이 통과한 뒤 좌우 구축한다.

### 단계 4 — 양쪽 통합
- [ ] 검증한 루프 구조는 미러링 가능하되 얼굴 중심면, 양쪽 안와 깊이와 눈꼬리를 다시 맞춘다.
- [ ] 양쪽 눈의 시선은 동일한 주시점을 보도록 조정한다. 두 본의 Euler 값 동일 여부만으로 판정하지 않는다.
- [ ] 무표정/고개 기울임/3/4에서 짝눈, 사시, 흰자 노출 차이를 비교한다.
통과: 기본 눈 폭/높이와 홍채 크기는 의도적으로 통일, 원근에 따른 화면상 차이는 허용. 미러링은 제작 보조이며 최종 검수의 대체가 아니다.

### 단계 5 — 재질과 원화 표현
- [ ] 홍채/동공/흰자/상부 그림자/하이라이트를 분리 가능한 레이어로 제작한다.
- [ ] Tripo 원본의 색감과 무늬는 참고하되 불완전한 512px 눈 패치를 최종 UV로 고착하지 않는다.
- [ ] 기존 주름을 새 피부 노멀로 재베이크하지 않는다. 허용한 세부만 선택 전사한다.
- [ ] 흰자는 조명 아래에서도 구분되되 순백 발광 스티커가 되지 않게 한다.
- [ ] 얼굴 전체/실제 게임 거리에서 원화의 순한 인상, 상안검 가림, 하부 테두리, 눈꼬리를 평가한다.
통과: 형상 문제를 페인팅으로 가리지 않으며, 원화 대비 아트 검수가 필요하다. 수치 대칭만으로 원화 수준이라고 보고하지 않는다.

### 단계 6 — Unreal 전달과 통합
- [ ] 작은 테스트 에셋으로 먼저 눈 제어와 모프 타깃 전달을 확인한다.
- [ ] Blink_L/R와 필요한 중간 보정, 상하 시선 추종을 Blender 셰이프 키에서 Unreal 모프/커브로 전달한다.
- [ ] Blender의 드라이버/제약은 Unreal로 자동 이식되지 않는다. 눈 본 방식은 애니메이션/본 제어, 셰이더 방식은 명시적 재질 파라미터 제어를 구현한다.
- [ ] 본편 조명, 고개 기울임, 락커 주시 연출, 대기/걷기에서 실제 프레임을 검수한다.
- [ ] 재질 정렬, 노멀/색 공간, LOD, 모프 유지, 머리 그림자에 따른 눈 가독성을 확인한다.
통과 후에만 유지 에셋 교체. 테스트 자원 제거는 의존성 확인 이후 수행한다.

## 6. 산출물과 중단 조건

예정 출력은 아트 루트 아래 EyeRebuild_vNext/의 design, source, textures, review, validation 폴더에 분리한다. 원형과 이전 후보는 변경하지 않는다.
단계 1-3의 검수 가능한 원형을 첫 작업 단위로 한다. 완성 시간은 피부 경계 재구성 난도와 외형 검수에 좌우되므로 지금 고정 시간을 약속하지 않는다.
경계 분리가 불가능하거나 더 넓은 얼굴/머리 형태 변경이 필요하면 변경 범위와 시각 비교를 제시한다. 자동 좌표 보정/색 임계값/붙임 표면의 반복을 성공으로 간주하지 않는다.
이번 턴에는 연구와 계획 문서만 작성했으며 Blender 또는 게임 에셋을 변경하지 않았다.
