# 전투 테스트 워크벤치 설계안

작성: 2026-10-05
상태: 사용자 승인 후 런타임 구현 완료. 사용법·검증: ../../2026-10-05-combat-workbench.md.

## 목적

별도 언리얼 에디터를 열지 않고 실제 게임 창에서 플레이어와 슬라임의 전투 수치를 바꾸고 반복 플레이한다. 가로로 늘어선 디버그 문자열을 상태별 UI로 교체한다. 기존 수동 실행 명령 tools/play-combat-recipe.ps1을 그대로 사용한다.

## 선택한 방향

현재 전투 시험장에 Slate 기반 인게임 패널을 붙인다. 플레이 화면과 별도 편집기를 오갈 필요가 없고, 플레이어와 몬스터의 실제 런타임 상태를 같은 화면에서 확인할 수 있다.

대안:
- 언리얼 에디터 Details 패널: 기존 자산 편집에 유리하지만 에디터 없이 플레이하려는 사용 흐름에 맞지 않는다.
- 별도 외부 편집기: 레시피 관리에는 유리하지만 게임 상태와 편집값 동기화가 추가로 필요하다.

이번 범위는 ACombatLabCharacter 기반 전투 시험장이다. 다른 프로젝트 맵, SceneDirector, 정식 게임 HUD에 자동으로 적용하지 않는다.

## 실행과 가독성 — 사용자 수정 반영

- 기본 창 크기는 1600×900. 1920×1080에서도 검증하고 창 크기 변경을 허용한다.
- 본문 글자 크기는 Slate 기준 18을 기본으로 하고 제목은 22 이상으로 설계한다. 실제 Windows DPI 환경에서 가독성을 확인한다.
- 공간이 부족하면 글자를 일괄 축소하지 않는다. 세로 스크롤, 탭, 상세 정보 접기를 사용한다.
- 1280×720은 보조 호환 크기이며 기본 배치 기준이 아니다. 하단 적용·닫기 버튼은 계속 접근 가능해야 한다.
- 프로젝트 루트의 Play-Combat.cmd를 더블클릭하면 기본 SlimeScout_v2 시험장이 열린다. 터미널에 명령을 입력할 필요가 없다.
- 실행기는 설치된 UE 5.8의 게임 모드를 사용한다. 별도 배포용 패키지 exe 제작은 이번 실행 편의 개선과 구분한다.
- 실행 실패 시 오류 창을 유지해 원인을 읽을 수 있게 한다.

## 플레이 화면

- 좌측 위 플레이어 카드: 현재/최대 HP와 SP, 막대, 공격·회피·피격·사망 상태.
- 우측 위 몬스터 카드: 선택한 슬라임의 HP/SP, AI 상태, 현재/마지막 선택 패턴.
- 좌측 아래 입력 카드: 선입력 대기 여부와 최근 공격 불가 이유. SP 부족, 쿨다운, 사망 등을 구분한다.
- 하단 조작 안내: 이동, 공격, 회피, 락온, 재시작, F1 조정 패널.
- 상세 AI 판단 문자열과 진단 정보는 접힌 상세 영역에 둔다. 긴 문자열은 줄바꿈하고 고정 폭 안에서 표시한다.
- 적 머리 위의 긴 진단 문자열은 제거한다. 필요하면 대상 표시와 간단한 HP만 유지한다.
- HP 0일 때 사망 및 재시작 방법을 명확히 표시한다.
- 기존 카메라와 이동 기본값은 변경하지 않는다. 플레이어 이동 500cm/s와 기존 프로젝트 입력 설정을 초기값으로 사용한다.

## F1 조정 패널

열면 전투를 일시정지하고 마우스 커서를 표시한다. 상단에 '전투 일시정지 / 적용 전 변경 있음'을 표시한다.

좌측 탭:
1. 플레이어
2. 슬라임
3. 공격·패턴
4. 상세 상태

본문은 두 열(항목명 / 편집값)과 그룹 제목으로 정리하고 세로 스크롤을 제공한다. 숫자 입력, 단위, 짧은 설명, 원래 값으로 되돌리기를 제공한다. 몬스터가 여러 마리면 명시적인 대상 선택기를 제공하며, 적이 없으면 해당 편집 영역을 비활성화한다.

하단 고정 버튼:
- 적용 후 전투 재시작
- 변경 취소 후 계속
- 초기 설정으로 복원
- 프리셋 저장 / 불러오기

편집 중 값은 초안에만 저장한다. 적용 버튼에서 전체 검증을 거치고, 성공한 경우 플레이어와 몬스터를 초기 위치·최대 자원으로 새 전투에 진입시킨다. 적용 시 현재 진행 중인 공격/회피/쿨다운은 초기화됨을 버튼 옆에 표시한다. 이 방식은 진행 중인 공격의 비용이나 판정 값만 절반 바뀌는 문제를 피하고 비교 조건을 일정하게 유지한다.

F1 또는 닫기는 초안을 버리고 기존 전투를 계속한다. 미적용 변경이 있음을 표시하며, 적용 없이 닫을 때 변경이 버려진다는 설명을 제공한다. 사망 상태에서도 패널 열기 및 적용 후 재시작이 가능해야 한다.

## 편집 항목

| 탭 / 그룹 | 항목 |
|---|---|
| 플레이어 / 자원 | 최대 HP, 최대 SP, SP 초당 회복량, 회복 시작 대기 시간 |
| 플레이어 / 이동·피격 | 이동 속도(cm/s), 피격 경직 시간(s) |
| 플레이어 / 회피 | SP 비용, 거리(cm), 지속 시간(s), 무적 시작·종료(s) |
| 플레이어 / 공격 | 콤보 단계 선택, 피해량, SP 비용, 쿨다운(s), 재생 배속, 판정 거리·반경(cm) |
| 슬라임 / 자원 | 최대 HP, 최대 SP, SP 회복량·대기 시간 |
| 슬라임 / 이동·교전 | 이동 속도, 감지 거리, 추적 해제 거리, 활동 반경, 공격 접근 거리 |
| 슬라임 / 복귀 | 시야 상실 유예 시간, 복귀 완료 거리, 복귀 시 자원 회복 여부 |
| 공격·패턴 / 슬라임 공격 | 패턴별 피해량, SP 비용, 쿨다운, 재생 배속, 판정 거리·반경 |
| 공격·패턴 / 선택 조건 | 최소·최대 거리, 최대 각도, 시야 필요 여부, 선택 가중치, 연속 사용 제한 |

현재 HP/SP는 상태 표시로 구분한다. 최대 자원 수치 변경 후 재시작하면 해당 최대값으로 시작한다. 사망한 액터의 HP만 강제로 올려 부활시키지 않는다.

애니메이션 파일, 몽타주 Notify, 스켈레톤, 콤보 연결 구조는 이번 패널에서 변경하지 않는다. 애니메이션 제작 요청은 기존 별도 작업 목록을 사용한다.

## 데이터와 저장

- 원본 Action, PatternProfile, EncounterProfile은 편집하지 않는다.
- 액터별 런타임 복사본을 만든 뒤 Ability/BehaviorTree/EnemyAgent 초기화에 전달한다.
- 콤보 NextAction 및 패턴 참조를 원본→복사본 매핑으로 재연결한다. 같은 원본을 사용하는 다른 적과 수치가 섞이지 않아야 한다.
- 세션 설정은 월드 재시작을 넘어 유지하되 현재 시험장과 대상 식별자에 묶는다. 다른 맵에 자동 적용하지 않는다.
- '프리셋 저장'은 Saved/CombatTuning 아래 버전과 원본 경로를 포함한 JSON 파일을 생성한다. 기존 파일을 무조건 덮어쓰지 않는다.
- 불러오기는 전체 검증 후 초안으로 읽는다. 사용자가 적용해야 전투에 반영한다.
- 첫 구현의 프리셋은 플레이어와 몬스터 설정을 포함하는 전용 형식이다. 기존 몬스터 전용 CombatRecipes schema_version=1과 혼동하지 않는다.
- 프리셋은 이후 AI에 전달 가능한 조정 결과물이다. 이번 저장 버튼이 원본 uasset이나 기존 레시피를 갱신한다고 표시하지 않는다.
- 초기 설정 복원은 저장 자산에서 읽은 이번 시험장의 원래 수치를 초안에 복원한다.

## 현재 코드에서 필요한 변경

1. CombatLabCharacter의 직접 화면 출력 대신 전용 Slate HUD/조정 위젯을 연결한다.
2. UI 입력 모드를 분리한다. 현재 WASD는 Tick에서 키 상태를 직접 읽으므로 패널이 열린 동안 이동, 시점 회전, 공격, 회피, 락온, R 입력을 모두 차단한다. 닫을 때 눌린 키 상태를 정리하고 게임 입력을 복구한다.
3. 월드 일시정지 중에도 닫기 버튼과 F1이 동작하도록 UI 키 처리를 둔다. 위젯/입력 상태는 EndPlay 및 UnPossessed에서 정리한다.
4. 런타임 데이터 복사와 프리셋/초안 검증을 UI와 분리해 자동 테스트가 가능하게 한다.
5. 현재 CombatAttributes는 HP/SP를 100으로 고정 제한한다. 최대 HP/SP 속성을 도입하고 초기화, 피해, 회복, 복귀 회복, 표시 및 관련 테스트의 고정 100 가정을 함께 갱신한다. 기본 최대값은 100으로 유지한다.
6. 기존 자동 교전 검사의 기본 프로필 결과를 보존한다. 새 최대값을 사용하는 경우에는 최대 자원을 기준으로 결과를 계산한다.
7. CombatRuntime에 Slate/SlateCore 의존성을 추가한다. CombatEditor 모듈을 런타임 UI에서 참조하지 않는다.

## 검증 규칙

- 모든 숫자는 유한값. 음수 금지 항목과 양수 필수 항목을 구분한다.
- 최대 HP/SP > 0. SP 소모와 회복량은 0 허용.
- 회피 무적 구간: 0 <= 시작 <= 종료 <= 지속 시간.
- 추적 해제 거리 >= 감지 거리; 공격 접근 거리 < 감지 거리; 복귀 완료 거리 < 활동 반경.
- 패턴 최소 거리 <= 최대 거리, 각도 0~180도, 연속 제한은 0 이상의 정수.
- Action/Pattern/Encounter의 기존 검증도 사용한다. 불러온 원본 경로와 현재 대상 호환성을 검사한다.
- 실패한 필드 옆에 오류를 표시하고 적용을 막는다. 일부 필드만 적용되는 상태는 만들지 않는다.
- JSON 형식 오류·누락·버전 불일치는 현재 전투를 변경하지 않고 설명한다.

## 완료 기준

- 기본 1600×900 및 1920×1080에서 충분한 글자 크기로 표시하고, 보조 크기 1280×720에서도 스크롤로 모든 항목과 저장/적용 버튼에 접근할 수 있다.
- 게임을 직접 조작하다 F1로 수치를 변경하고 적용 후 같은 조건으로 재시험할 수 있다.
- 편집 중 공격·카메라 회전·이동이 발생하지 않고 닫으면 원래 조작이 복구된다.
- 플레이어/슬라임 최대 HP, 이동 속도, 공격 피해 및 SP 회복 변경이 실제 플레이에 반영된다.
- 플레이어와 슬라임이 같은 원본 공격 자산을 참조해도 서로의 수정 및 원본 자산에 영향을 주지 않는다.
- 원본 자산값과 기존 기본 조작값을 보존한다.
- 프리셋 저장→종료→재실행→불러오기→적용이 재현된다.
- 기본값 기존 전투 회귀 테스트, 최대 자원/복귀 회복 테스트, 초안 검증·복사 격리·프리셋 왕복 테스트를 통과한다.
- 실제 렌더 화면에서 기본 HUD와 조정 패널을 확인한다. 자동 테스트 성공만으로 수동 사용성 확인을 대체하지 않는다.

## 제외 범위

정식 게임 메뉴, 멀티플레이 동기화, 임의 캐릭터 Blueprint 편집기, 애니메이션 제작, 몽타주 편집, AI 그래프 편집, 원본 uasset 저장은 이번 구현 범위에 포함하지 않는다.
