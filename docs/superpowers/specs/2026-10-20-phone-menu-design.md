# 인게임 핸드폰 메뉴 기획서

작성일: 2026-10-20  
상태: 사용자 승인 대기  
대상: Project Constellation, Unreal Engine 5.8

Esc를 누르면 캐릭터가 주머니에서 핸드폰을 꺼내고, 꺼내기가 완료된 다음 손과 핸드폰을 내려다보는 구도로 전환한다. 화면 우측에는 조작 가능한 임시 메뉴를 표시한다. 다시 Esc를 누르면 메뉴를 닫고 핸드폰을 넣은 뒤 일반 플레이로 돌아간다.

이번 문서는 제작 방향의 승인용이다. 코드·애니메이션·게임 에셋 구현은 승인 이후 진행한다.

## 1. 요청 범위와 제안 사항

| 구분 | 내용 |
| --- | --- |
| 사용자 요청 | Esc로 시작, 주머니에서 꺼내기, 꺼낸 뒤 카메라 변경, 첨부 이미지와 같은 손·폰 구도, 우측 임시 UI |
| 임시 리소스 | 엔진 기본 큐브를 얇은 직육면체로 조정해 핸드폰 대용으로 사용 |
| 이번 제작 범위 | 꺼내기·들고 있기·수납 동작, 카메라 전환과 복귀, 임시 버튼 반응, 입력·예외 처리 |
| 후속 범위 | 정식 핸드폰 모델·화면 콘텐츠, 실제 메뉴 기능, 최종 그래픽·사운드, 게임패드·터치 지원 |
| 승인받을 기본안 | 왼손으로 들기, 지상 안전 상태에서 진입, 메뉴가 완전히 열린 동안 싱글플레이 일시정지, Esc로 닫기 |

손·주머니 위치, 수치, 일시정지 정책은 아래의 **제안값**이며 기존에 승인된 요구사항으로 간주하지 않는다. 첨부 이미지는 구도와 화면 분할의 참고 자료로만 사용한다. 이미지 속 메뉴명·아이콘·프로필·문구는 게임 기능 요구사항이 아니다.

## 2. 화면과 카메라

캐릭터가 자신의 손을 내려다보는 듯한 근접 사선 구도를 사용한다. 화면 왼쪽에 실제 캐릭터의 전완·손과 임시 핸드폰이 보이고, 배경에는 현재 게임 월드가 남는다. 오른쪽에는 화면에 고정된 2D 메뉴를 배치한다.

| 영역 | 제안 |
| --- | --- |
| 왼쪽 약 55% | 손과 세로로 든 큐브 핸드폰. 손·폰이 UI에 가려지지 않도록 배치 |
| 오른쪽 약 45% | 세로형 반투명 패널. 상단 제목, 임시 버튼 6개, 하단 닫기 안내 |
| 일반 HUD | 미니맵·전투 HUD·상호작용 안내는 메뉴 중 숨기고 이전 표시 상태로 복원 |
| 마우스 | 메뉴 조작이 가능해지는 시점에 커서 표시 및 UI 포커스 부여 |

실제 폰에 3D UI를 붙여 조작하는 방식보다, **월드 속 소품 + 우측 화면 UI** 조합을 권장한다. 참고 이미지의 구도를 재현하면서 임시 메뉴와 후속 정식 메뉴를 쉽게 교체할 수 있다. 폰 표면에는 앞뒤를 구분할 단색 면만 둔다.

카메라는 캐릭터 기준의 안정적인 위치를 사용하고 손 본의 미세한 흔들림을 그대로 따라가지 않는다. 머리·머리카락·어깨 내부가 보이거나 가까운 벽을 통과하지 않도록 위치와 시야각을 조정한다. 안전한 구도를 확보하지 못하면 기존 카메라로 복구하고 메뉴 진입을 취소한다.

16:9를 우선 검수하고 16:10·21:9에서도 폰과 패널이 겹치거나 잘리지 않는지 확인한다. 분할 비율·카메라 거리·시야각은 실제 캐릭터 검수에서 조정할 값이다.

## 3. 조작 흐름

| 단계 | 화면·동작 | 입력 처리 |
| --- | --- | --- |
| 일반 플레이 | 기존 카메라와 HUD | Esc 최초 누름으로 진입 요청 |
| 준비 | 이동 감속 후 정지, 진입 조건 재확인 | 이동·공격·회피·점프·상호작용·시점 조작 차단 |
| 꺼내기 | 손이 주머니 위치로 이동하고 폰을 잡아 들어 올림 | Esc 추가 누름은 닫기 예약 1회로 합침 |
| 카메라 전환 | 꺼내기 완료 신호 후 손·폰 구도로 부드럽게 이동 | UI는 아직 조작 불가 |
| 메뉴 열림 | 우측 패널 표시, 폰을 든 자세 유지 | 클릭·키보드 UI 조작, Esc로 닫기 |
| 닫기 | UI 숨김, 카메라 복귀와 수납 동작 진행 | 중복 Esc 무시 |
| 복귀 완료 | 폰 숨김, 기존 카메라·HUD·입력 상태 복원 | 정상 플레이 재개 |

꺼내기 완료는 고정 대기 시간만으로 판단하지 않고 애니메이션의 완료 신호로 연결한다. 그보다 먼저 메뉴 카메라로 넘어가거나 손에 폰이 갑자기 나타나지 않게 한다. 닫기 예약이 있다면 안전하게 꺼내기 동작을 마친 뒤 UI를 열지 않고 수납으로 연결한다.

첫 조정 목표는 꺼내기 0.8~1.2초, 카메라 전환 0.25~0.4초, 패널 표시 0.15~0.25초, 닫기 전체 0.6~1.0초다. 연출 타이밍 제안이며 자연스러운 손 동작을 희생해 맞추지 않는다.

## 4. 캐릭터와 임시 핸드폰

왼손으로 폰을 잡는 것을 기본안으로 한다. 손을 의상의 주머니 위치까지 내린 후 잡고, 몸 앞쪽으로 들어 올려 화면을 보는 동작을 제작한다. 실제 의상에 적절한 주머니가 없다면 엉뚱한 신체 부위에서 생성하지 않고, 주머니 위치 또는 임시 수납 위치를 이미지로 제시해 확인받는다.

큐브 크기의 시작값은 약 7 × 1 × 15cm로 두고 실제 손 크기에 맞춰 조절한다. 충돌·물리 시뮬레이션은 끄며, 잡는 시점에 검증된 손 부착점에 연결한다. 수납 접촉 시점에 숨긴다. 최종 모델 교체 시에도 부착 위치와 이벤트 연결을 재사용할 수 있게 한다.

꺼내기·유지·수납 세 구간을 제작한다. 폰을 드는 동안 손가락은 그립을 유지하고, 메뉴 클릭마다 별도의 터치 애니메이션은 만들지 않는다. 무기·운반 포즈와 손 점유가 충돌하지 않도록 무기를 든 상태는 1차 진입 제한 대상에 포함한다.

손목 회전만으로 폰 방향을 맞추지 않는다. 어깨–팔꿈치–전완–손바닥과 엄지·각 손가락을 함께 검사한다. 손가락 교차·역꺾임·과굴곡, 손과 폰의 관통, 의상 간섭이 큰 상태는 임시 모델이라는 이유로 통과시키지 않는다.

애니메이션 제작 전 유지 원본과 실제 리그를 확인한다. 사용자가 지정한 저장된 .blend가 필요하며, 이번 요청에는 지정 파일이 없으므로 임의로 선택하지 않는다. 제작 착수 시 유지 소스를 제시해 입력 파일을 확정한다. 원본 보존, 별도 후보 저장, audit·snapshot·compare 및 저장 후 재열기를 따른다.

## 5. 임시 UI

제목은 ‘핸드폰’, 보조 문구는 ‘임시 메뉴’로 표시한다. 본문은 ‘메뉴 01’부터 ‘메뉴 06’까지 2열 3행 버튼으로 구성한다. 특정 게임 시스템을 먼저 확정하는 이름은 붙이지 않는다.

버튼에는 마우스 올림·키보드 포커스·누름 상태를 표시한다. 클릭 또는 Enter로 선택하면 같은 패널 안의 상태 문구를 ‘메뉴 03 선택됨 — 기능 준비 중’처럼 변경한다. 화면 이동이나 실제 게임 데이터 변경은 하지 않는다.

Tab 또는 방향키로 포커스를 이동할 수 있고, 최초 포커스는 첫 버튼이다. 하단 ‘닫기’ 버튼과 Esc는 동일한 종료 동작을 실행한다. UI가 열린 동안 클릭과 키 입력이 뒤쪽 게임으로 전달되지 않게 한다.

## 6. 진입 제한과 일시정지

1차는 **싱글플레이 지상 탐색 상태**를 대상으로 한다. 걷거나 달리는 중 Esc를 누르면 감속·정지 후 연출을 시작한다. 준비가 0.5초 내 끝나지 않거나 도중 조건이 바뀌면 요청을 취소한다.

전투 중, 공격·피격·사망·낙하·점프·착지·기상 동작 중, 물체 운반·조준·투척 중, 무기 손 점유 중, 슬라임 등 다른 형태 조작 중, 대화·컷신·획득 연출·다른 모달 UI 중에는 진입하지 않는다. 요청은 뒤늦게 자동 실행하지 않고 버린다. 다른 UI가 Esc를 소유하고 있으면 그 UI의 닫기 규칙을 우선한다.

제안하는 정지 정책은 다음과 같다.

- 준비·꺼내기·카메라 전환 중에는 월드가 진행되고 플레이어 조작만 차단된다.
- 카메라 전환이 끝난 메뉴 열림 상태에서 월드를 일시정지한다. 손 자세는 정지 상태로 유지하고 UI 입력·표시는 계속 동작한다.
- 닫을 때 메뉴가 건 일시정지만 해제하고 수납·카메라 복귀를 재생한다. 완료까지 플레이어 조작 차단을 유지한다.
- 이미 다른 시스템이 정지시킨 월드에는 진입하지 않는다. 다른 시스템의 정지·입력 차단을 임의로 해제하지 않는다.

따라서 꺼내기·닫기 중에는 외부 사건이 발생할 수 있다. 이때 피격·사망·강제 컷신이 시작되면 메뉴 연출을 취소하고 해당 시스템에 제어권을 넘긴다. 메뉴 열림 동안은 월드 진행이 멈춘다. 멀티플레이 또는 월드가 계속 진행되는 메뉴 정책은 후속 설계 범위다.

## 7. 중단과 복구

레벨 전환, 플레이어 교체·파괴, 강제 컷신, 애니메이션 중단, 위젯 생성 실패, 카메라 전환 실패, 완료 신호 누락에는 공통 정리 절차를 적용한다.

위젯·임시 폰을 제거 또는 숨기고, 이 기능이 소유한 카메라·입력 차단·일시정지만 해제한다. 입력 모드, 커서, 포커스, HUD 표시와 게임 카메라 설정은 진입 전 값으로 복원한다. 새 컷신이 카메라를 넘겨받았거나 플레이어가 바뀌었다면 과거 카메라를 강제로 덮어쓰지 않는다.

열고 닫을 때 눌린 키 상태를 정리해 이동·공격이 잔류하지 않게 한다. Esc 자동 반복은 무시한다. 완료 신호 누락 시에는 클립 길이 기반 제한 시간을 두고 안전 복귀하며, 입력이 영구 잠기는 상태를 남기지 않는다.

## 8. 프로젝트 연결 방향

현재 소스에서 확인한 사실과 구현 때 확인할 항목을 구분한다.

| 확인 사항 | 설계 영향 |
| --- | --- |
| DefaultInput.ini가 Enhanced Input을 사용 | 메뉴 전용 입력 액션으로 시작·종료를 연결하는 방향 |
| 기존 도구가 BP_Player_Heroine, BP_PlayerController, ABP_Player_Heroine을 참조 | 이 Blueprint들의 실제 현재 그래프와 소유권을 구현 전 확인 |
| AMyCharacter에는 기본 입력 설정 코드만 존재 | 이 C++ 클래스만 수정하면 된다고 가정하지 않음 |
| AbilityAcquisitionSubsystem이 입력 선점·커서·일시정지를 관리 | 획득 연출과 동시 실행하지 않고 입력 우선순위 확인 |
| CarryComponent가 손 점유 상태와 BlocksOtherActions를 제공 | 운반 상태에서 메뉴 진입을 막고 기존 IK와 중복 실행 방지 |

권장 구성은 메뉴 상태를 관리하는 전용 컴포넌트, 우측 위젯, 메뉴용 카메라 설정, 교체 가능한 폰 메시, 꺼내기·유지·수납 애니메이션이다. 진입 조건은 실제 플레이어의 전투·이동·연출 상태에 연결하며 추측한 Blueprint 변수명에 의존하지 않는다.

애니메이션 이벤트는 ‘폰 잡기’, ‘꺼내기 완료’, ‘폰 수납’, ‘동작 완료’ 역할로 분리한다. 이벤트 누락 복구와 정상 전환은 동일한 상태 관리 경로를 사용한다. 정확한 클래스명·본명·소켓명·슬롯명은 실제 에셋 검사 후 정한다.

Esc가 에디터 PIE 종료 단축키와 충돌할 수 있으므로 최종 조작 검수는 Standalone 게임에서 수행한다. 사용자 에디터의 전역 단축키를 임의 변경하지 않는다.

## 9. 제작과 검수 순서

1. 이 기획서의 동작·범위·기본안을 승인받는다.
2. 현재 플레이어·입력·카메라·애니메이션 에셋을 읽기 전용으로 검사하고 구현 계획을 작성한다. 지정할 .blend와 주머니 위치를 확정한다.
3. 큐브를 사용한 꺼내기·유지·수납 후보와 동일 조건의 정면·측면·손 근접 검수 영상을 제작한다. 사용자 동작 승인 후 엔진에 반영한다.
4. 입력·상태 전환·임시 UI·카메라를 연결한다. 큐브 모델만 임시 대체하며 꺼내기 연출은 생략하지 않는다.
5. 엔진 저장·재로드 후 실제 플레이 영상을 검수하고 반복 진입·중단·복귀를 확인한다.

프로젝트의 Intermediate 및 Plugins/*/Intermediate는 삭제하거나 정리하지 않는다. 다른 채팅의 빌드와 경쟁하는 빌드도 시작하지 않는다.

| 제한 | 낙하·전투·운반·다른 UI·컷신 등에서 규칙대로 차단됨 |
| 복구 | 꺼내기·전환·열림·닫기 각각의 강제 중단에서 소유 상태가 해제됨 |
| 환경 | 엔진 재로드 후 Standalone에서 일시정지 중 닫기, 화면비별 배치, 근접 장애물 검수 통과 |

전달물은 구현 계획, 별도 애니메이션 후보 및 검수 영상, 임시 메뉴 구현 에셋·코드, 실제 게임 작동 영상, 수정 파일 목록과 검증 결과다. Blender 데이터 검사, 외형·동작 확인, Unreal 5.8 실제 재생 확인, 미검증 항목을 구분해 보고한다.

이 기획서 승인은 제작 방향 승인이다. 신규 손·관절 동작의 영상 승인과 최종 플레이 검수는 위 단계에서 별도로 진행한다.
